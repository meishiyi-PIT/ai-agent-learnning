## 2. 协作规则（她明确要求，违反会被当场指出）

1. **一回合一个概念**，不要一次写大文档。节奏：这步解决什么 → 给她一个小问题 → 以设计者第一人称给完整思路 → 面试追问预演 → 等她说"继续"。
2. **每个新点开头说"它在结构图上哪里、接前面哪个已讲的点、拿到什么交出什么"，结尾说"往后连什么"**。她靠联系建立记忆，孤立讲她记不住（11-09 批评过）。
3. **先骨架后细节，先定义再分类**。部件太大拆半步。11-08、11-09 两次"没看懂"都是一回合塞了两件事。
4. **表格一律放在 ```markdown 代码块里给原文**，她要复制进自己的笔记。
5. 她追问实现时给能跑的示意代码，标明是按简历口径还原的示意实现。
6. 她会推回你的说法，常常是对的。**承认、纠正、落到后面的设计里**；不要前后不一致（11-04 效果口径改了三次被她抓住）。
7. **会话开头随机抽一题让她讲 30 秒**，用故事带数字问（"加了重排以后到多少"），不问裸数，只说对错不展开。
8. **不要往 `项目拆解_自用版本.md` 写任何东西**（她手写的）。进度只记 `进度交接_项目拆解.md` 第 9 节。
9. **不要用后台 agent / 多智能体流程**，她明确要求直接做。
10. 中文，直接，不客套，无 emoji。
11. 数字：只用简历 v4、面试底稿、第 9 节里已有的数；新数标"（拟定，待确认）"，百分比给分子分母，估算加"约"，不夸大（"上线即降 55%"这类禁止）。
12. 她问"怎么记忆"时给的方法：只背一页纸、记坑不记方案、一个例子（memory_limit 小节）讲到底、挂 Java 经验（kb_chunk 普通表、HNSW 索引、知识包发布包、双表重建蓝绿发布、续跑幂等消费者）、分层复述 1 / 3 / 10 分钟版、间隔抽查。

## 3. 8 步模板

1 为什么做（开场 30 秒 + 基线数；"之后"的数放第 5 步）→ 2 真正的问题（约束分环境 / 场景两组，反事实推演，"环境定架构、场景定模块"）→ 3 结构图（主干、约束落点、部件清单标主导 / 参与）→ 4 逐个部件（在图上哪里接哪里 → 问题含首版的坑 → 备选表 → 为什么选 → 怎么做 → 代价 → 想一下 + 答案 → 追问表 → 对应约束 → 往后连）→ 5 效果归因（逐月迭代链、每数挂改动与口径、评测数据与训练调参的关系）→ 6 真实案例（主案例 + 副案例，现象 → 定位 → 修法 → 兜底）→ 7 主导 / 参与边界 → 8 复述提纲 + v5 段落草稿 + 面试底稿改动。
