# 项目四 RAG：一页纸骨架 + 数字卡

2026-11-09 给出，11-10 按两期时间线修订。用法：只背这一页；每次会话开头被抽一题讲 30 秒。

## 一页纸

### 为什么做
值班工单四成多手册里有答案（4 周 436 条中 181 条，41.5%）→ 先做内部版给 L1 当场答、少升级 L3；验证后产品团队 2025.08 做进 OCP，交付版 2025.12 上线客户自助。

### 五条约束（环境定架构，场景定模块）
环境：① 客户内网不加组件 → OceanBase 自建、知识包随版本发（内部版一开始就按此预留） ② 发版慢内部要快 → 两套运行时共享知识包
场景：③ 精确术语对口语 → 两路召回 + 精确通道 ④ 文档多版本 → 版本前过滤 ⑤ 答错有人照做 → 证据约束 + 锚点 + 拒答

### 结构图
文档 → ① 入库 → 知识包 → [内部版 Python | 交付版 Java] 各自 ② 存储 ③ 召回 ④ 生成；⑤ 评测只在内部版
唯一跨边界的箭头：知识包随安装包出去，什么都不回来。

### 五个部件（坑 → 选择 → 代价）
① 入库：参数表被切断、子块丢标题 → 标题感知父子分块，表格 SQL 整块，子块带前缀 → 依赖文档结构
② 存储：五个版本副本抢名额、答旧版本 → 同表前过滤；换模型 → 双表重建 + 一行配置切 → 重建期双份存储
③ 召回：-4012 查不到、口语够不着、排不进前 5 → 两路 50 / RRF 30 / Reranker 5；精确通道钉顶；证据不够才 Multi-Query → Reranker 几百毫秒
④ 生成：证据不够模型补默认值 → 证据约束提示词 + 锚点 + 阈值拒答；内部版多轮改写 + 工单历史；交付版只读工具 → 误拒要监控
⑤ 评测：不知道错在哪一环 → 日志三级五组、离线重放、六类归因、两键反馈只在内部版 → 日志敏感信息要脱敏

### 五个交接物
块 + 向量 + 标签 → 建好索引的表 → 5 个块 + 5 个分数 → 回答 + 引用 或 拒答 → Bad Case 回流

### 时间线
2024.07–08 建库 ｜ 09–2025.02 调检索六个月有回退 ｜ 03 准备、04–05 试运行 8 周 ｜ 06–07 接口交项目二 ｜ 2025.08–12 二期产品化（参与）

### 四个案例标题
旧版本资料 ｜ 精确通道没命中 ｜ 模型不支持 Function Calling ｜ Recall 高回答仍错（→ 项目三）

### 一句话
检索侧负责找对证据，生成侧负责只用证据说话；存储跟环境走，模块跟场景走；内部先试用再产品化。

## 数字卡（故事 → 数 → 钩子）

| 故事 | 数 | 钩子 |
|---|---|---|
| 首版单路向量 | Recall@5 66.7%（200/300） | 三分之二起步 |
| 加两路召回 + RRF | 76.0%（228/300） | 涨九个点，多救 28 题，救精确词 |
| 加 Reranker（含两开关） | 85.0%（255/300） | 再涨九个点，多救 27 题，救排 6–30 的 |
| 正确块平均排第几 | MRR 0.78 | 第一到第二之间，是小数别和 76 混 |
| 证据约束提示词十来版 | 忠实度 91.7%（275/300） | 九二 |
| 锚点 + 在线引用检查 | 引用正确率 94.3%（283/300） | 九四，比忠实高因为有代码检查 |
| Reranker 只做 30 对 | P50 0.9s / P95 3.8s | 1 和 4 往下一点 |
| 入库规则 | 9,000 篇 / 12 万子块 | 每篇十三块 |
| 值班调研 | 41.5%（181/436） | 四成多工单手册里有答案 |
| 内部版 8 周 | 直接采用 55.0%（132/240） | 一半多一点；首版约三成 |
| 内部版拦第二层 | 升级率 14.9% → 7.9%（27/181 → 19/240） | 砍一半 |

三句话记八组数：检索三段每段涨九个点；生成两个九十多、引用比忠实高；业务两个一半、直接采用一半多一点、升级率砍一半。
记分数不记百分比：分母 300、240、436，顺手答了样本量。
交付版效果不给数：二期 2025.12 才上线，客户升级滞后，"要长期看支持侧工单结构"。
忘了就说趋势加口径，不编小数。
