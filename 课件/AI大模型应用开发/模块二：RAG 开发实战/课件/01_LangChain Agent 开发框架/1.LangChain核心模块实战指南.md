# LangChain 核心模块实战

## 一、框架概览：LangChain 是什么
你可以把 LangChain 理解为**大模型应用开发的"瑞士军刀"**。

单独调用大模型 API，能做的事情其实很有限——你发一句提示，它回一句答案，仅此而已。但现实中的 AI 应用远没那么简单：需要管理多轮对话、让模型调用外部工具、把多个步骤串联成完整的处理流程……

LangChain 正是为解决这些问题而生的。它是一个开源框架，也可以理解为一套在大模型能力之上构建的工具层。它的目标是帮助开发者更轻松地搭建基于语言模型（尤其是大语言模型）的应用程序。LangChain 的核心思路，是用一套结构化的方式，把语言模型、外部数据源、各种组件连接起来，从而支撑起更复杂的业务逻辑。简单说，它把与大模型交互的整个流程拆解成一个个标准化的模块，你像搭积木一样组合拼接，就能快速搭建出功能丰富的 AI 应用。

### 核心模块一览
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1782119215321-0441d762-8aa5-4880-85bc-8d38f09ea61e.png)

| 模块 | 职责 | 一句话说明 |
| :---: | :---: | --- |
| **Models** | 模型接入 | 对接各种大模型 API，屏蔽底层差异 |
| **Prompts** | 提示管理 | 把 prompt 模板化，支持变量、复用、版本管理 |
| **Chains** | 链式编排 | 用管道符 `|` 把多个步骤串成流水线 |
| **Memory** | 记忆管理 | 让无状态的 LLM 记住上下文 |
| **Agents** | 智能调度 | 让模型自己决定该调哪个工具、传什么参数 |
| **Output Parsers** | 输出解析 | 把模型返回的"人话"转成结构化数据 |

## 二、模型层：与大模型对话的三种姿势
LangChain 把模型分成三类，覆盖了几乎所有大模型交互场景：

| 类型 | 输入 | 输出 | 典型用途 |
| :---: | :---: | :---: | --- |
| **LLM** | 纯文本字符串 | 纯文本字符串 | 简单文本生成 |
| **Chat Model** | 消息列表 | 消息对象 | 多轮对话（主流） |
| **Embedding** | 文本 | 向量（浮点数组） | 语义搜索、RAG |


实际开发中 90% 的场景用的都是 **Chat Model**，下面重点讲。

### 2.3 跑本地模型（Ollama）
不想花钱调 API？用 Ollama 在本地跑模型，零成本开发调试。

#### 2.3.1 Ollama 是什么
Ollama 是一个**本地大模型运行引擎**——你可以把它理解为大模型界的 Docker。

它帮你解决了最头疼的问题：不用折腾 CUDA 环境、不用手动下载权重文件、不用写一堆加载脚本。一条命令，模型就能跑起来。

| 特性 | 说明 |
| --- | --- |
| **极简部署** | `ollama run deepseek-coder` 一行命令搞定 |
| **模型丰富** | 支持 Llama 3、Qwen、DeepSeek、Mistral 等主流开源模型 |
| **跨平台** | Windows / macOS / Linux 全覆盖 |
| **本地运行** | 数据不出本机，隐私安全有保障 |
| **资源友好** | 针对消费级显卡优化，8GB 显存也能跑 |


适用场景：

```plain
✅ 个人学习大模型原理
✅ 本地开发调试 AI 应用
✅ 隐私敏感场景（如医疗、法律文档处理）
✅ 企业内网离线部署
❌ 需要大规模并发的生产环境（建议用 vLLM / TGI）
```

### 2.4 消息类型：System / Human / AI
和大模型对话不是随便丢一句文字就完事了。LangChain 把消息拆成三种角色，对应真实的对话结构：

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

# SystemMessage：设定模型的"人设"，相当于给它一个角色卡
# HumanMessage：用户说的话
# AIMessage：模型之前的回答（用于多轮对话）

messages = [
    SystemMessage(content="你是一个资深的 Python 技术博主，擅长用大白话解释概念"),
    HumanMessage(content="解释一下什么是装饰器？"),
]

response = llm.invoke(messages)
print(response.content)
```

> **为什么要区分消息类型？**  
因为大部分模型 API 都要求按 `[system, user, assistant]` 的结构传消息。  
System 定义规则，Human 是用户输入，AI 是历史回复——三者配合才能实现多轮对话。
>

### 2.5 参数调优三件套：temperature / top_p / top_k
这三个参数控制模型生成文本的"创造力"，理解它们的协作关系很关键：

```plain
原始概率分布（50000 个候选词）
        │
        ▼
  ① Temperature 缩放 logits
  （控制整体随机性）
        │
        ▼
  ② Top-K 过滤
  （只保留概率最高的 K 个词）
        │
        ▼
  ③ Top-P 过滤
  （保留累积概率 ≤ P 的词）
        │
        ▼
  ④ 重新归一概率 → 随机采样 → 输出一个词
```

| 参数 | 作用 | 调节建议 |
| :---: | --- | --- |
| **temperature** | 缩放 logits，控制分布"平坦度"，用于控制生成文本的随机性，影响文本的确定性与多样性。温度高就多样性高，确定性低。 | 0.1 = 稳定输出，1.0+ = 创意发散 |
| **top_k** | 只保留概率最高的 K 个候选词，用于限制候选词数量，提升文本质量。 | K=1 就是确定性输出，K=100 很随机 |
| **top_p** | 保留累积概率达到 P 的候选词，用于动态调整候选词集，平衡质量与多样性，想创意高点，top_p就大点。 | 0.9 = 保留主流选项，过滤冷门 |


```python
# 写代码/做数学题：低温 + 小 top_p，追求确定性
llm_coding = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com",
    temperature=0.1,
    model_kwargs={"top_p": 0.8}
)

# 写小说/头脑风暴：高温 + 大 top_p，追求多样性
llm_creative = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com",
    temperature=0.9,
    model_kwargs={"top_p": 0.95}
)
```

#### 三个参数如何一步步筛选候选词
下面用一个具体例子，完整走一遍模型生成下一个词的过程。假设模型正在写一句话："今天的晚餐我想吃___"，模型要从词汇表中选出下一个词。

**原始 logits（模型直接输出的分数，还没归一化成概率）：**

```plain
词汇表：  ["火锅",  "烧烤",  "寿司",  "披萨",  "沙拉",  "牛排",  "麻辣烫", "意面"]
原始logit：[ 3.2,    2.8,     1.9,     1.5,     0.8,     0.6,     0.3,      0.1 ]
```

---

**第 ① 步：Temperature —— 调整分布的"尖锐度"**

Temperature 不直接筛词，而是通过缩放 logits 来改变概率分布的形状。公式是 `调整后logit = 原始logit / temperature`。

**场景 A：temperature = 0.3（低温，写确定性文本）**

```plain
调整后 logit：
  火锅: 3.2/0.3 = 10.67    烧烤: 2.8/0.3 = 9.33
  寿司: 1.9/0.3 = 6.33     披萨: 1.5/0.3 = 5.00
  沙拉: 0.8/0.3 = 2.67     牛排: 0.6/0.3 = 2.00
  麻辣烫: 0.3/0.3 = 1.00   意面: 0.1/0.3 = 0.33

Softmax 后的概率：
  "火锅": 63.8%  ████████████████████████████████
  "烧烤": 16.7%  ████████
  "寿司":  0.8%  ▌
  "披萨":  0.2%  ▏
  其余词：几乎为 0
```

→ 概率高度集中在"火锅"上，模型几乎一定会选它。**分布很"尖"，输出确定性高。**

**场景 B：temperature = 1.5（高温，头脑风暴）**

```plain
调整后 logit：
  火锅: 3.2/1.5 = 2.13    烧烤: 2.8/1.5 = 1.87
  寿司: 1.9/1.5 = 1.27    披萨: 1.5/1.5 = 1.00
  沙拉: 0.8/1.5 = 0.53    牛排: 0.6/1.5 = 0.40
  麻辣烫: 0.3/1.5 = 0.20  意面: 0.1/1.5 = 0.07

Softmax 后的概率：
  "火锅": 19.6%  ██████████
  "烧烤": 14.8%  ███████
  "寿司":  8.3%  ████
  "披萨":  6.4%  ███
  "沙拉":  3.9%  ██
  "牛排":  3.5%  ██
  其余词：也有概率
```

→ 概率分布变平坦了，"火锅"不再是压倒性优势，"寿司""披萨"也有机会被选中。**分布很"平"，输出更多样。**

---

**第 ② 步：Top-K —— 砍掉排名靠后的词**

经过 temperature 调整后，假设我们设 `top_k = 3`（以场景 A 低温为例）：

```plain
按概率排序后，保留前 3 个：
  ✅ "火锅": 63.8%    ✅ "烧烤": 16.7%    ✅ "寿司":  8.7%
  ❌ "披萨": 2.5%     ❌ "沙拉": 0.5%     ❌ "牛排": 0.3%
  ❌ "麻辣烫": 0.1%   ❌ "意面": 0.0%

归一化（让保留词的概率重新加到 1）：
  总和 = 63.8 + 16.7 + 8.7 = 89.2%
  "火锅": 63.8/89.2 = 71.5%
  "烧烤": 16.7/89.2 = 18.7%
  "寿司":  8.7/89.2 =  9.8%
```

→ 只从这 3 个词里选，其余词彻底出局。**K 越小，候选越少，输出越确定。**

---

**第 ③ 步：Top-P —— 按累积概率动态截断**

假设设 `top_p = 0.85`，以下演示基于场景 B（高温）调整后的概率：

```plain
按概率从高到低排序，逐步累加：
  "火锅": 19.6%  ← 累积 19.6%
  "烧烤": 14.8%  ← 累积 34.4%
  "寿司":  8.3%  ← 累积 42.7%
  "披萨":  6.4%  ← 累积 49.1%
  "沙拉":  3.9%  ← 累积 53.0%
  "牛排":  3.5%  ← 累积 56.5%
  ...继续累加直到超过 85%...

保留累积概率 ≤ 0.85 的所有词 → 可能保留 6~7 个词
```

→ Top-P 的巧妙之处在于：**它是动态的**。当某个词概率特别高时（如低温下的"火锅"71.5%），可能只保留 1~2 个词；当概率分布均匀时（如高温场景），会保留更多词。这比 Top-K 的固定数量更灵活。

---

**第 ④ 步：归一化 + 随机采样**

把筛选后的候选词概率重新归一化（缩放到加和为 1），然后**按概率随机抽取**——不是直接选最大的！

```plain
以 Top-K = 3 的结果为例：
  "火锅": 71.5%    ← 有 71.5% 的概率被选中
  "烧烤": 18.7%    ← 有 18.7% 的概率被选中
  "寿司":  9.8%    ← 有  9.8% 的概率被选中

掷骰子 → 这次选中了"烧烤" → 输出："今天的晚餐我想吃烧烤"
```

注意：概率最大的词不一定被选中！这就是"随机采样"和"贪心解码（直接选最大）"的区别。温度越高、top_p 越大，"冷门词"被选中的可能性越大。

---

**总结：三个参数的协作流程**

```plain
原始 logits（50000 个候选词）
        │
        ▼
  ① Temperature  调整分布形状（尖 or 平）
        │
        ▼
  ② Top-K        砍掉排名靠后的词（固定数量）
        │
        ▼
  ③ Top-P        按累积概率截断（动态数量）
        │
        ▼
  ④ 归一化 → 随机采样 → 输出一个词
```

> **实际建议**：一般先调 temperature 控制整体风格，再用 top_p 微调候选范围。top_k 和 top_p 不需要同时设——选一个配合 temperature 即可。写代码时 `temperature=0.1, top_p=0.8`；写创意内容时 `temperature=0.9, top_p=0.95`。
>

### 2.6 结构化输出：让模型返回 JSON 而非散文
模型默认返回的是自由文本，但程序需要结构化数据。`with_structured_output` 能让模型按你定义的 Schema 输出：

```python
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model

# 定义你期望的输出结构（Pydantic 模型）
class MovieInfo(BaseModel):
    """电影信息"""
    title: str = Field(description="电影名称")
    year: int = Field(description="上映年份")
    director: str = Field(description="导演")
    rating: float = Field(description="评分（10分制）")

llm = init_chat_model(
    model="qwen-plus",
    model_provider="openai",
    api_key="sk-你的密钥",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

# .with_structured_output() 会自动把 Schema 注入 prompt，
# 并在底层做 JSON 解析和类型校验
structured_llm = llm.with_structured_output(MovieInfo)

result = structured_llm.invoke("介绍一下电影《星际穿越》")

# 返回的是 MovieInfo 对象，可以直接用属性访问
print(f"片名：{result.title}")
print(f"年份：{result.year}")
print(f"导演：{result.director}")
print(f"评分：{result.rating}")
```

## 三、提示工程：让 LLM 听懂你的话
### 3.1 提示模板是什么
直接拼字符串写 prompt？可以，但不优雅。模板的价值在于：

+ **参数化**：同一套 prompt 结构，换个变量就能复用
+ **可维护**：prompt 和业务逻辑分离，改模板不用动代码
+ **标准化**：LangChain 统一了模板接口，方便组合成链

### 3.2 ChatPromptTemplate：多角色对话模板
这是最常用的模板类型，支持按角色组织消息：

```python
from langchain_core.prompts import ChatPromptTemplate

# 定义一个带变量的对话模板
# {name} 和 {question} 是占位符，运行时会被替换
chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是一个叫 {name} 的 AI 助手，说话风格简洁专业"),
    ("human", "{question}")
])

# 填充变量，生成最终的消息列表
messages = chat_template.format_messages(name="小助手", question="什么是机器学习？")
print(messages)
# 输出：
# [SystemMessage(content='你是一个叫 小助手 的 AI 助手，说话风格简洁专业'),
#  HumanMessage(content='什么是机器学习？')]
```

```python
# 直接和模型组合使用
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

response = llm.invoke(messages)
print(response.content)
```

### 3.3 PromptTemplate：纯文本模板
不需要区分角色时，用 `PromptTemplate` 更简单：

```python
from langchain_core.prompts import PromptTemplate

# 单变量模板

# → "给我讲一个关于程序员的笑话"

# 多变量模板
prompt = PromptTemplate(

    input_variables=["style", "topic", "limit"]

print(prompt.format(style="幽默", topic="加班", limit=100))
```

### 3.4 部分填充：预设部分变量
有些变量在定义模板时就已经知道了，可以提前"锁定"：

```python
from langchain_core.prompts import PromptTemplate
from datetime import datetime

# 一个需要三个变量的模板
prompt = PromptTemplate(
    template="请分析{city}在{year}年{date}的天气趋势",
    input_variables=["city", "year", "date"]
)

def get_datetime():
    now = datetime.now()
    return now.strftime("%m/%d/%Y, %H:%M:%S")

# partial() 可以预填部分变量
# 注意：date 传的是函数引用而非调用结果，每次 format 时会重新执行
partial_prompt = prompt.partial(
    city="成都",
    year="2026",
    date=get_datetime)  # 动态获取当前日期
)

# 只需填剩余的变量（这里已经全部填完了）
print(partial_prompt.format())
```

### 3.5 Few-Shot：用"例题"教会模型做题
Few-Shot 的核心思路：**先给模型看几个例子，再让它做新题**。这比写一大段 instructions 有效得多。

```python
from langchain_core.prompts import FewShotPromptTemplate, PromptTemplate

# 第一步：准备示例数据
examples = [
    {"input": "YYDS",   "output": "永远的神（极度赞美）"},
    {"input": "绝绝子", "output": "太棒了（强烈赞叹）"},
    {"input": "躺平",   "output": "心态平和、不再内卷（不争不抢的生活态度）"},
]

# 第二步：定义每个示例的展示格式
example_prompt = PromptTemplate(
    input_variables=["input", "output"],
    template="黑话: {input}\n翻译: {output}"
)

# 第三步：组装完整的 Few-Shot Prompt
prompt = FewShotPromptTemplate(
    examples=examples,               # 示例列表
    example_prompt=example_prompt,   # 每个示例的格式

    prefix="你是一个精通网络流行语的翻译官。请把黑话翻译成正式的职场语言。\n",  # 前缀（指令）
    suffix="黑话: {input}\n翻译:",                                           # 后缀（用户问题）
    input_variables=["input"]
)

# 第四步：生成最终 prompt
final_prompt = prompt.format(input="下头")
print(final_prompt)
# 输出效果：
# 你是一个精通网络流行语的翻译官。请把黑话翻译成正式的职场语言。
#
# 黑话: YYDS
# 翻译: 永远的神（极度赞美）
#
# 黑话: 绝绝子
# 翻译: 太棒了（强烈赞叹）
#
# 黑话: 躺平
# 翻译: 心态平和、不再内卷（不争不抢的生活态度）
#
# 黑话: 下头
# 翻译:
```

```python
# 把 Few-Shot Prompt 丢给模型
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

response = llm.invoke(final_prompt)
print(response.content)
# → "扫兴、令人不适（形容某事破坏了好心情）"
```

## 四、链式调用：用管道符组装流水线
### 4.1 什么是 Chain
Chain（链）是 LangChain 的核心抽象——**把多个处理步骤串起来，前一步的输出自动成为下一步的输入**。

就像 Unix 管道 `cat file | grep "error" | sort`，LangChain 用 `|` 运算符把模块连起来：

```plain
用户输入
   │
   ▼
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ Prompt    │ →  │ LLM      │ →  │ Parser   │ →  │ 最终输出  │
│ 模板填充  │    │ 模型调用  │    │ 结果解析  │    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 4.2 最简 Chain：Prompt + LLM
```python
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

prompt = PromptTemplate.from_template("请用一句话解释什么是{concept}")

# 用管道符 | 把 prompt 和 llm 连起来，就构成了一条链
chain = prompt | llm

# invoke 时只需传入变量，prompt 填充和模型调用自动完成
result = chain.invoke({"concept": "量子计算"})
print(result.content)
```

### 4.3 LCEL 表达式：LangChain 的灵魂语法
LCEL（LangChain Expression Language）是 LangChain 推荐的链构建方式。核心理念是：**所有实现了 **`Runnable`** 接口的组件，都可以用 **`|`** 串联**。

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

# 定义对话模板
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个中国历史专家，回答简洁明了"),
    ("user", "{input}")
])

# StrOutputParser 把 AIMessage 转成纯字符串
# 这样链的输出就是 str，而非 AIMessage 对象
parser = StrOutputParser()

# 三段式链：Prompt → LLM → Parser
chain = prompt | llm | parser

result = chain.invoke({"input": "秦始皇统一六国的顺序是什么？"})
print(result)  # 直接是字符串，不需要 .content
```

### 4.4 输出解析器：把"人话"变"代码"
模型返回的是自然语言，但你的程序需要结构化数据。输出解析器就是干这个翻译活的。

#### 字符串解析器（StrOutputParser）
最简单，就是去掉 AIMessage 的包装，提取纯文本：


#### Pydantic 解析器：输出强类型对象

```python
introduction = """
```

### 4.5 并行执行：RunnableParallel
有时候你需要**同一个输入，同时跑多条链，最后汇总结果**。`RunnableParallel` 就是干这个的：

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableParallel
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

parser = StrOutputParser()

# 定义两条独立的链
joke_prompt = ChatPromptTemplate.from_template("讲一个关于{topic}的冷笑话，越短越好")
poem_prompt = ChatPromptTemplate.from_template("写一首关于{topic}的五言绝句")

joke_chain = joke_prompt | llm | parser
poem_chain = poem_prompt | llm | parser

# 用 RunnableParallel 把两条链并联
# 同一个 topic 会同时发给两条链，结果以 dict 返回
combined = RunnableParallel(joke=joke_chain, poem=poem_chain)

result = combined.invoke({"topic": "程序员"})
print(f"冷笑话：{result['joke']}")
print(f"五言绝句：{result['poem']}")
# 两条链是并行执行的，总耗时约等于较慢的那条，而非两者之和
```

## 五、记忆系统：让 AI 拥有"记忆"
### 5.1 为什么需要记忆
大模型本质上是无状态的——每次请求都是独立的，它不记得你上一句说了什么。这是LLM 固有缺陷，没有记忆。LLM 的本质是基于统计和概率来生成文本，对于每次请求，它们都将上下文视为独立事件。这意味着当你与 LLM 进行对话时，它不会记住你之前说过的话，这就导致了 LLM 有时表现得不够智能。

这种“无记忆”属性使得 LLM 无法在长期对话中有效跟踪上下文，也无法积累历史信息。比如，当你在聊天过程中提到一个人名，后续再次提及该人时，LLM 可能会忘记你之前的描述。

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

# 第一轮
r1 = llm.invoke("我叫小明，我是一名程序员")
print(r1.content)  # "你好，小明！程序员是个很棒的职业..."

# 第二轮：问它记不记得
r2 = llm.invoke("我叫什么名字？")
print(r2.content)  # "抱歉，我无法知道你的名字..." ← 完全忘了
```

解决方案很朴素：**把历史消息塞进 prompt 里一起发过去**。

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1782197599404-cb533007-e154-4b19-85ba-fcecfe89789a.png)

+ 在对话之前调取之前的历史消息。
+ 将历史消息填充到Prompt里。
+ 对话结束后，继续将历史消息保存到到memory记忆中。



在解决 LLM 的记忆问题时，有两种记忆方案，长期记忆和短期记忆。  


+ 短期记忆：基于内存的存储，容量有限，用于存储临时对话内容。  

+ 长期记忆：基于硬盘或者外部数据库等方式，容量较大，用于存储需要持久的信息。

### 5.2 短期记忆：ConversationBufferMemory
`ConversationBufferMemory` 是最基础的记忆组件——把所有对话原封不动地存起来：ConversationBufferMemory 包含input变量和output变量，input代表人类输入，output代表 AI 输出。  
每次往ConversationBufferMemory组件里存入对话信息时，都会存储到history的变量里。

```python
from langchain_classic.memory import ConversationBufferMemory

# 创建记忆实例
# return_messages=True 表示返回 Message 对象而非纯文本
memory = ConversationBufferMemory(return_messages=True)

# 手动添加对话记录
memory.save_context(
    {"input": "我叫小明，是一名 Python 开发者"},    # 用户输入
    {"output": "你好小明！Python 开发者很厉害呢"}    # AI 回复
)

# 查看存储的历史
print(memory.load_memory_variables({}))
# {'history': [HumanMessage(content='我叫小明...'), AIMessage(content='你好小明...')]}
```

#### 配合 MessagesPlaceholder 使用
`MessagesPlaceholder` 是一个占位符，可以在模板中动态插入历史消息：

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_classic.memory import ConversationBufferMemory
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

memory = ConversationBufferMemory(return_messages=True)

# MessagesPlaceholder 会在运行时被历史消息列表替换
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个友好的 AI 助手"),
    MessagesPlaceholder(variable_name="history"),   # 历史消息插槽
    ("human", "{input}")                            # 当前用户输入
])

chain = prompt | llm | StrOutputParser()

# 第一轮
history = memory.load_memory_variables({})["history"]
r1 = chain.invoke({"input": "我叫小明", "history": history})
print(r1)
memory.save_context({"input": "我叫小明"}, {"output": r1})

# 第二轮：历史自动带入
history = memory.load_memory_variables({})["history"]
r2 = chain.invoke({"input": "我叫什么？", "history": history})
print(r2)  # "你叫小明呀！" ← 这次记住了
```

#### 用 ConversationChain 简化流程
手动管理 history 太繁琐？`ConversationChain` 把这些琐事都封装好了：

```python
from langchain_classic.chains import ConversationChain
from langchain_classic.memory import ConversationBufferMemory
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-chat",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

memory = ConversationBufferMemory(return_messages=True)

# ConversationChain 自动处理：注入历史 → 调用模型 → 保存对话
chain = ConversationChain(llm=llm, memory=memory)

r1 = chain.invoke({"input": "你好，我叫小明，我是程序员"})
print(r1["response"])

r2 = chain.invoke({"input": "我是做什么工作的？"})
print(r2["response"])  # "你是程序员呀！" ← 自动记住
```

#### 自定义 Prompt + ConversationChain

### 5.3 长期记忆：用数据库持久化
短期记忆存在内存里，程序一重启就全没了。生产环境通常需要把对话存到数据库。

LangChain 支持多种后端（SQLite、MySQL、PostgreSQL、Redis 等），原理一样：用 `RunnableWithMessageHistory` 包装链，自动读写历史。

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_community.chat_message_histories import SQLChatMessageHistory
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

# 定义 prompt（带历史占位符）
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个擅长物理的助手"),
    MessagesPlaceholder(variable_name="history"),
```

## 六、Agent 智能体：让 AI 学会"用工具"(重点)
### 6.1 Agent 是什么
Agent就是一个有着聪明大脑而且能够感知外部环境并采取行动的智能系统。

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1782198051993-c1e0589a-10db-4b73-8315-65bcb4543246.png)

单独的 LLM 只能聊天，但 Agent 能"做事"——它能根据用户的问题，自主决定该调用哪个工具、传什么参数，然后把工具返回的结果整合成最终回答。其实说到底是因为单一的模型对我们来说作用不大，我们需要的是一个具备智能的复杂系统。只有复杂系统才能真正的应到到实际生产工作中。

```plain
用户："今天成都天气怎么样？"
          │
          ▼
    ┌───────────┐
    │   Agent   │  ← 大脑：分析意图，决定调用 get_weather 工具
    └─────┬─────┘
          │  tool_call: get_weather("成都")
          ▼
    ┌───────────┐
    │   Tool    │  ← 手脚：真正去查天气 API
    └─────┬─────┘
          │  result: "晴天，25°C"
          ▼
    ┌───────────┐
    │   Agent   │  ← 整合结果，生成自然语言回复
    └─────┬─────┘
          │
          ▼
  "今天成都天气晴朗，气温 25°C，适合出门~"
```

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1782198171533-9fd4f220-471f-43ee-b2c0-a1cb6e53eb1e.png)

Agent工作原理可以概括为以下几个步骤：

+ 接收用户输入：Agent首先接收用户的输入，这可以是一个问题、一个请求或一个指令。
+ 分析并决策：接着，Agent利用语言模型对用户输入进行分析，并根据分析结果决定要采取的操作。这个决策过程可能涉及到对多个可能操作的评估，以及根据上下文选择最合适的操作。
+ 调用工具并执行：一旦决定了要采取的操作，Agent就会调用相应的工具来执行该操作。这些工具可以是LangChain提供的内置工具，也可以是开发者自定义的工具。
+ 返回结果并更新状态：执行完操作后，Agent将结果返回给用户，并更新其内部状态，以便处理后续的用户输入。

### 6.3 Function Calling 机制
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1782198911623-603ebd38-6d11-4d3c-9d6c-d1f528ccfdb0.png)

Agent 的核心能力来自 **Function Calling**（函数调用）。这不是 LangChain 发明的，而是大模型厂商提供的原生能力。

<font style="color:#3f3f3f;">Function Calling 的实际流程是这样的：</font>

1. **你告诉模型**：我有几个工具，每个工具干什么、需要什么参数
2. **用户提问**，模型判断是否需要调工具
3. **如果需要**，模型返回一个结构化的 `tool_calls`（工具名 + 参数），而不是直接回答
4. **你的代码**拿到 `tool_calls`，在本地真正执行函数
5. **把执行结果**塞回消息列表，再发一次请求
6. **模型**根据工具返回的结果，生成最终回复

关键点：**模型只负责"决策"，不负责"执行"**。它告诉你该调什么、传什么参数，真正的执行在你这边。（<font style="color:rgb(132, 132, 132);background-color:rgb(20, 20, 20);">大模型只负责理解语义、并找出需要调用的工具，但运行工具的流程流程实际不是大模型完成的。这个道理很简单——当你使用计算器时，执行实际计算的是计算器、并不是你。因此当大模型调用工具时，大模型只负责定位工具，工具实际是在本地编程环境/或API背后的服务器上运行的。</font>）<font style="color:#3f3f3f;">这个设计很合理：模型是语言模型，不是执行引擎。它擅长理解意图、生成结构化输出，但它没有权限访问你的数据库、调用你的内部 API。</font>

```plain
┌─────────────────────────────────────────────────────────────┐
│                  Function Calling 完整流程                   │
│                                                             │
│  ① 用户消息 + 工具 Schema                                   │
│          │                                                  │
│          ▼                                                  │
│  ② LLM 分析：需要调工具吗？                                  │
│      ├── 不需要 → 直接生成文字回复                           │
│      └── 需要 → 返回 tool_calls（JSON 格式的调用意图）        │
│                    │                                        │
│                    ▼                                        │
│  ③ 你的代码解析 tool_calls，在本地执行函数                    │
│                    │                                        │
│                    ▼                                        │
│  ④ 把工具执行结果 + 原始消息 一起再发给 LLM                   │
│                    │                                        │
│                    ▼                                        │
│  ⑤ LLM 基于工具结果生成最终回复                              │
└─────────────────────────────────────────────────────────────┘
```

### 6.4 用 @tool 装饰器定义工具
<font style="color:rgb(15, 17, 21);">LangChain 中的自定义工具本质上就是 </font>**<font style="color:rgb(15, 17, 21);">function calling 的封装和抽象</font>**<font style="color:rgb(15, 17, 21);">。LangChain自定义工具</font>**<font style="color:rgb(15, 17, 21);">依赖</font>**<font style="color:rgb(15, 17, 21);">底层Function Calling来工作，但它让你</font>**<font style="color:rgb(15, 17, 21);">不用关心</font>**<font style="color:rgb(15, 17, 21);">协议细节，只需关注业务逻辑。</font>

<font style="color:rgb(15, 17, 21);">用 </font>`<font style="color:rgb(15, 17, 21);">@tool</font>`<font style="color:rgb(15, 17, 21);"> 装饰器定义一个自定义工具时，它做的事情就是把描述和类型注解转化为 OpenAI 的 function schema，交给模型去调用。</font>

```python
from langchain.tools import tool
import requests

@tool
def get_weather(location: str) -> str:
    """查询指定城市的实时天气信息
    
    Args:
        location: 城市名称，如"北京"、"成都"
    """
    # 调用免费天气 API
    url = f"https://wttr.in/{location}?format=j1&lang=zh"
    response = requests.get(url)
    data = response.json()

    current = data['current_condition'][0]
    weather_desc = current['weatherDesc'][0]['value']
    temp = current['temp_C']

    return f"{location}的天气：{weather_desc}，温度：{temp}°C"

# @tool 装饰器自动提取的信息
print(get_weather.name)         # "get_weather"
print(get_weather.description)  # "查询指定城市的实时天气信息"
print(get_weather.args)         # {'location': {'title': 'Location', 'type': 'string'}}

# 工具可以直接调用
result = get_weather.invoke({"location": "成都"})
print(result)  # "成都的天气：Sunny，温度：28°C"
```

> **重要提示**：工具的 `description` 不是写给人看的注释，而是写给 LLM 看的"使用说明书"。模型根据它来判断什么时候该调用这个工具。写得越清晰，模型调用得越准确。
>

### 6.5 把工具绑定到模型
```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(
    model_name="deepseek-chat",
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

# bind_tools() 把工具的 Schema 注入到模型请求中
llm_with_tools = llm.bind_tools([get_weather])

# 此时模型已经"知道"你有一个叫 get_weather 的工具了
messages = [HumanMessage(content="成都今天天气怎么样？")]

response = llm_with_tools.invoke(messages)

# LLM的输出不再是一段自然语言文本，而是一个结构化的JSON对象(tool_calls)。
#这个对象包含了要调用的函数名和所需的参数。
print(response.tool_calls)
# [{'name': 'get_weather', 'args': {'location': '成都'}, 'id': 'call_xxx', 'type': 'tool_call'}]
```

langchain框架自动做的事情：

1. 提取工具信息
2. 自动生成工具描述（JSON Schema）告诉模型这个函数叫什么、干什么、需要什么参数

```python
{
  "title": "get_weatherArgs",
  "type": "object",
  "properties": {
    "location": {
```

当调用<font style="color:rgb(15, 17, 21);">LLM时，LangChain会将这个JSON</font>**<font style="color:rgb(15, 17, 21);">转换成LLM提供商要求的格式</font>**<font style="color:rgb(15, 17, 21);">：</font>

<font style="color:rgb(15, 17, 21);">对于OpenAI：</font>

```python
{
  "tools": [{
    "type": "function",

      "parameters": {
        "type": "object",
        "properties": {
          "location": {
            "type": "string",
            "description": "城市名称，如\"北京\"、\"成都\""
          }
        },
        "required": ["location"]
      }
    }
  }]
}
```

<font style="color:rgb(15, 17, 21);">对于Anthropic Claude：</font>

```python
{
  "tools": [{
    "name": "get_weather",
    "description": "查询指定城市的实时天气信息",
    "input_schema": {
      "type": "object",
      "properties": {
        "location": {
          "type": "string",
          "description": "城市名称，如\"北京\"、\"成都\""
        }
      },
      "required": ["location"]
    }
  }]

```



<font style="color:rgb(15, 17, 21);">JSON Schema作为</font>**<font style="color:rgb(15, 17, 21);">工具的描述说明书</font>**<font style="color:rgb(15, 17, 21);">，在调用LLM时，LangChain会把所有工具的Schema打包，作为API请求的一部分发送给LLM.</font>

```python
# 实际发送给OpenAI的请求（简化）
{
  "model": "gpt-4",
  "messages": [
    {"role": "user", "content": "成都天气怎么样？"}
  ],
  "tools": [  # ← 注意这里！包含了你的工具描述
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "查询指定城市的实时天气信息",
        "parameters": {  # ← 这个就是你的JSON Schema！
          "type": "object",
          "properties": {
            "location": {
              "type": "string",
              "description": "城市名称，如\"北京\"、\"成都\""
            }
          },
          "required": ["location"]
        }
      }
    }
  ],
  "tool_choice": "auto"  # 让LLM自己决定是否调用
}
```

<font style="color:rgb(15, 17, 21);">LLM接收并理解这个JSON Schema</font>

<font style="color:rgb(15, 17, 21);">LLM（比如GPT-4）在推理时：</font>

1. **<font style="color:rgb(15, 17, 21);">读取所有工具的描述</font>**<font style="color:rgb(15, 17, 21);">（就是这个JSON Schema）</font>
2. **<font style="color:rgb(15, 17, 21);">分析用户的问题</font>**<font style="color:rgb(15, 17, 21);">："成都天气怎么样？"</font>
3. **<font style="color:rgb(15, 17, 21);">决定是否需要调用工具</font>**<font style="color:rgb(15, 17, 21);">：需要，因为自己没有实时天气数据</font>
4. **<font style="color:rgb(15, 17, 21);">提取参数</font>**<font style="color:rgb(15, 17, 21);">：从"成都天气"中提取</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">location="成都"</font>`
5. **<font style="color:rgb(15, 17, 21);">返回调用指令</font>**<font style="color:rgb(15, 17, 21);">（不是执行，是指令）</font>

```python
// LLM的响应
{
  "choices": [{
    "message": {
      "role": "assistant",
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {
          "name": "get_weather",
          "arguments": "{\"location\": \"成都\"}"  // 符合JSON Schema要求
        }
      }]
    }
  }]
}
```

```python
你定义工具 → LangChain生成JSON Schema → 发送给LLM（附带在请求中）→ LLM理解后返回tool_calls
```

**<font style="color:rgb(15, 17, 21);">你给LLM一份工具操作手册（JSON Schema），手册上写着每个工具的名称、用途、需要什么材料（参数）。当用户提出需求时，LLM会查阅手册，判断需要哪个工具，然后写一份工单（tool_calls）给你，你再去实际执行。</font>**

### 6.6 手动执行 Function Calling
理解手动流程有助于掌握底层原理：

```python
from langchain_core.messages import ToolMessage

# 假设 response 是上面 bind_tools 后调用的结果
if response.tool_calls:
    tool_results = []
    for call in response.tool_calls:
        # 根据工具名找到对应的函数并执行
        if call["name"] == "get_weather":
            result = get_weather.invoke(call["args"])
            # 把执行结果封装成 ToolMessage
            tool_results.append(ToolMessage(
                content=result,
                tool_call_id=call["id"]  # 关联到对应的 tool_call
            ))
    
    # 把工具结果追加到消息列表，再发一次请求
    messages.extend([response] + tool_results)
    final_response = llm_with_tools.invoke(messages)
    print(final_response.content)
    # "成都今天天气晴朗，温度28°C，很适合出门~"
```

<font style="color:rgb(15, 17, 21);">总结一下：</font>**<font style="color:rgb(15, 17, 21);">LangChain 自定义工具 = function schema 自动生成 + 参数解析 + 结果封装</font>**<font style="color:rgb(15, 17, 21);">，底层跑的就是 function calling，但 LangChain 让你不用手写 schema、不用手动解析 </font>`<font style="color:rgb(15, 17, 21);">tool_calls</font>`<font style="color:rgb(15, 17, 21);">、不用操心异步调度，把整个流程标准化了。</font>

### 6.7 用 Agent 自动编排全流程
大模型:负责理解

Tools：负责干活

Agent: 负责编排调度

LangChain 的 Agent 能自动完成"分析 → 调工具 → 整合结果"的完整循环：

```python
from langchain.tools import tool
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
import requests

# ─── 第一步：定义工具 ───
@tool
def get_weather(location: str) -> str:
    """查询指定城市的天气"""
    url = f"https://wttr.in/{location}?format=j1&lang=zh"
    data = requests.get(url).json()
    current = data['current_condition'][0]
    desc = current['weatherDesc'][0]['value']
    temp = current['temp_C']
    return f"{location}：{desc}，{temp}°C"

@tool
def multiply(a:int,b:int) ->int:
    """实现两个整数相乘"""
    return a * b

tools = [get_weather, multiply]

# ─── 第二步：配置大模型 ───
llm = ChatOpenAI(
    model_name="deepseek-v4-flash",
    api_key="",
    base_url="https://api.deepseek.com"
)

# ─── 第三步：创建 Agent ───
# create_agent 把模型、工具、prompt 组装成 Agent
agent = create_agent(
    model=llm,
    tools=tools,
    system_prompt="你是一名智能助手，可以调用工具帮助用户解决问题。"
)
```

```python
# ─── 第四步：使用 ───

     "content": "成都的天气怎么样？"
     }]})

print(res)
```
