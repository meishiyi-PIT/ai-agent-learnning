## 二、核心知识点精讲

### 1. 为什么提示词有用：从原理倒推

模型逐 Token 猜"下一个最可能的词"。**你给的提示词就是它猜测的全部依据**。"你是一位资深产品经理"之所以有效，是因为这句话把模型的概率分布"推"向了训练数据里产品经理文本的区域——它不是真的换了个人格，而是**条件概率被改变了**。理解这一点，所有技巧都不神秘：

- 角色扮演 = 把分布锚定到某个领域的语料风格；
- 给示例 = few-shot / 上下文学习（in-context learning），模型照着输入输出的映射模式继续；
- 指定格式 = 缩小候选空间，让"下一个 Token"更可预测；
- 消除歧义 = 避免概率质量分散到你不想要的解释上。

提示词工程的核心卖点：**不重新训练模型、零成本切换任务**。传统 NLP 换任务要微调参数，这里只改输入文本。

### 2. 六要素结构（Role / Instruction / Context / Example / Input / Output）

六个槽位各司其职：角色定"谁来答"、指令定"做什么"、上下文定"在什么背景下"、示例定"照什么样子"、输入是"待处理的料"、输出格式定"交付形态"。**简单任务只需指令+输入，别教条**。课件的合同审查示例值得反复读：它把六要素分别写成 Python 字符串变量再用 f-string 拼装——这个"提示词模块化"的写法就是 LangChain PromptTemplate 的雏形。

注意：课件称此为"RICHEO 框架"，这个名字业界查无出处（见勘误），**记住六个要素本身即可，别背这个缩写**。

### 3. 调优五法则——每条背后的原因

1. **简洁**：无关内容会分走注意力权重（第 1 讲的注意力机制），噪声多了模型抓不住重点；
2. **具体**："一些""合适的"在概率上没有约束力，数字和标准才有；
3. **上下文充分**：模型没有你的背景知识，猜测你的场景只会用"训练数据里最常见的场景"兜底；
4. **消除歧义**：多义词让概率质量分裂；
5. **逻辑自洽**：互相矛盾的要求（"通俗但要完整数学推导"）会让输出在两个目标间摇摆。

### 4. 思维链（CoT）：为什么"分步想"能提高正确率

自回归模型每生成一个 Token 只做一次固定量的计算。让它直接吐答案，等于要求"一步算完"；让它先输出推理步骤，等于**把计算摊到更多 Token 上**，每一步还能以前面已写出的中间结果为条件。这就是 CoT 有效的机制性解释。

三种用法：

| 方式 | 做法 | 代价/效果 | 出处 |
| :--- | :--- | :--- | :--- |
| 标准 CoT（Few-shot CoT） | 人工写好带完整推理过程的示例 | 效果最好，费人工 | Wei et al. 2022, arXiv:2201.11903 |
| Zero-shot CoT | 只加一句"请一步步思考"（Let's think step by step） | 零成本，效果次之 | Kojima et al. 2022, arXiv:2205.11916 |
| Auto-CoT | 问题聚类→每簇选代表题→用 Zero-shot CoT 自动生成推理示例→拼成示例库 | 兼顾效果与人工成本 | Zhang et al. 2022, arXiv:2210.03493 |

### 5. 自我一致性（Self-Consistency）

同一道题用**较高温度采样 N 条不同推理路径**，对最终答案做多数表决。原理：单条推理路径可能在某步出错，但不同路径在同一处犯同样错误的概率低；正确答案往往能从多条路径殊途同归。注意它的定位是**提升推理准确率的解码策略**（配合 CoT 使用），不是治理幻觉的通用手段（见勘误第 4 条）。代价是 N 倍的调用成本——工程上要在准确率和成本间权衡。

### 6. 实战模式：自然语言转 SQL

课件 NL2SQL 案例浓缩了工程化提示词的标准套路，值得当模板背下来：
1. **注入 Schema**：把表结构（字段、类型、注释、主外键）完整给模型，让它在"沙盒"内生成，不许臆造字段；
2. **低温度**（0.2）：SQL 要确定性，不要创意；
3. **双重格式约束**：system 消息压一句"只输出 JSON"，user 提示词里再给出 JSON 模板；
4. **防御性解析**：模型可能用 ```json 围栏包裹输出，代码里先剥围栏再 `json.loads`，解析失败要有兜底分支。

### 7. Prompt 注入攻防

- **本质**：LLM 的指令和数据走**同一条通道**（都是提示词文本），模型无法从机制上区分"这是老板的命令"还是"这是待处理的数据里夹带的命令"——这是 AI 版 SQL 注入，且比 SQL 注入更难根治（SQL 有参数化查询，LLM 没有等价物）。OWASP 将其列为 LLM 应用十大风险之首（LLM01）。
- **三个攻击场景**：代码注释投毒（污染 AI 编码助手）、网页隐藏指令劫持 Browser Agent、多 Agent 链上的蠕虫式传播（上游被污染→沿工作流感染下游）。
- **五层防御**：输入过滤（黑名单）、上下文隔离（system/user 角色分离）、提示词加固（预先声明安全规则）、输出监控、对抗训练+红队测试。要点：**没有任何单层是可靠的，只能纵深防御、降低概率**；黑名单尤其容易被改写措辞绕过（换语言、编码、拆词即可躲开关键词匹配）。

## 三、课件勘误与更新

1. **课件原文**：`api_key=api_key = os.getenv('OPENAI_API_KEY')`（出现两处：4.6 自我一致性示例、第五章 NL2SQL 示例的 `OpenAI(...)` 调用里）
   **问题类型**：错误（Python 语法错误，代码无法运行）
   **正确说法**：函数调用的关键字参数里不允许再写赋值语句，运行会直接 `SyntaxError`。应改为 `api_key=os.getenv('OPENAI_API_KEY')`。
   **来源**：Python 官方语法参考（调用表达式）https://docs.python.org/3/reference/expressions.html#calls

2. **课件原文**：自我一致性示例中 `model="deepseek-chat"` 搭配 `n=5,  # 生成 5 个独立回答`
   **问题类型**：错误（API 不支持该参数）
   **正确说法**：DeepSeek 官方 API 文档明确 `n` 参数**不支持**——传入不会报错，但会被静默忽略，永远只返回 1 个 choice。课件代码实际只会收集到 1 个候选答案，"5 选 1 投票"名存实亡。正确做法：循环/并发调用 5 次，或换用原生支持 `n` 的 OpenAI 等 API。
   **来源**：https://api-docs.deepseek.com/api/create-chat-completion/

3. **课件原文**："业界有时称之为 RICHEO 框架"
   **问题类型**：不严谨（查无此名）
   **正确说法**：检索不到任何名为 "RICHEO" 的业界框架。结构相同或相近的公开框架叫 **RICE**（Role/Instruction/Context/Examples）、**RICCE**、**RICECO**（多了 Constraints/Output）。疑为课件自创或拼写变体，六要素内容本身没有问题。
   **来源**：https://github.com/jfowlSpark/RICE-Framework 、https://www.fabrixai.com/blog/using-the-riceco-framework-to-create-better-ai-prompts

4. **课件原文**："大模型有个著名的问题叫'幻觉'……自我一致性的应对策略非常朴素"
   **问题类型**：不严谨（概念错位）
   **正确说法**：Self-Consistency 原论文（Wang et al.）解决的是 **CoT 推理的采样不稳定问题**——对多条推理路径的答案做边际化/多数表决，以提升算术、常识推理准确率；它不是针对幻觉的技术。对知识性幻觉（编造论文、法条），多数表决可能只是"多次编造同一个错误"，应对手段是 RAG、引用溯源等。
   **来源**：https://arxiv.org/abs/2203.11171

5. **课件原文**：三段示例代码均为 `client = OpenAI(base_url="", api_key=...)`，且用 `OPENAI_API_KEY` 环境变量装第三方（Kimi/DeepSeek）的密钥
   **问题类型**：不严谨（照抄无法运行，易误导）
   **正确说法**：`base_url` 留空跑不通，必须填对应厂商端点：Moonshot（kimi 系列模型）为 `https://api.moonshot.cn/v1`，DeepSeek 为 `https://api.deepseek.com`。环境变量名建议按厂商命名（如 `MOONSHOT_API_KEY`、`DEEPSEEK_API_KEY`），避免与真正的 OpenAI 密钥混淆——OpenAI SDK 会自动读取 `OPENAI_API_KEY`，混用是常见事故源。
   **来源**：https://api-docs.deepseek.com/ （首页 base_url 说明）、https://platform.moonshot.cn/

6. **课件原文**：`model="deepseek-chat"`（自我一致性示例）
   **问题类型**：已过时（端点更替）
   **正确说法**：DeepSeek 于 2026 年 4 月发布 V4 预览版（V4-Pro / V4-Flash，百万上下文），官方公告 `deepseek-chat` / `deepseek-reasoner` 旧端点于 2026 年 7 月下旬起转向 V4 体系并停用旧名。写课件时（2025）该模型名有效，现在跑课件代码前应查 DeepSeek 最新模型列表。

## 四、课件没讲透的关键点补充

### 1. messages 数组与三种角色（课件代码用了却没解释）

Chat API 的输入不是一个字符串，而是一个消息列表，每条消息有 `role`：
- `system`：开发者设定的最高优先级指令（人设、规则）——模型被训练成对它更"服从"；
- `user`：用户输入；
- `assistant`：模型历史回复（多轮对话时由你回传）。

**多轮对话的"记忆"是假的**：API 无状态，每次请求你都要把全部历史 messages 重发一遍，所以轮数越多越贵——这就是后续"记忆系统"模块要解决的问题。课件 NL2SQL 例子把"只输出 JSON"放进 system，就是利用 system 优先级做格式与安全加固。

### 2. temperature / top_p / n 的机制（课件用了 0.1 / 0.2 / 0.8 却没说为什么）

模型输出的是整个词表的概率分布。`temperature` 缩放分布的尖锐程度：低温（0~0.3）适合 SQL、抽取、投票判定这类要确定性的任务；高温（0.7~1.0）用于要多样性的场景（自我一致性采样正是靠高温制造不同推理路径）。`top_p` 截断候选集合的尾部。`n` 让服务端一次采样多个独立回答（省去重发提示词，但 DeepSeek 等部分厂商不支持，见勘误 2）。**记法：自我一致性 = 高温采样制造分歧 + 低温投票收敛结论**，课件代码里两处温度一高一低就是这个用意。

### 3. 结构化输出的"正规军"做法

课件用"提示词约束 + 手工剥 ```json 围栏"是通用兜底法，但主流 API 已有更稳的机制：
- `response_format={"type": "json_object"}`（JSON 模式，OpenAI/DeepSeek 均支持）：强制合法 JSON；
- JSON Schema / 结构化输出：连字段结构都强制；
- **Function Calling / 工具调用**：把期望结构定义成函数参数 schema，模型返回结构化参数——这是后续 Agent/MCP 模块的基石。
生产建议：能用 API 级约束就别裸靠提示词；两者叠加最稳。参考：https://api-docs.deepseek.com/guides/json_mode

### 4. 推理模型时代，CoT 提示要"看对象下菜"

2025 年后大量模型自带推理链（DeepSeek-R1、思考模式的 Kimi/Qwen 等）。DeepSeek-R1 论文明确提示：对 R1 **few-shot 提示反而会降低表现**，官方建议零样本、直接描述问题并指定输出格式。也就是说：对普通模型，课件的标准 CoT 依然有效；对推理模型，"请一步步思考"和多示例可能是多余甚至有害的。**先弄清对面是不是推理模型，再决定用不用 CoT 模板。**
来源：https://arxiv.org/abs/2501.12948 （DeepSeek-R1 论文，Discussion/Usage Recommendations）

### 5. 流式输出（stream=True）的工作方式

课件 4.2 代码用了流式却没解释：非流式是等模型全部生成完一次性返回；流式是服务端边生成边推送增量片段（chunk），每个 chunk 里是 `delta`（增量），不是完整消息。所以代码逐 chunk 打印 `delta.content`。注意两个坑：首个/末尾 chunk 的 `delta.content` 可能为 `None`（课件代码会打印出字符串 "None"，应写 `chunk.choices[0].delta.content or ""`）；聊天 UI 的"打字机效果"就是流式，能大幅改善体感延迟。

### 6. 为什么黑名单过滤挡不住注入

关键词黑名单是**模式匹配**，攻击者只需改写措辞：换语言（用法语写"忽略之前指令"）、Base64 编码、拆字、同义改写、把指令藏进"翻译这段话"的任务里。防御必须假设过滤会被绕过，所以课件的五层是"纵深"而非"选一"。进一步阅读：OWASP GenAI 风险清单 https://owasp.org/www-project-top-10-for-large-language-model-applications/

## 五、Python 随堂补基础

本讲代码量大，以下是基础薄弱学员最容易卡住的语法点：

**1. f-string 与三引号（课件拼提示词的核心手法）**
```python
name = "小明"
s1 = f"你好，{name}"           # f 开头，{} 里放变量或表达式
s2 = f"""多行字符串
也可以插值：{1 + 1}"""
s3 = f'{{"key": "value"}}'      # 想输出字面量大括号，就写两个：{{ }}
```
课件 NL2SQL 提示词里 `{{"sql": ...}}` 用双大括号，就是为了在 f-string 里输出 JSON 模板的 `{}`。

**2. 环境变量与 .env（为什么不把密钥写进代码）**
```python
import os
from dotenv import load_dotenv  # pip install python-dotenv
load_dotenv()                    # 读取项目根目录 .env 文件到环境变量
key = os.getenv("DEEPSEEK_API_KEY")   # 取不到时返回 None，不报错
```
密钥写死在代码里一旦提交 Git 就泄露，这是"红线级"常识。

**3. 函数定义、关键字参数、默认返回**
```python
def add(a, b=10):        # b 有默认值
    """这是 docstring，写函数用途"""
    return a + b
add(5)                   # 15
add(a=5, b=1)            # 6，关键字参数可乱序
```
`client.chat.completions.create(model=..., messages=..., temperature=0.2)` 全是关键字参数。

**4. 字典、列表与 JSON**
```python
import json
d = {"name": "王大叔", "apples": [45, 18]}
s = json.dumps(d, ensure_ascii=False)  # dict -> JSON 字符串
d2 = json.loads(s)                     # JSON 字符串 -> dict
print(d2["apples"][0])                 # 45，字典取值用键，列表取值用下标
```
messages 就是"列表套字典"；模型返回的 JSON 文本要用 `json.loads` 才能变成可编程的 dict。

**5. try / except：解析可能失败时的保险丝**
```python
try:
    data = json.loads("这不是JSON")
except json.JSONDecodeError:
    data = None          # 解析失败走这里，程序不崩
```
课件 `generate_sql` 的容错就是这个结构；`except KeyboardInterrupt` 则是捕获 Ctrl+C。

**6. 字符串查找与切片（剥 ```json 围栏用到）**
```python
text = "前缀```json{\"a\":1}```后缀"
start = text.index("```json") + 7   # index 返回子串位置，找不到会抛异常
end = text.index("```", start)      # 从 start 之后继续找
core = text[start:end].strip()      # 切片[起:止]，strip() 去首尾空白
```

**7. for 循环 + enumerate（带序号遍历）**
```python
steps = ["读题", "列式", "验算"]
for i, s in enumerate(steps, 1):    # 第二个参数是起始序号
    print(f"{i}. {s}")              # 1. 读题 ...
```

**8. join + 生成器表达式（把多个答案拼成一段文本）**
```python
answers = {0: "答案A", 1: "答案B"}
text = "\n".join(f"【答案{i+1}】{a}" for i, a in answers.items())
```
课件用 `chr(10)` 表示换行符（字符编码 10 = \n），是因为旧版 Python 的 f-string 表达式内不允许写反斜杠；Python 3.12+ 已允许直接写 `"\n".join(...)`，可读性更好。

**9. while True + break / continue（交互循环）**
```python
while True:
    cmd = input(">>> ").strip()
    if cmd == "q":
        break        # 跳出循环
    if not cmd:
        continue     # 跳过本轮，回到循环开头
    print("你输入了", cmd)
