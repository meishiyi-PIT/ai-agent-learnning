# Vibe Coding 与 Spec Coding 急速开发流 复习笔记

> 对应课件：3.Vibe Coding 与 Spec Coding 急速开发流.md

## 一、在知识体系中的位置

**前置依赖**：
- 第 1 讲：知道大模型能做什么、边界在哪（为什么 AI 会写出"能跑但乱"的代码——因为它是概率生成，不保证架构合理）；
- 第 2 讲：CLAUDE.md、Cursor Rules、AGENTS.md 本质都是**系统级提示词**，是第 2 讲提示词工程的工程化落地；PRD/SPEC 提示词模板就是六要素的应用。

**这一讲在课程里的角色**：它是从"用 API 聊天"跨到"AI 自主干活（Agent）"的桥梁。课件反复出现的 **LLM Loop（想→做→看→再想）** 正是后续所有 Agent 模块的核心循环：

| 本讲概念 | 后续模块的呼应 |
| :--- | :--- |
| LLM Loop（大模型循环） | **Agent / LangGraph**：Agent 就是"LLM + 工具 + 循环控制"，LangGraph 用图来编排这个循环 |
| MCP 服务器（连数据库/工单） | **MCP** 专题模块 |
| Skills（可复用方法论） | **Agent Skills** 专题模块 |
| Subagents（独立上下文、只带结论回来） | **Multi-Agent / A2A**：子代理协作、上下文隔离 |
| Agentic Search vs 传统 RAG | **RAG / Agentic RAG**：两种"让 AI 获取信息"路线的对比 |
| CLAUDE.md 分层、上下文压缩 | **记忆系统**：项目级持久记忆 vs 会话级临时记忆 |

## 二、核心知识点精讲

### 1. Vibe Coding vs Spec Coding：一个光谱的两端

- **Vibe Coding**（直觉/交互式）：说意图、AI 落地，走"生成→跑→改"的快循环。四条信条——意图先行、快速试错、信任但抽查、喂好上下文。**适合**原型、练手、前端这类"一眼看得出对不对"的活；**不适合**金融/医疗核心业务、安全敏感、性能极致场景。
- **Spec Coding / SDD**（规范驱动）：动手前先跟 AI 签"合同"——做什么（PRD）、怎么做（SPEC）、做到什么程度（质量规范）。项目一变大，光靠直觉会撞四堵墙：质量失控、前后矛盾、只见树木不见森林、协作噩梦。

关系不是二选一，而是**随项目复杂度演进**：Vibe Coding → Agentic Engineering（工程化）→ SDD。小项目 vibe 就够，大项目必须上规范。

深一层理解：为什么 AI 需要"合同"？因为大模型是概率生成器，**上下文没约束时，它会在无数合理实现里随机挑一个**，不同会话挑的还不一样（前后矛盾的根源）。规范文档 = 把选择空间收窄成"你要的那一种"。

### 2. 为什么说 Claude Code 是 Agent 而非聊天框：LLM Loop

- **聊天 AI**：你问一句→答一句，主动权始终在你手里，AI 是"高级应答机"。
- **Agent（Claude Code）**：你给目标→它自己拆步骤→调工具（读/写文件、跑命令）→看结果→决定下一步→循环到完成。**主动权移交给了 AI**。

这个"想→做→看→再想"的自主循环就是 LLM Loop，是 Agent 的定义性特征。后续 LangGraph 就是用状态图显式地编排、控制这个循环（加分支、加条件、加人工审核节点）。

### 3. Harness 七层扩展架构（Claude Code 的可扩展性）

课件列的七层是理解 Claude Code 生态的骨架，逐层递进：

| 层 | 是什么 | 记忆锚点 |
| :--- | :--- | :--- |
| CLAUDE.md | 项目备注/规矩，每次会话自动读 | "入职手册" |
| Hooks | 生命周期钩子，事件触发 | "自动化触发器" |
| Skills | 可复用方法论，按需加载 | "打包好的 SOP" |
| Plugins | Skills+Hooks+MCP 打包 | "整套插件包" |
| LSP | 语言服务器，给 AI 装"跳转定义/查引用" | "IDE 能力" |
| MCP 服务器 | 连外部工具（DB/文档/工单） | "对外接口" |
| Subagents | 独立上下文的子实例，只带结论回来 | "外派专员" |

关键理解：**上下文是稀缺资源**（第 1 讲的 KV Cache 成本），所以这套架构的设计哲学是"按需加载、隔离污染"——Skills 用时才加载、Subagents 独立上下文只回传结论，都是为了不把主上下文塞爆。

### 4. Agentic Search vs 传统 RAG（本讲最重要的对比之一）

Claude Code 读代码的方式不是先建向量索引，而是**像新人入职**：翻目录→读关键文件→grep 搜关键字→顺调用链追→脑中拼全景。

| 维度 | 传统 RAG | Agentic Search |
| :--- | :--- | :--- |
| 怎么找 | 全库转向量，按相似度捞 | 现场翻文件/grep/追引用 |
| 要索引服务器吗 | 要，还要维护 | 不要 |
| 代码变了 | 索引可能过期，返回旧代码 | 永远读实时代码 |
| 最适合 | 基本不动的老库 | 活跃开发、百万行 monorepo |

这个对比会在 RAG 模块反复出现：**不是所有"让 AI 获取信息"的场景都得建向量库**。代码这种结构清晰、变动频繁、有精确检索工具（grep/LSP）的场景，Agentic Search 更合适；而海量非结构化文档、需要语义模糊匹配的场景，向量 RAG 才有优势。二者是互补而非替代。

### 5. CLAUDE.md 三层级与实战规则

- **全局**（`~/.claude/CLAUDE.md`）：个人习惯、语言偏好（如"永远用中文回答"）；
- **项目**（项目根 `CLAUDE.md`）：技术栈、架构、规范、进度，可提交 Git 团队共享；
- **文件夹**（子目录 `CLAUDE.md`）：模块专属约定。
- **优先级：文件夹级 > 项目级 > 全局级**（越近越优先）。在子目录启动时，Claude Code 会向上遍历、把沿途各级 CLAUDE.md 都加载。

维护心法（课件金句）：**"每被 AI 坑一次，马上加一条进 CLAUDE.md"**，让它成为"这个项目 AI 犯过的所有错的预防手册"。但注意配套的反面提醒——见下方第 9 点/勘误：规则也会过时，要定期删。

### 6. 四阶段工作流：Explore → Plan → Implement → Commit

| 阶段 | 你做什么 | 模式 |
| :--- | :--- | :--- |
| 探索 | 指出要动哪块，让 AI 读代码理清现状 | Plan Mode（只读） |
| 规划 | 让 AI 出方案、评估边界，你审核 | Plan Mode |
| 执行 | 确认后按步骤改文件、跑构建 | Normal / Auto-Accept |
| 提交 | 让 AI 写 commit message，可开 PR | Normal |

一句话判据：**能一句话说清就直接干，说不清就先规划**。Plan Mode（只读规划）是防止 AI 在你没看清方案前就乱改的安全阀。

### 7. 工程纪律三件套

- **动手先存档**（Git commit）：让 AI 大改前先 commit，翻车就 `git checkout .` 回滚。课件称这是"AI 编程里最常见也最痛的翻车"，五个字刻进肌肉记忆。
- **任务颗粒度小**：经验值 **单次任务 ≤ 5 个文件 / 200 行改动**，超了就拆。大需求一句话甩给 AI 是"最坑的做法"。（注意：这条经验随模型能力增强在放宽，见勘误/补充第 9 点）
- **上下文管理**：`/context` 看占比 →超 60% 用 `/compact` 压缩 →换任务用 `/clear` 重开。心法："宁可多 clear 几次重新介绍背景，也别一直聊"。

### 8. 成本优化：模型分层 + 精准喂上下文

- **模型分层**：简单活用便宜快模型，硬骨头才上最强模型（"不是每次出门都打专车"）。
- **`@` 精准喂文件**：反直觉认知——**指令越短，AI 花的 token 可能越多**，因为它得花力气探索项目猜你要什么。明确 `@文件` + 具体描述，成本反而更低、结果更准。
- 省钱手段：分层调用、一次说清、及时 `/compact`、`/cost` 监控、Console 设预算上限。

### 9. 配置会过时：给自己的规则做"体检"

课件末尾这条常被忽略但极重要：**你给上一代模型写的规则，换到新模型上可能帮倒忙**。两个官方案例：CLAUDE.md 里"每次只改一个文件"（新模型能跨文件协调，这条成了绊脚石）；每次写文件跑 `p4 edit` 的 Hook（Claude Code 已原生支持 Perforce，Hook 多余）。建议每 3–6 个月或大版本更新后过一遍配置，问自己："这条还有用吗？有没有更好写法？这是在补哪代模型的短板？"

信号灯：如果觉得 AI 表现到了天花板，**八成不是模型的问题，是配置没跟上**。

## 四、课件没讲透的关键点补充

### 1. Plan Mode 到底是什么、怎么进（课件反复提但没说操作）

Plan Mode 是 Claude Code 的**只读规划模式**：AI 能读文件、搜索、分析，但**不能改文件、不能跑有副作用的命令**，只输出一份计划让你审。它是"Explore/Plan 两阶段"的安全保障——你没点头前，它碰不了你的代码。这与后续 LangGraph 里"human-in-the-loop（人工审核节点）"是同一个思想：在自主循环里插入人工确认点。

### 2. Git 回滚为什么是 AI 编程的救命稻草

`git checkout .` 丢弃工作区改动、`git reset` 回退提交——因为 AI 可能一次改十几个文件，人工逐个撤销不现实。**把每次"让 AI 干活"当成一次实验**：commit 是存档点，失败就读档重来。进阶：用 `git worktree` 或分支让多个 AI 任务并行互不干扰（Codex Desktop 已内置 worktree 支持，正是这个思路）。

### 3. MCP 到底解决什么问题（课件只说"连外部工具"）

大模型本身是"纯文本动物"（第 1 讲），它不能直接查数据库、调 API、读工单。MCP（Model Context Protocol）是 Anthropic 提出的**开放标准**，规定了"AI 如何统一地发现和调用外部工具/数据源"——好比给 AI 装了个 USB 接口，任何遵守协议的工具（数据库、Jira、文件系统）都能即插即用。这是后续 MCP 专题的核心，本讲先建立"为什么需要它"的直觉即可。

### 4. Subagents 与上下文隔离：为什么"只带结论回来"

如果让主 Agent 亲自读 50 个文件找一个答案，这 50 个文件会把主上下文塞满（KV Cache 成本 + lost in the middle）。派一个 Subagent 去读、只把"结论"回传，主上下文就干净了。这就是 Multi-Agent 架构的底层动机之一：**用上下文隔离换取规模**。理解这点，后面 Multi-Agent / A2A 就不再抽象。

### 5. CLAUDE.md / .cursorrules / AGENTS.md 是"同一件事的三个方言"

三者都是"系统级提示词的持久化"——把每次都要重复解释的项目背景，一次性写进配置文件，每次会话自动加载。理解这个统一本质，就不会被三个不同文件名绕晕。它们本质是第 2 讲提示词工程里 **system 消息** 的项目级固化版本。

### 6. 为什么"任务颗粒度小"这条正在被放宽

课件同时说了"≤5 文件/200 行"和"新模型能跨文件协调（旧的'只改一个文件'规则成了绊脚石）"——这看似矛盾，实则是**同一趋势的两面**：模型越强，单次能可靠处理的改动越大。所以这些数字是"当前经验值"，不是物理定律。学员要理解的是背后的原则——**改动越大越难审查、越难回滚、上下文越容易失焦**——而不是死记 200 这个数。

### 7. Vibe Coding 的真实风险（课件点到为止）

"信任但抽查"里的"抽查"绝不能省。AI 生成的代码常见隐患：不做输入校验、把密钥写进代码、SQL 拼接（注入）、错误吞掉不报、依赖幻觉出的库名。前端"一眼看得出对不对"，但安全漏洞恰恰"一眼看不出"——所以课件才把"安全敏感模块"划为 Vibe Coding 禁区。这与第 2 讲的 Prompt 注入防御一脉相承：**AI 参与得越深，审查越不能松。**

## 五、Python 随堂补基础

本讲**无 Python 代码**（课件出现的代码块是目录树、Bash 命令 `cd`/`claude`、Git 命令、Markdown 模板，不是 Python）。这里补几个学员会照着敲的**命令行/工具基础**：

**1. 终端切目录与启动（课件 5.1.3 用到）**
```bash
cd services/payment    # 进入子目录（钻进去再启动 Claude Code，缩小工作范围）
claude                 # 在当前目录启动 Claude Code
```

**2. Git 存档/回滚三连（"动手先存档"）**
```bash
git add -A && git commit -m "存档：AI 改动前"   # 存档点
# —— 让 AI 干活 ——
git checkout .          # 翻车了：丢弃工作区所有未提交改动，回到上次存档
git commit -m "AI 改动没问题，继续"             # 满意了：再存一个档
```

**3. 项目里的关键文件都是纯文本，用编辑器直接改**
- `CLAUDE.md` / `AGENTS.md` / `.cursorrules`：Markdown 文本，谁都能读能写；
- `.env`：`KEY=VALUE` 一行一条，**绝不提交 Git**（写进 `.gitignore`）。
