## 一、在知识体系中的位置

这一讲是整个课程的**地基**，没有前置依赖，但后面几乎每个模块都建立在它之上：

| 本讲概念 | 后续哪里会用到 |
| :--- | :--- |
| "大模型 = 逐 Token 预测下一个词" | **提示词工程**（第 2 讲）的全部技巧都基于这个本质 |
| Token / 上下文窗口 / 计费 | **LangChain**（API 调用参数）、**RAG**（切块大小怎么定）、所有模块的成本控制 |
| 知识截止 + 幻觉 | **RAG / Agentic RAG** 存在的根本理由——用检索补知识、用引用治幻觉 |
| "模型没有长期记忆" | **记忆系统** 模块：为什么要外挂记忆而不是指望模型自己记住 |
| 能力边界（不会实时计算、不能碰真实世界） | **Agent / MCP / LangGraph**：为什么要给模型装工具、让它调用外部系统 |
| 注意力机制 / 上下文是"平铺"的 | **Multi-Agent / A2A**：为什么要拆分上下文、让多个 Agent 各管一摊 |

一句话：这一讲解释了大模型"能什么、不能什么、为什么"，后面所有模块都是在**绕开它的短板、放大它的长处**。

## 二、核心知识点精讲

### 1. 概念套娃：AI ⊃ 机器学习 ⊃ 深度学习 ⊃ 大语言模型

- **AI**：让机器表现出"像人"的智能，是最大的圈。
- **机器学习（ML）**：不再由人写死规则，而是让机器**从数据里自己归纳规律**。为什么需要它？因为很多任务（识别猫、理解语言）的规则人类根本写不出来。
- **深度学习（DL）**：用多层神经网络做机器学习。"深"指层数多。为什么要深？每一层提取一层抽象——底层认边缘，中层认形状，高层认"这是一只猫"。层数够深才能表达足够复杂的映射。
- **LLM**：深度学习专攻语言的分支，架构清一色是 Transformer。

关键取舍要记住：深度学习**用"海量数据 + 巨大算力"换掉了"人工设计特征"**，代价是可解释性差（黑箱）。

### 2. 神经网络的本质：一堆可调的旋钮

每个连接有一个权重（weight），训练 = 反复做三件事：
1. 前向计算：输入过一遍网络得到预测；
2. 算损失：预测和正确答案差多少（损失函数）；
3. 反向传播：按"哪个旋钮该往哪拧、拧多少"调整所有权重。

所谓"6710 亿参数"，就是 6710 亿个这样的旋钮。**训练的产物不是代码，而是这堆旋钮的最终位置。**

### 3. 大模型为什么"读"就能学会语言

预训练任务只有一个：**给定前文，预测下一个 Token**。这个任务看似简单，但要想预测得准，模型被迫学会语法、常识、逻辑、甚至代码规律——因为不懂这些就猜不对下一个词。这就是"没人教它语法，它自己悟出来"的真正含义：**语言能力是"预测下一个词"这个目标的副产品**。

这也直接解释了它的缺陷（见第 7 点）：它的目标从来不是"说真话"，而是"说得像"。

### 4. Transformer 为什么赢了 RNN

RNN 逐词串行处理，两大死穴：
- **长距离依赖**：信息一路传递会衰减，句子长了前面的内容就"忘"了；
- **无法并行**：必须算完第 1 个词才能算第 2 个，GPU 有几千个核心却只能干等。

Transformer 的自注意力让**每个词直接和所有词算相关性**（注意力分数），一步到位解决长距离依赖；而且所有位置可以同时计算，完美吃满 GPU 并行能力。**"能并行"意味着"能堆数据堆算力"，这才有了后来的规模竞赛。**

注意力三步：算相关性分数 → 按分数加权汇总各词的信息 → 每个词得到融合了上下文的新表示。课件里"她→小红 0.55"的例子就是这个过程的可视化。

因为 Transformer 把词"一把平铺"处理、天生没有顺序概念，所以要额外加**位置编码**（给每个词发号牌）。

### 5. Decoder-only 与自回归

现在主流大模型（GPT、DeepSeek、Qwen、Llama、Claude）都是 **Decoder-only** 架构：只保留解码器，用**自回归**方式生成——生成一个词，把它拼回输入，再生成下一个，循环往复。BERT 那类 Encoder（理解型）模型擅长分类、抽取，但不擅长生成，所以在"生成时代"退居幕后。

### 6. 三段式训练：每一步都不能省

| 阶段 | 学什么 | 为什么必须有 |
| :--- | :--- | :--- |
| **预训练** | 语言规律、世界知识 | 最烧钱（万亿级 Token、数千 GPU）。产物叫**基座模型（base model）**，只会"接话"不会"对话"——你问"什么是机器学习？"它可能接一句"这是期末考试第 3 题" |
| **SFT 监督微调** | 学会"好好回答问题"的格式 | 用人工写的高质量问答对，把"接话机器"掰成"回答机器"。数据量小但质量要求极高 |
| **RLHF** | 对齐人类偏好 | 很多"好回答"没法写成标准答案（礼貌、无害、详略得当），只能靠人类对多个回答**排序打分**，训练一个奖励模型，再用强化学习优化。副作用：标注员的偏见会被模型继承 |

面试级理解：**预训练给能力，SFT 给格式，RLHF 给品味。**

### 7. Tokenization：模型的"识字"方式

模型不认识字，只认识 Token（子词单元，主流算法是 BPE 一族）。按字切太碎、按词切遇生僻词就死，子词切分是折中：常见词整存，生僻词拆成常见碎片拼出来（unhappiness → un + happi + ness）。

为什么要关心：**上下文窗口和 API 计费都按 Token 算**。同一句话不同分词器切出的 Token 数不同；中文通常 1 个汉字 ≈ 0.5~1 个 Token（取决于分词器），直接影响成本估算。

### 8. 能力边界：为什么会幻觉

- **幻觉**：训练目标是"生成概率最高的下一个词"，不是"生成真话"。当它没有相关知识时，依然会生成"看起来最像答案"的文本——一本正经地胡说八道是**机制内生的**，不是 bug，无法彻底根除，只能缓解（RAG、引用来源、让它说"不知道"）。
- **知识截止**：训练数据有时间边界 → 解法是 RAG / 联网搜索。
- **无长期记忆**：模型参数在推理时是冻结的，每次对话从零开始 → 解法是外挂记忆系统（后续模块）。ChatGPT 等产品的"记忆"功能是**应用层**把历史信息塞回上下文，不是模型本身记住了。
- **不是计算器**：它按 Token 生成数字，不做精确运算 → 解法是给它计算工具（Function Calling / Agent）。

### 9. MoE：大而不贵

MoE（混合专家）把前馈网络拆成很多"专家"，每个 Token 只由路由器挑出的少数专家处理。例如 DeepSeek-V3 总参数 6710 亿，但每个 Token 只激活 370 亿。**总参数决定"知识容量"，激活参数决定"单次推理成本"**——这就是"模型很大，但每次只用一小部分"的含义。也因此，MoE 时代拿"总参数量"直接比较模型强弱已经失真。

## 三、课件勘误与更新

1. **课件原文**："DeepSeek-V3 6710 亿(MoE) 2025"（4.2 参数表）及编年史将 DeepSeek-V3 归入 2025 年
   **问题类型**：错误（时间不准）
   **正确说法**：DeepSeek-V3 于 **2024 年 12 月 26 日**发布，技术报告 2024 年 12 月挂出。2025 年 1 月发布的是 DeepSeek-R1。参数 671B 总量 / 37B 激活正确。
   **来源**：https://arxiv.org/abs/2412.19437 、https://huggingface.co/deepseek-ai/DeepSeek-V3

2. **课件原文**："DeepSeek-V3 的预训练用了 14.8 万亿个 Token，消耗的算力折合几千万美元"
   **问题类型**：不严谨（数字与官方口径差一个量级）
   **正确说法**：14.8 万亿 Token 正确。但官方技术报告给出的**全部训练成本为 557.6 万美元**（278.8 万 H800 GPU 时 × $2/时，其中预训练 266.4 万 GPU 时），不是"几千万美元"。注意官方口径只算"正式训练这一跑"，不含前期研究、消融实验和买卡成本——如果算总账"几千万"未必夸张，但课件表述容易让学员记错官方数字。
   **来源**：https://arxiv.org/abs/2412.19437 （报告第 1 节 Table 1）

3. **课件原文**："以 DeepSeek-VL2、Qwen-VL 为代表的多模态模型，可以同时处理文字、图片、音频甚至视频"
   **问题类型**：错误（以偏概全）
   **正确说法**：DeepSeek-VL2 是**图像 + 文本**的视觉语言模型（动态切图 + MoE），官方论文与仓库均不支持音频/视频输入。Qwen-VL 系列支持图像和视频理解，但音频属于 Qwen-Audio / Qwen-Omni 一类模型。"文字、图片、音频、视频全都能"的原生全模态模型直到 2026 年（如 Kimi K2.5/K2.6）才逐渐普及。
   **来源**：https://arxiv.org/abs/2412.10302 、https://github.com/deepseek-ai/DeepSeek-VL2

4. **课件原文**："参数量约每 18 个月翻 10 倍"（4.2 参数表底部）
   **问题类型**：不严谨
   **正确说法**：这个"定律"只在 2018–2020（GPT-1→GPT-3，约 1500 倍/2 年）成立。2020 年之后：前沿闭源模型不再公布参数量；开源侧 GPT-3(175B, 2020) → DeepSeek-V3(671B 总参数, 2024) 四年才约 4 倍；且 MoE 普及后"总参数"与"激活参数"分离，单一参数量指标已失去趋势意义。行业竞争重点已转向数据质量、推理时计算（reasoning）和架构效率。
   **来源**（用于对照的官方数字）：https://arxiv.org/abs/2005.14165 （GPT-3 175B）、https://arxiv.org/abs/2412.19437 （V3 671B/37B）、https://huggingface.co/Qwen/Qwen3-235B-A22B （235B/22B）

### 待核实

- "GPT-4 ~1.8 万亿(估) 2023"：OpenAI 从未公布 GPT-4 参数量，1.8 万亿是媒体/分析机构的推测值。课件标了"估"，处理得当，但学员应知道这不是官方数字，无法核实真伪。
- "训练数据几 TB 到几十 TB 的文本"：量级说法宽泛。按 14.8 万亿 Token 折算原始文本约数十 TB，勉强在课件区间上沿，但不同模型差异极大，此数字仅当量级感受即可。
- 编年史 2026 行"多模态原生模型成为主流，端侧部署兴起"：属趋势预判，方向上已被 2026 年上半年的原生多模态发布潮（如 Kimi K2.5 原生多模态、1T MoE）部分印证，但"主流""兴起"无法量化核实。

## 四、课件没讲透的关键点补充

### 1. temperature / top_p：模型"随机性"的真正来源（课件完全没讲）

模型每一步输出的不是一个词，而是**整个词表上的概率分布**（先算 logits 分数，再经 softmax 归一化成概率）。怎么从分布里挑词，就是采样策略：

- **temperature（温度）**：把 logits 除以 T 再 softmax。T→0 时概率最高的词一家独大（输出几乎确定，适合 SQL、代码、抽取）；T 越大分布越"平"，冷门词更容易被抽中（更有创意也更容易胡说）。
- **top_p（核采样）**：只保留累计概率达到 p 的头部候选词，在其中按比例抽。它和 temperature 是两道不同的闸门，一般**只调其中一个**。

第 2 讲代码里 `temperature=0.2`（SQL 生成）和 `temperature=0.8`（自我一致性要多样性）的取值，用的正是这里的原理。

### 2. 推理模型（Reasoning Model）：课件 2025 年那行的"推理能力大幅提升"是怎么来的

o1 / DeepSeek-R1 这类模型的思路叫**推理时计算（test-time compute）**：训练时用强化学习专门奖励"先输出长长的思考过程、再给答案"的行为，推理时让模型多"想"（多生成中间 Token）来换准确率。这条路线解释了 2024 年后行业为什么不再单纯堆参数——**堆训练算力的收益放缓后，改堆推理算力**。它与第 2 讲的思维链（CoT）一脉相承：CoT 是提示词层面要求"分步想"，推理模型是把"分步想"训练进了模型。

### 3. 上下文窗口为什么"贵"：KV Cache

自回归生成时，每生成一个新 Token 都要对前面所有 Token 做注意力计算。为了不重复计算，推理引擎会缓存每个历史 Token 的 Key/Value 向量（KV Cache）——上下文越长，显存占用和计算量越大，这就是长上下文又贵又慢、以及"超长文档丢中间细节"（lost in the middle）现象的工程根源。后续学 RAG 时会明白：**RAG 的本质之一就是"别把整本书塞进上下文，只塞相关的几页"来省这笔钱。**

### 4. Base 模型 vs Chat/Instruct 模型

去 Hugging Face 下载模型会看到 `Qwen3-8B-Base` 和 `Qwen3-8B` 两种。Base 是只做过预训练的"接话机器"；不带 Base 后缀的通常做过 SFT+RLHF，才能正常对话。**自己微调选 Base，直接使用选 Instruct/Chat**——这是后续本地部署（Ollama/vLLM）时的第一个选型问题。

### 5. 损失函数到底在算什么

预训练用**交叉熵损失**：模型给"真"预测了 45% 的概率，正确答案就是"真"，那损失 = -log(0.45)。概率给得越高损失越小。所谓"训练"就是在数万亿个这样的完形填空上，不断把正确词的概率往上推。理解这一点，"模型是统计规律的压缩"就不再是玄学。
