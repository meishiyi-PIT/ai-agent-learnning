# RoPE 旋转位置编码
---

## 一、正余弦位置编码 vs 旋转位置编码
### 1.1 传统的正余弦位置编码存在哪些问题?
位置编码的作⽤就是：给不同位置的 token 向量 “打上位置标记”，让模型知道谁在前、谁在后。

传统 Transformer 使用简单的**相加融合**:

```plain
最终输入 = 词嵌入 + 位置编码
```

**这种看似直观的设计却在实际应用中带来一系列问题:**

+ **❌**** 位置信息间接性**:模型需要通过复杂的注意力计算才能"学会"位置关系,无法在向量操作中直接体现相对位置。
+ **❌**** 外推能力受限**:处理超过训练长度的序列时效果显著下降,正余弦位置编码在超长序列中失去区分度。
+ **❌**** 计算效率低下**:需要额外的位置编码向量存储空间,注意力机制要额外学习位置关系。

**什么样的位置编码才是好的位置编码:**

1.q和k的内积应该和他们之前的距离呈现一定的关系，我们希望通过某种方式，降位置信息嵌入到注意力的计算中。使得计算出来的注意力分数依赖token之间的相对位置。

2.模型在训练时只见过长度为 Ltrain的序列，但在推理时能否处理比 Ltrain 更长的序列（Ltest>Ltrain），并且性能不出现严重下降。(训练短，推理长，还能用。)

### 1.2 什么是 RoPE(Rotary Position Embedding)旋转位置编码?
在每次计算自注意力分数时，让 **Q、K** 矩阵中的每个行向量根据各自的位置旋转一个角度。

假设位置为 m 的 token 向量是 (x1, x2)。那么 RoPE 会把它绕原点旋转 **mθ** 度。

| 位置 | 旋转角度 |
| --- | --- |
| 第 1 个 token | 旋转 0 |
| 第 2 个 token | 旋转 θ |
| 第 3 个 token | 旋转 2θ |

核⼼思想是通过旋转矩阵给 token 的向量 “旋转” 特定⻆度，从⽽将位置信息编码到向量中，既

能让模型理解 token 的位置关系，⼜能很好地⽀持⻓序列外推（处理⽐训练时⻓更⻓的⽂本）。

每个位置对应不同的旋转角度,位置信息就这样被优雅地"编码"到了向量的方向中。

### 1.3 RoPE 的数学之美:点积中自动出现相对位置
![​ q ​  ⋅R[(n−m)⋅θ].  k ​   : 两个分别位于位置  m  和  n 的向量，在进行了各自的位置 旋转后，它们的内积只取决于它们的原始向量和旋转角度差  ( n − m ) ⋅ θ  内积结果与它们的绝对位置  m 和  n 无关，只与相对距离  ∣ n − m ∣  有关。 q , K  计算完成以后的注意力权重的结果自然就带有了相对位置 信息。](https://cdn.nlark.com/yuque/0/2026/png/21571931/1790133963784-8f4c604c-e372-49a0-bcb7-90ade7713073.png)

当两个旋转后的向量进行点积运算时,会发生一个美妙的数学现象:

```plain
⟨旋转 m 的 q, 旋转 n 的 k⟩ 
=Qᵀ · R(n-m) · K
=Qᵀ · [[ cos((n-m)·θ)  -sin((n-m)·θ) ] · K
      [ sin((n-m)·θ)   cos((n-m)·θ) ]]
```

注意这个公式中的 `(m-n)`——这正是两个位置之间的**相对距离**!

+ 相对位置信息被自动嵌入到了向量运算的结果中
+ 模型无需额外学习位置关系
+ 注意力分数天然地包含了位置信息

这种设计让位置编码不再是"外加"的信息,而是**内在地融入**了向量的几何结构中。

**结论:注意力分数完全由相对位置差 (n−m) 决定。**

## 二、总结
| 对比维度 | 正余弦位置编码 | RoPE 旋转位置编码 |
| --- | --- | --- |
| 编码方式 | 词嵌入 + 位置向量(相加融合) | 对 Q/K 向量做旋转变换 |
| 位置信息 | 绝对位置,相对位置需模型间接学习 | 点积结果天然包含相对位置 (n−m) |
| 外推能力 | 超长序列区分度下降 | 相对位置设计,外推表现更好 |
| 计算开销 | 需额外存储位置编码向量 | 旋转操作,无额外存储 |
