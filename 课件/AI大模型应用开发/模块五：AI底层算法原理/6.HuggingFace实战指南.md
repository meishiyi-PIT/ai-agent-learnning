### 2.3 三种创建方式
```python
from transformers import pipeline, AutoModelForSequenceClassification, AutoTokenizer

# 方式一：只给任务类型
# transformers 会加载官方给该任务配的默认模型——通常是英文模型，中文场景基本用不上
# pipe = pipeline("text-classification")

# 方式二：任务 + 指定模型（日常最常用）
pipe = pipeline("text-classification", model="uer/roberta-base-finetuned-dianping-chinese")

# [{'label': 'positive (stars 5)', 'score': 0.99xx}]

# 方式三：先手动加载组件再组装（最灵活）
# 比如你想对 tokenizer 做定制、或复用已加载的模型时，就用这种
model = AutoModelForSequenceClassification.from_pretrained("uer/roberta-base-finetuned-dianping-chinese")
tokenizer = AutoTokenizer.from_pretrained("uer/roberta-base-finetuned-dianping-chinese")
pipe = pipeline("text-classification", model=model, tokenizer=tokenizer)
```

### 2.4 用 GPU 加速推理
默认情况下模型跑在 CPU 上。有显卡的话，一个 `device` 参数就能上 GPU：

```python
                device=device)

```

### 2.5 把 Pipeline 扒光：手动实现一遍
学工具最怕"会用但不知道它在干嘛"。下面不用 pipeline，纯手动复现一次文本分类推理，你会发现 pipeline 干的就是这三件事：

```python
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

model_id = "uer/roberta-base-finetuned-dianping-chinese"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForSequenceClassification.from_pretrained(model_id)

text = "这家外卖送得飞快，汤一滴没洒！"

# ===== 第一站：预处理 =====
# 文本 -> 模型能吃的数字张量（input_ids、attention_mask 等）
# return_tensors="pt" 表示返回 PyTorch 张量（pt = PyTorch）
inputs = tokenizer(text, return_tensors="pt")

# ===== 第二站：模型推理 =====
# **inputs 把字典展开成关键字参数喂给模型
# no_grad：推理不算梯度，省显存还更快
with torch.no_grad():
    outputs = model(**inputs)
logits = outputs.logits   # 每个类别一个原始分数，未归一化，形如 [[-1.2, 2.8]]

# ===== 第三站：后处理 =====
# softmax：把原始分数压成概率分布（所有类别概率之和为 1）
probs = torch.softmax(logits, dim=-1)
# argmax：找出概率最大的类别下标
pred_id = torch.argmax(probs, dim=-1).item()
# id2label：把下标翻译回人类可读的标签名（存在模型 config 里）
label = model.config.id2label[pred_id]

print(f"预测标签：{label}，置信度：{probs[0][pred_id]:.4f}")
```

看明白这三站，Pipeline 对你而言就没有黑盒了。接下来两章，就是把"预处理"和"模型"这两站放大细看。

## 第 3 章 Tokenizer：把人话翻译成模型能懂的数字
### 3.1 数据预处理四部曲
模型不认字，只认数字。Tokenizer 的工作就是把文本变成数字序列，标准动作四步：

1. **分词**：把句子切成 token（中文按字、英文按子词 subword）；
2. **查词表**：每个 token 在词表里有唯一 id（词表随模型不同而不同）;
3. **映射**：token 序列 → id 序列；
4. **填充与截断**：短的补齐、长的砍断，保证一个 batch 内长度一致。

### 3.2 基本操作
```python
from transformers import AutoTokenizer

# 加载 MacBERT 的分词器（哈工大讯飞联合实验室出品的中文预训练模型）
tokenizer = AutoTokenizer.from_pretrained("hfl/chinese-macbert-base")

text = "今天点的黄焖鸡米饭绝了！"

# 1) 分词：中文按字切
tokens = tokenizer.tokenize(text)
print(tokens)   # ['今', '天', '点', '的', '黄', '焖', '鸡', '米', '饭', '绝', '了', '！']

# 2) 词表有多大
print(tokenizer.vocab_size)   # 21128，沿用 BERT 中文词表

# 3) 编码：文本 -> id 序列，encode 会自动在首尾加上 [CLS]、[SEP] 两个特殊 token
ids = tokenizer.encode(text)
print(tokenizer.convert_ids_to_tokens(ids))   # 可以看到头尾的 '[CLS]' 和 '[SEP]'

# 不想要特殊 token？比如做文本相似度拼接时：
ids_plain = tokenizer.encode(text, add_special_tokens=False)

# 4) 解码：id 序列 -> 文本，skip_special_tokens=True 输出更干净
print(tokenizer.decode(ids, skip_special_tokens=True))
```

> **一个经典坑**：模型和分词器必须是"原配"。不同模型的词表不同，同一个字在 A 模型词表里是 1024 号，在 B 模型里可能是 2048 号——拿错分词器，等于拿错钥匙开锁，模型直接懵圈。
>

### 3.3 填充与截断
```python
# 填充到固定长度 15：不足的位置补 [PAD]（id 为 0）
padded = tokenizer.encode(text, padding="max_length", max_length=15)

# 截断：最多保留 5 个 token（含特殊 token），超长的直接砍掉
truncated = tokenizer.encode(text, max_length=5, truncation=True)
```

### 3.4 batch 处理与"三件套"
实际训练都是按 batch 喂数据的，一次编码多句：

```python
batch_texts = [
    "今天点的黄焖鸡米饭绝了！",
    "配送慢不说，汤还洒了一半，emo 了。",
]
res = tokenizer(batch_texts, max_length=20, padding="max_length", truncation=True)
```

返回结果里有三样东西（BERT 系模型的标准输入）：

| 字段 | 含义 | 生活化理解 |
| --- | --- | --- |
| input_ids | 每个 token 的词表 id | 句子的"身份证号序列" |
| token_type_ids | 区分句子 A / 句子 B（A 全 0，B 全 1） | 问答任务里区分"问题"和"原文" |
| attention_mask | 1 = 真实内容，0 = 填充位 | 告诉模型："那些凑数的 PAD 别理" |

## 第 4 章 Model：模型本体与"任务头"
### 4.1 什么是 Model Head
同一个预训练底座（比如 MacBERT），能干分类、能搞问答、能做 NER，差别就在**任务头（Head）**——底座负责把文本编码成向量，任务头负责把向量映射成任务要的输出格式。

类比一下：底座是发动机，任务头是变速箱。同一台发动机，换个变速箱就能干不同的活。

### 4.2 常见 Head 家族
| 类名 | 输出 | 适用任务 |
| --- | --- | --- |
| AutoModel | 每个 token 的向量（无任务头） | 提取特征、二次开发 |
| AutoModelForSequenceClassification | 整句一个类别 | 情感分析、文本分类 |
| AutoModelForTokenClassification | 每个 token 一个类别 | NER、词性标注 |
| AutoModelForQuestionAnswering | 答案在原文中的起止位置 | 抽取式问答 |
| AutoModelForCausalLM | 下一个 token 的概率 | GPT 类生成、大模型对话 |
| AutoModelForSeq2SeqLM | 编码器+解码器生成序列 | 翻译、摘要 |


### 4.3 加载、配置与调用
```python
from transformers import AutoModel, AutoConfig, AutoModelForSequenceClassification, AutoTokenizer

model_id = "hfl/chinese-macbert-base"

# AutoModel：只要底座，输出每个 token 的向量表示，不带任务头
backbone = AutoModel.from_pretrained(model_id)

# 模型配置：隐藏层维度、层数、词表大小……全在 config 里
config = AutoConfig.from_pretrained(model_id)
print(config.hidden_size, config.num_hidden_layers)   # 768 12

# 带分类头的模型
clf_model = AutoModelForSequenceClassification.from_pretrained(model_id, num_labels=2)

# 走一遍前向传播
tokenizer = AutoTokenizer.from_pretrained(model_id)
inputs = tokenizer("今天点的黄焖鸡米饭绝了！", return_tensors="pt")
outputs = clf_model(**inputs)
print(outputs.logits.shape)   # torch.Size([1, 2])：1 个样本，2 个类别分数
```

### 4.4 num_labels：新手必踩的坑
预训练模型的分类头默认按 2 分类配置。如果你的任务是 10 分类，必须显式传 `num_labels=10`：

```python
# 标签数不匹配时，transformers 会重建分类头（权重随机初始化，等着微调来喂）
# 忘记指定 num_labels，常见症状是报一堆莫名其妙的 device / shape 错误
clf_model = AutoModelForSequenceClassification.from_pretrained(model_id, num_labels=10)
```

### 4.5 保存与加载
微调完的模型一定存下来，别每次重新训：

```python
# 保存：模型和分词器都要存（分词器是模型的"原配钥匙"）
clf_model.save_pretrained("./my_sentiment_model")
tokenizer.save_pretrained("./my_sentiment_model")

# 之后随时随地一行加载
```

### 5.3 select / filter / map 三剑客
```python
# select：按下标挑样本
sub = ds.select([0, 5, 10])

# filter：按条件过滤，比如只留好评
good_only = ds.filter(lambda x: x["label"] == 1)

# map：对每条（或每批）数据做加工，预处理全靠它
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("hfl/chinese-macbert-base")

def preprocess(batch):
    # batched=True 时一次进来一批样本，效率远高于逐条处理
    out = tokenizer(batch["text"], max_length=128, truncation=True)
    out["labels"] = batch["label"]   # Trainer 约定俗成：标签字段必须叫 labels
    return out

# remove_columns 把原始文本列扔掉，只留模型要的数字列，干干净净
tokenized = ds.map(preprocess, batched=True, remove_columns=ds.column_names)
```

### 5.4 处理结果存盘，下次直接用
```python
# 预处理只跑一次，存盘后下次秒加载
tokenized.save_to_disk("./tokenized_data")

from datasets import load_from_disk
tokenized = load_from_disk("./tokenized_data")
```

### 5.5 DataCollatorWithPadding：勤俭持家的动态填充
你可能会问：为什么不在 map 里直接 padding 到 128？因为 batch 里最长可能才 30 个 token，统一填到 128 纯属浪费算力。`DataCollatorWithPadding` 在组 batch 的那一刻，按"本批最长"动态填充：

```python
#动态地将序列填充到该 batch 中最长序列的长度
from transformers import DataCollatorWithPadding
from torch.utils.data import DataLoader

collator = DataCollatorWithPadding(tokenizer=tokenizer)
loader = DataLoader(tokenized, batch_size=8, shuffle=True, collate_fn=collator)

batch = next(iter(loader))
print(batch["input_ids"].shape)   # [8, 本批最长长度]，每个 batch 都可能不同
```
