# Part 1 文本分类实战：教模型看懂外卖评价
## 1.1 任务拆解
情感分类是最典型的文本分类任务：输入一段文本，输出一个类别标签。

> 输入：`这家麻辣烫绝了，汤底我都喝完了！`  
输出：`好评（1）`
>

工程上它就是"给每句话打个分"，但它是所有 NLP 任务里最适合入门微调的——数据好找、模型小、十分钟就能看到效果。

## 1.3 加载数据
数据集地址:[https://github.com/SophonPlus/ChineseNlpCorpus](https://github.com/SophonPlus/ChineseNlpCorpus)

用的是经典的 **ChnSentiCorp** 中文酒店评论数据集，每条数据一个 `review`（评论文本）+ 一个 `label`（0 差评 / 1 好评）。

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from datasets import load_dataset

# 从本地 CSV 加载；也可以直接 load_dataset("lansinuote/ChnSentiCorp") 从 Hub 拉
dataset = load_dataset("csv",
                       data_files="ChnSentiCorp_htl_all.csv",
                       split="train")

# 数据清洗第一课：先扔脏数据。评论为空的行留着只会让训练报莫名其妙的错
dataset = dataset.filter(lambda x: x["review"] is not None)

# 9:1 切分训练集/验证集；seed 固定，保证每次划分结果一致、实验可复现
splits = dataset.train_test_split(test_size=0.1, seed=42)
print(splits)
```

## 1.4 分词与 DataLoader
底座模型选 **rbt3**——哈工大讯飞联合实验室（HFL）出品的 RoBERTa-wwm-ext 三层精简版。只有 38M 参数，CPU 上都能训得动，教学场景的神器。生产环境想要更高精度，可以无缝换成 `hfl/chinese-macbert-base`。

```python
from transformers import AutoTokenizer, DataCollatorWithPadding
from torch.utils.data import DataLoader

# 分词器必须与底座模型配套——它俩共享同一张词表，混用必炸
tokenizer = AutoTokenizer.from_pretrained("hfl/rbt3")

def tokenize_fn(examples):
    # max_length=128：酒店评论大多几十个字，128 足够覆盖；超长直接截断
    out = tokenizer(examples["review"], max_length=128, truncation=True)
    # Trainer 默认认 "labels" 这个字段名来计算损失，名字千万别起错
    out["labels"] = list(examples["label"])
    return out

# batched=True 批量处理比逐条快一个数量级；
# remove_columns 把原始文本列扔掉，只留模型需要的数字字段
tokenized = splits.map(tokenize_fn, batched=True,
                       remove_columns=splits["train"].column_names)

# DataCollatorWithPadding：按 batch 内最长样本动态补齐。
# 对比"全部句子补齐到 128"的粗暴做法，显存占用能省一半以上
collator = DataCollatorWithPadding(tokenizer=tokenizer)

train_loader = DataLoader(tokenized["train"], batch_size=32,
                          shuffle=True, collate_fn=collator)
valid_loader = DataLoader(tokenized["test"], batch_size=64,
                          shuffle=False, collate_fn=collator)
```

## 1.5 模型与优化器
```python
import torch
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification

# num_labels=2 是二分类的关键：它决定模型最后分类头的输出维度。
# 不指定的话默认二分类之外的维度对不上，上来就是 shape 报错
model = AutoModelForSequenceClassification.from_pretrained("hfl/rbt3", num_labels=2)

device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device)

# AdamW 把"权重衰减"从梯度更新里解耦出来，是微调界的事实标准。
# lr=2e-5 是 BERT 系微调的黄金学习率——
# 学习率这东西像洗澡水温：2e-5 刚刚好，1e-3 直接把预训练知识烫秃噜皮
optimizer = AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
```

## 1.6 评估指标
分类任务看两个指标：**Accuracy**（整体准确率）和 **F1**（类别不均衡时更诚实）。

```python
import evaluate
import numpy as np

# 在线加载官方指标；网络不通时可以下载指标脚本到本地再 load 本地路径
acc_metric = evaluate.load("accuracy")
f1_metric = evaluate.load("f1")

def compute_metrics(eval_pred):
    logits, labels = eval_pred
    # 模型输出的是每个类别的原始打分（logits），argmax 取最大者的下标当预测类别
    preds = np.argmax(logits, axis=-1)
    acc = acc_metric.compute(predictions=preds, references=labels)
    f1 = f1_metric.compute(predictions=preds, references=labels)
    return {**acc, **f1}  # 两个字典合并返回，Trainer 会自动记录
```

## 1.7 TrainingArguments 参数详解
`TrainingArguments` 是训练的总控制台。原教程是一大段文字堆砌，这里直接上表：

| 参数 | 作用 | 实战建议 |
| --- | --- | --- |
| `output_dir` | checkpoint 和日志的输出目录 | 每个实验单独一个目录，别混 |
| `eval_strategy` | 评估时机：`"no"` / `"steps"` / `"epoch"` | 小数据集用 `"epoch"` 就够 |
| `save_strategy` | 保存时机，取值同上 | 与 `eval_strategy` 保持一致，否则"加载最优模型"会报错 |
| `save_total_limit` | checkpoint 保留上限，旧的自动删 | 设 3，磁盘友好 |
| `per_device_train_batch_size` | 每张卡的训练 batch | 显存不够就减半，配合梯度累积 |
| `gradient_accumulation_steps` | 累积若干步梯度再更新 | 等效放大 batch，显存救星 |
| `learning_rate` | 初始学习率 | BERT 系 2e-5 起步 |
| `weight_decay` | 权重衰减（正则化） | 0.01 是惯例；bias 和 LayerNorm 自动豁免 |
| `num_train_epochs` | 训练轮数 | 小数据 3~5 轮，盯紧验证集别过拟合 |
| `metric_for_best_model` | 用哪个指标挑最优 checkpoint | 类别不均衡选 `"f1"` |
| `load_best_model_at_end` | 训练结束后自动装回最优权重 | 永远开，谁用谁知道 |
| `logging_steps` | 多少步打一次日志 | 训练慢时调大，看着心静 |


```python
from transformers import TrainingArguments

train_args = TrainingArguments(
    output_dir="./checkpoints",           # checkpoint 输出目录
    per_device_train_batch_size=64,       # 训练 batch
    per_device_eval_batch_size=128,       # 评估 batch 可以开大点，不用算梯度
    logging_steps=100,                    # 每 100 步打一次日志
    eval_strategy="epoch",                # 每轮结束评估一次
    save_strategy="epoch",                # 每轮结束保存一次
    save_total_limit=3,                   # 最多留 3 个 checkpoint
    learning_rate=2e-5,                   # 黄金学习率
    weight_decay=0.01,                    # 权重衰减
    num_train_epochs=5,                   # 5 轮
    metric_for_best_model="f1",           # 按 F1 挑最优
    load_best_model_at_end=True,          # 训完自动装回最优权重
)
```

## 1.8 DataCollatorWithPadding 详解
`DataCollator` 负责把数据集的散样本打包成一个 batch 张量。`DataCollatorWithPadding` 是其中最常用的实现：**打包时按 batch 内最长样本动态 padding**。

| 参数 | 说明 |
| --- | --- |
| `tokenizer` | 用谁的分词器，就用谁的 `pad_token_id` 来补 |
| `padding` | `True`/`"longest"` 按 batch 最长补齐；`"max_length"` 补到定长；`"do_not_pad"` 不补 |
| `max_length` | 配合 `padding="max_length"` 使用的目标长度 |
| `pad_to_multiple_of` | 补齐到 N 的倍数（Tensor Core 友好，如 8） |
| `return_tensors` | 返回张量类型：`"pt"` PyTorch / `"tf"` TensorFlow / `"np"` NumPy |

# Part 2 命名实体识别（NER）
## 2.1 NER 是什么
命名实体识别（Named Entity Recognition）要干两件事：**找到实体的边界**，再**确定实体的类别**（人名、地名、组织名……）。

<!-- 这是一张图片，ocr 内容为： -->
![](images/ner-intro-example.png)

比如"小明在北京上班"这句话，模型需要框出 `小明`（人物）和 `北京`（地点）两个实体。和分类任务"整句话一个标签"不同，NER 要对**每个字/token 都打标签**，所以它在任务家族里属于**序列标注（Sequence Labeling）**。

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1789371343350-1b47f0e4-4b9e-4837-8f4f-7f868e9b8aba.png)

## 2.2 常见实体类型
| 标签 | 含义 | 示例 |
| --- | --- | --- |
| `PER` | 人名 | 小明、老王 |
| `LOC` | 地名 | 北京、西湖区 |
| `ORG` | 组织名 | 清华大学、某科技公司 |
| `TIME` | 时间表达式 | 今天下午、双十一 |
| `DATE` | 日期表达式 | 2026 年 9 月 |
| `MONEY` | 货币表达式 | 三十八块五 |
| `PERCENT` | 百分比表达式 | 85% |


实际业务里还会自定义领域实体：电商抽商品名、医疗抽疾病和药品名、法律抽罪名和法条——标注体系是活的，按业务定。

## 2.3 应用场景
+ **金融/法务**：从信贷合同、招股书、投资协议里抽公司名、金额、日期，做智能审核与风险评估。国内银行的合同要素抽取系统，底层几乎都站着 NER；
+ **医疗**：病历结构化，从非结构化病历文本里抽疾病、症状、用药；
+ **政务/法律**：裁判文书中抽取当事人、罪名、涉案金额；
+ **电商**：评论里抽商品名、型号，做口碑分析；
+ **招聘**：简历解析，抽姓名、学校、工作经历。

一句话：凡是"从一大段非结构化文本里抠出结构化字段"的需求，都是 NER 的主场。

## 2.4 IOB 标注体系
标签不是随便打的，业内有标准标注规范：

**IOB2** 最常用，三个前缀：

+ `B-XXX`：实体 XXX 的**开始**位置
+ `I-XXX`：实体 XXX 的**内部**位置
+ `O`：非实体（Outside）

**IOBES** 更严格，额外加两个：`E` 表示实体结束，`S` 表示单字实体（Single）。`M` 偶尔用来代替 `I`，含义一样。

看一个中文例子就懂了：

```latex
小  王  在  杭  州  开  了  家  奶  茶  店
B-PER I-PER O  B-LOC I-LOC O  O  O  O  O  O
```

`小王` 是人名 → `B-PER I-PER`；`杭州` 是地名 → `B-LOC I-LOC`；其余字一律 `O`。

## 2.5 评估指标：实体级别的 P / R / F1
NER 评估的残酷之处：**实体级别统计，边界错一个字都算全错**。还是上面那句话：

+ 真实实体（2 个）：`小王`(PER)、`杭州`(LOC)
+ 模型预测（2 个）：`小王`(PER)、`杭州奶茶店`(ORG)

逐一对照：

```latex
predict_num = 2     # 模型预测出 2 个实体
gold_num    = 2     # 真实有 2 个实体
correct_num = 1     # 只有"小王"完全正确（"杭州奶茶店"边界和类别都错）

P  = correct / predict = 1/2 = 0.5
R  = correct / gold    = 1/2 = 0.5
F1 = 2PR / (P+R)       = 0.5
```

手算太累，工程上直接用 **seqeval**，它原生支持 IOB2/IOBES 体系：

```python
# pip install seqeval —— 纯 Python 实现。
from seqeval.metrics import f1_score, classification_report

y_true = [["O", "B-PER", "I-PER", "O", "B-LOC", "I-LOC"]]
y_pred = [["O", "B-PER", "I-PER", "O", "O",     "O"]]  # 模型漏掉了"杭州"

print(f1_score(y_true, y_pred))                 # 实体级 F1
print(classification_report(y_true, y_pred))    # 按类别细分的 P/R/F1
```

## 2.6 2026 年的另一种解法：直接问大模型
这两年多了一个新选项：不训模型了，直接写 prompt 让大模型抽实体。以国内的 DeepSeek 为例：

```python
# 思路示意：调用 DeepSeek API 的 chat 接口
prompt = """从下面这句话中抽取人名、地名、组织名，以 JSON 返回，不要输出多余内容：
张三上周去杭州参加了阿里云举办的技术大会。"""
# 期望输出：{"人名": ["张三"], "地名": ["杭州"], "组织名": ["阿里云"]}
```

哪条路更香？看场景：

| 维度 | 微调小模型（MacBERT 等） | 大模型 Prompt（DeepSeek 等） |
| --- | --- | --- |
| 标注成本 | 需要几千条标注数据 | 零样本/少样本即可 |
| 精度上限 | 垂直领域内很高 | 通用类别不错，细粒度边界易翻车 |
| 推理延迟 | 毫秒级 | 秒级 |
| 单次成本 | 自建后边际成本≈0 | 按 token 计费，量大肉疼 |
| 输出可控性 | 结构化输出天然稳定 | 需要 prompt 工程 + 输出校验兜底 |


经验法则：**冷启动验证用大模型，高并发、低延迟、垂直领域的生产环境还是微调小模型**。两条腿走路不丢人。

## 3.2 核心难点：子词拆分与标签对齐
这是整个 NER 微调里最容易踩坑、也最值得讲透的地方。

问题根源：**数据是"按词"标注的，但 tokenizer 会按"子词（subword）"再拆一刀**。一个英文单词可能被拆成好几个 token，词只有一个标签，token 却有好几个，标签数量直接对不上：

`knowledge` 只有一个标签，拆成 `know` + `ledge` 后变成两个 token——多出来的 token 该贴什么标签？

`interesting word` 两个词，被拆成 5 个 token（id: 10673, 12865, 12921, 8181, 8681），前 4 个都属于 `interesting`，必须共享它的"标签1"。

解法靠 tokenizer 自带的 `word_ids()`：它能告诉你每个 token 回溯到第几个原始词。整体对齐逻辑如下：

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1789372411357-ba3386ff-901c-4a60-9099-fb090f16c3cd.png)

`-100` 是个魔法数字：PyTorch 交叉熵损失默认 `ignore_index=-100`，贴了这个标签的位置**不参与损失计算**，模型就当它不存在。

```python
# 借助word_ids 实现标签映射
def process_function(examples):
    tokenized_exmaples = tokenizer(examples["tokens"],
                                   max_length=128, 
                                   truncation=True, 
                                   is_split_into_words=True)
    #return tokenized_exmaples
    labels = []
    for i, label in enumerate(examples["ner_tags"]):
        word_ids = tokenized_exmaples.word_ids(batch_index=i)
        label_ids = []
        for word_id in word_ids:
            if word_id is None:
                #CLS SEP 不参与计算
                #在cross loss 中-100不参与运算
                label_ids.append(-100)
            else:
                label_ids.append(label[word_id])
        labels.append(label_ids)
    tokenized_exmaples["labels"] = labels
    return tokenized_exmaples
```

## 3.4 评估函数
模型输出的是 id，seqeval 吃的是标签字符串，中间要做一次翻译，并把 `-100` 位置剔除：

```python
import evaluate

seqeval = evaluate.load("seqeval")
```

```python
import numpy as np

 # predictions = [['O', 'O', 'B-MISC', 'I-MISC', 'I-MISC', 'I-MISC', 'O'], ['B-PER', 'I-PER', 'O']]
 # references = [['O', 'O', 'O', 'B-MISC', 'I-MISC', 'I-MISC', 'O'], ['B-PER', 'I-PER', 'O']]

def eval_metric(pred):
    predictions, labels = pred
    predictions = np.argmax(predictions, axis=-1)

    # 将id转换为原始的字符串类型的标签
    true_predictions = [
        [label_list[p] for p, l in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels) 
    ]

    true_labels = [
        [label_list[l] for p, l in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels) 
    ]

    result = seqeval.compute(predictions=true_predictions, references=true_labels, scheme="IOB2")

    return {
        "f1": result["overall_f1"]
    }
    
```

```python
    per_device_train_batch_size=64,
    per_device_eval_batch_size=128,
    eval_strategy="epoch",
    save_strategy="epoch",
    metric_for_best_model="f1",
    load_best_model_at_end=True,
    logging_steps=50,
    num_train_epochs=3,           
)

# DataCollatorForTokenClassification 专为序列标注设计：
# token 按 batch 内最长补齐，多出来的 label 位置自动填 -100，
# 保证所有序列等长，又不会让 padding 污染损失
data_collator = DataCollatorForTokenClassification(tokenizer=tokenizer)

trainer = Trainer(
    model=model,
    args=args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    processing_class=tokenizer,         # 新版写法，旧的 tokenizer= 已弃用
    compute_metrics=compute_metrics,
    data_collator=data_collator,
)
```

## 3.6 训练与评估

```python
trainer.train()
trainer.evaluate(eval_dataset=tokenized_datasets["test"])
```
