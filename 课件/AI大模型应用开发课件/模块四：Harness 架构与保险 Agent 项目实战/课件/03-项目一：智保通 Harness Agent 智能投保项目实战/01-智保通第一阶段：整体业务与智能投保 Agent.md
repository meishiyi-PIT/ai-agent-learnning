## 1. 项目定位
智保通是一套面向保险咨询、投保、知识服务和保单生命周期管理的智能保险系统，包括：

+ **H5 用户端**：客户咨询保险、选择方案、完成投保、查看保单并发起后续服务。
+ **PC 运营端**：运营人员管理保险业务、查看经营数据、维护知识并处理需要人工介入的流程。
+ **统一后端**：两个前端共用业务能力、Agent Harness 和数据服务。

三个阶段采用包含式演进：

1. **第一阶段——智能投保**：完成“需求理解 → 方案推荐 → 投保 → 支付 → 出单”的闭环。
2. **第二阶段——知识服务与经营分析**：在第一阶段之上增加 Agentic RAG、长期记忆、多模态材料识别和趋势分析。
3. **第三阶段——保单生命周期工作流**：在前两阶段之上增加 LangGraph 退保编排、人工审批、退款 Worker 和 MCP。

> **项目主线：Agent Engineering**
>
> 传统业务模块负责提供**可信数据**和执行**确定性规则**；Agent 负责**理解意图、选择工具、组织证据并生成结果**。
>

## 4. 第一阶段业务
### 4.1 H5 用户端
客户通过手机号和验证码登录，也可以通过带推广码的链接进入。登录后可以：

+ **智能咨询**：向智能顾问描述投保对象、年龄、地区、职业和保障诉求。
+ **方案推荐**：接收保险方案推荐、资格判断和确定性保费试算。
+ **投保衔接**：从推荐结果直接进入投保流程。
+ **投保关系**：选择本人、父母、配偶或子女作为被保险人。
+ **资料确认**：填写投保资料，阅读投保须知、保险条款和责任免除。
+ **订单创建**：完成用户确认，生成待支付订单。
+ **模拟支付**：通过本地模拟收银台完成支付并生成电子保单。
+ **保障查询**：查看本人订单、支付状态和多张电子保单。

### 4.2 PC 运营端
PC 端用于承接保险运营业务：

+ **经营总览**：查看订单、保单、保费和近期业务动态。
+ **产品管理**：查看产品、版本和保障计划，并管理销售状态。
+ **推广归因**：查看推广访问、线索、归因订单和业务员保费贡献。
+ **权限管理**：维护后台账号、投保客户、角色、权限和数据范围。
+ **运营分析**：使用运营 Agent 分析经营总览、订单、保单和推广转化。
+ **运行观察**：在 Agent 运行中心查看历史会话、Run、工具调用和 Trace。

> **传统模块的定位**
>
> 向 Agent 提供真实的产品、价格、订单和保单数据，并承接 Agent 生成的受控业务入口。
>

## 5. 一个内核、两个 Agent 人格
第一阶段没有为客户咨询和运营分析分别实现两套 Agent，而是使用同一个 **Agent Kernel** 承载两个受控人格。

两个人格的差异由以下配置形成：

+ **Prompt**：客户人格强调需求理解、产品解释和投保引导；运营人格强调数据口径、只读分析和风险提示。
+ **Skills**：以文件化 `SKILL.md` 描述保险咨询、投保引导和经营分析方法。
+ **Tool 白名单**：客户人格可以查询产品、计算报价、生成投保入口、查询本人订单和保单；运营人格只能调用授权的只读分析工具。
+ **Policy**：在真正执行工具前再次检查人格、工具副作用、账号权限和数据范围。

> **设计价值**
>
> 复用模型接入、会话、结构化输出、可观测性和评测能力，同时防止不同业务人格越权。
>

## 6. Agent 执行流程
一次典型的智能投保咨询包含：

1. **创建会话**：API 根据登录身份创建或恢复会话。
2. **加载人格**：Agent Kernel 加载客户人格对应的 System Prompt 和 Skills。
3. **控制上下文**：仅将最近有限轮次的历史对话送入模型，避免上下文无限增长。
4. **理解需求**：DeepSeek 识别投保对象和保障诉求。
5. **查询产品**：Agent 调用产品查询工具，获取真实在售产品。
6. **确定性报价**：资格与保费均由业务规则计算。
7. **生成结构化结果**：Agent 将工具结果组织成推荐卡、报价卡和受控操作。
8. **推送运行事件**：H5 通过 SSE 接收运行开始、工具完成、UI 就绪和运行完成事件。
9. **记录运行链路**：Run、消息、工具名称、Trace ID 和最终状态被持久化并关联 LangSmith。

> **不可越过的边界**
>
> 模型不能自行生成产品价格，也不能绕过确认直接创建订单。涉及**金额、资格和状态变更**的结果必须来自受控工具。
>

## 7. 关键设计
### 7.1 模型负责理解，工具负责事实
大模型擅长理解自然语言和解释结果，但不适合充当产品库、费率表或订单数据库。因此：

+ 产品、保费、资格、订单和保单由确定性领域服务返回。
+ 工具使用 Pydantic 校验参数并拒绝未声明字段。
+ 工具统一返回摘要、数据、结构化 UI 区块和受控 Action。
+ 支付、出单和保单状态不能由模型自由修改。

### 7.2 结构化 UI，而不是解析模型文本
Agent 返回稳定的推荐、报价、指标和业务列表结构。前端直接根据 Schema 渲染卡片和按钮，不依赖正则表达式解析模型回复，因此页面不会因为模型措辞变化而失效。

### 7.3 权限进入 Agent 工具层
运营 Agent 的工具调用同时受到人格白名单、账号权限和数据范围约束。业务员只能看到归属于自己的数据，需要保护的手机号和证件信息由后端脱敏后再交给 Agent。

### 7.4 全链路可观测
每次 Agent 运行都有独立 Run 和 Trace：

+ 本地运行中心查看问题、人格、状态、耗时和工具记录。
+ LangSmith 查看模型输入输出和工具调用链。
+ 固定评测用例使用真实模型检查工具覆盖、关键结论和结构化区块。

> **可观测性**回答“Agent 为什么这样回答”；**自动评测**回答“改动后能力是否退化”。
>

### 7.5 交易链路保持幂等
Agent 可以引导投保，但订单、模拟支付和出单仍执行幂等约束。重复提交不会重复创建订单、支付流水或保单。

## 8. 本阶段使用的主要技术
| Agent 技术 | 在本阶段的作用 |
| --- | --- |
| **DeepSeek** | 客户咨询与运营分析的文本模型 |
| **LangChain **`create_agent` | 模型与工具调用循环 |
| **Agent Harness / Agent Kernel** | 统一承载人格、Prompt、Skill、Tool 和 Policy |
| **Prompt Registry** | 文件化加载不同人格的 System Prompt |
| **Skills** | 固化保险咨询、投保引导和经营分析方法 |
| **Function Calling** | 让模型调用产品、报价、订单、保单和经营数据工具 |
| **Pydantic / JSON Schema** | 工具参数校验与结构化输出 |
| **滑动上下文窗口** | 控制每次模型调用携带的历史轮次 |
| **SSE** | 向 H5 推送 Agent 执行进度 |
| **LangSmith** | Trace、工具调用观察和模型评测记录 |
| **Run/Event 记录** | 本地运行中心、历史追踪和事件回放 |


业务底座使用 **Vue 3、FastAPI、MySQL 和 Redis**，负责双端页面、统一 API、业务数据、会话热状态和运行事件。这些技术为 Agent 提供可信业务环境，但**不是本阶段的叙述重点**。

## 10. 第一阶段边界
第一阶段完成“从客户需求到有效保单”的闭环，但暂不处理：

+ 保险条款向量检索和 Agentic RAG。
+ 跨会话长期记忆。
+ 医疗票据多模态识别。
+ 显式 LangGraph 长流程和人工中断恢复。
+ 退保试算、审批、退款和保单终止。

> 这些能力分别由第二、第三阶段在同一 **Agent Harness** 基础上继续扩展。
>
