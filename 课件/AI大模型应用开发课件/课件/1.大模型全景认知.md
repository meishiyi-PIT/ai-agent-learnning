## 一、先搞懂 AI 在聊什么
### 1.1 什么是人工智能
简单说，**人工智能（Artificial Intelligence, AI）** 就是让计算机表现出"像人一样思考和行动"的能力。注意，这里的"像"是重点——它并不真的在思考，而是在模拟。

AI 的三个段位：

| 段位 | 含义 | 现状 |
| :--- | :--- | :--- |
| **弱人工智能（ANI）** | 只擅长某一个特定任务 | 我们就在这儿。人脸识别、语音助手、推荐算法都是 |
| **强人工智能（AGI）** | 什么都能干，和人一样通用 | 还在追赶中，大模型是最接近的一条路 |
| **超人工智能（ASI）** | 全面碾压人类智能 | 目前纯属理论层面 |


> 📌 **一句话总结**：现阶段所有你能用到的 AI 产品，包括 ChatGPT、DeepSeek、豆包，统统都是"弱人工智能"。只不过大模型把这个"弱"字的含金量拉得越来越高了。
>

### 2.2 传统机器学习 vs 深度学习
| 对比维度 | 传统机器学习 | 深度学习 |
| :--- | :--- | :--- |
| **特征提取** | 得靠人手动设计特征（很累） | 网络自己学特征（省心） |
| **数据需求** | 数据少点也能干活 | 没海量数据基本废了 |
| **模型复杂度** | 相对简单 | 参数多到离谱 |
| **可解释性** | 还能看看内部逻辑 | 黑箱，很难解释为什么 |
| **典型代表** | 决策树、SVM、随机森林 | CNN、RNN、Transformer |

## 三、大模型到底"大"在哪
### 3.1 定义
**大语言模型（Large Language Model, LLM）** 是一种基于深度学习的语言模型。它在海量文本数据上训练，学会了语言的内在规律，从而能理解和生成自然语言。

### 3.2 "大"在四个维度
| 维度 | 量级 |
| :--- | :--- |
| **参数量** | 几十亿到上万亿个参数 |
| **训练数据** | 几 TB 到几十 TB 的文本 |
| **算力消耗** | 几千到几万块 GPU，训练几周到几个月 |
| **模型体积** | 几 GB 到几百 GB |


### 3.3 一个直觉类比
```plain
传统程序：    人写规则 → 输入 → 输出
              （规则是人定的，机器只是执行者）

机器学习：    教它语法(算法) → 人给数据和标签 → 模型训练 → 输出
              （人告诉机器"这是猫""这是狗"，机器学会区分）

大语言模型：  海量文本 → 模型自学 → 生成文本
              （没人教它语法，它自己从万亿句话里悟出来的）
```

**关键区别**：传统程序是"编程"出来的，大模型是"读"出来的。它读了互联网上几乎所有公开文本，从中学会了语言的统计规律。

## 五、Transformer：一切的基石
### 5.1 为什么 Transformer 这么重要
2017 年 Google 那篇论文提出的 Transformer 架构，直接把之前的 RNN、LSTM 拍在了沙滩上。原因很简单：**它解决了长距离依赖问题，而且支持并行计算**。

现在你能叫得上名字的大模型——DeepSeek、Qwen、GPT、Claude、Llama——清一色都是基于 Transformer 构建的。

### 5.2 注意力机制（Attention）：核心中的核心
**问题场景**：人在读一句话的时候，会根据上下文选择性地关注重点词语。机器怎么做到这一点？

```plain
句子："小明把苹果给了小红，因为她很饿。"

人一眼就知道"她"指的是"小红"。
但机器需要一个机制来做出这个判断——这就是注意力机制。
```

**自注意力的计算过程**：

```plain
输入: "小明 把 苹果 给了 小红 因为 她 很 饿"

计算"她"与每个词的相关度（注意力分数）：

  小明: ██░░░░░░░░  0.15
  把:   ░░░░░░░░░░  0.02
  苹果: ██░░░░░░░░  0.10
  给了: ░░░░░░░░░░  0.03
  小红: ██████████  0.55  ← 最高！"她"最关注"小红"
  因为: ░░░░░░░░░░  0.05
  她:   ██░░░░░░░░  0.08
  很:   ░░░░░░░░░░  0.01
  饿:   ███░░░░░░░  0.11

✅ 模型通过注意力分数，学会了"她"指的是"小红"
```

注意力机制的三步走：

1. **计算相关性**：每个词和其他所有词之间算一个"注意力分数"
2. **加权聚合**：按分数权重把相关信息汇总起来
3. **输出表示**：每个词的新表示都融合了上下文信息

### 5.3 Transformer 的整体结构
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1781774606871-74d75ab8-4d0e-454c-b4c2-55979a8887d0.png)

> 📌 **划重点**：现在主流的大语言模型（DeepSeek、Qwen、GPT、Llama）基本都是 **Decoder-only** 架构——只用解码器那一半，通过"自回归"方式逐词生成文本。编码器那一半更多用在 BERT 这类"理解型"模型里。
>

### 5.4 位置编码：让模型知道词的顺序
Transformer 本身没有"顺序"的概念——它把所有词一并处理。为了让模型知道"谁在前谁在后"，需要给每个词加一个位置编码（Positional Encoding）。

> 💡 这就像给排队的人发号牌，模型通过号牌知道先后顺序。
>

## 六、大模型的"三段式"成长之路
训练一个大语言模型，就像培养一个学生：先大量阅读打基础，再针对性补课，最后学会察言观色。

### 6.1 阶段一：预训练（Pre-training）
**目标**：让模型学会语言的基本规律。

**方法**：把互联网上的海量文本（书籍、网页、代码、论文……）喂给模型，让它做"完形填空"——给定前文，预测下一个词。

```plain
训练过程（简化版）：

输入:  "今天 天气"
标签:  "真"

模型内部：
  1. 把文字切成 Token（子词单元）
  2. 通过 Transformer 网络计算
  3. 输出每个候选词的概率分布

  "真"  → 45%  ← 最高，这就是模型的预测
  "不"  → 20%
  "很"  → 15%
  "晴"  → 10%
  其他  → 10%

然后拿预测和真实答案对比，算出"差距"（损失函数）
反向传播，调整参数，缩小差距
重复数百亿次 → 模型逐渐学会语言规律
```

> 💡 **关键点**：预训练是最烧钱的阶段。DeepSeek-V3 的预训练用了 14.8 万亿个 Token，消耗的算力折合几千万美元。
>

### 6.2 阶段二：监督微调（SFT, Supervised Fine-Tuning）
**目标**：让模型学会"好好回答问题"。

预训练后的模型虽然懂语言，但它只会"接话"，不会"回答"。你需要用人工编写的高质量问答对来教它：

```plain
示例：
  问：什么是机器学习？
  答：机器学习是人工智能的一个分支，它让计算机能够从
      数据中自动学习规律，而不需要人工编写每一条规则。
```

这个阶段需要的数据量远小于预训练，但质量要求极高——每一条都是人工精心编写的。

### 6.3 阶段三：人类反馈强化学习（RLHF）
**目标**：让模型的回答更符合人类的偏好和价值观。

<!-- 这是一个文本绘图，源码为：graph LR
    A["模型生成多个回答"] --> B["人类标注员排序打分"]
    B --> C["训练奖励模型"]
    C --> D["用强化学习优化原始模型"]
    D --> A -->
![](https://cdn.nlark.com/yuque/__mermaid_v3/d0be6ac5ecf8db11e266abee20ef2033.svg)

简单说就是：让模型不断生成回答，人类来打分排序，模型根据反馈调整自己的"回答策略"。经过多轮迭代，模型逐渐学会了什么回答是好的、什么是不好的。

> 🕳️ **踩坑提醒**：RLHF 的效果高度依赖标注员的质量。如果标注员本身有偏见，模型也会学到这些偏见。这也是为什么各家厂商都在疯狂投入标注团队建设。
>

### 6.4 Tokenization：模型的"识字"方式
模型不认识中文字符，也不认识英文单词。它认识的是 **Token**——一种介于字符和单词之间的子词单元。

```plain
原始文本: "我喜欢学习人工智能"

方式一（按字切）:
  我 / 喜 / 欢 / 学 / 习 / 人 / 工 / 智 / 能
  → 9 个 Token，太碎了

方式二（按词切）:
  我 / 喜欢 / 学习 / 人工智能
  → 4 个 Token，但遇到生僻词就傻眼了

方式三（子词切分，主流方案）:
  我 / 喜欢 / 学 / 习 / 人工 / 智能
  → 6 个 Token，兼顾粒度和覆盖率

英文示例:
  "unhappiness" → "un" + "happi" + "ness"
  → 通过常见子词的组合，覆盖几乎所有英文词汇
```

> 💡 **为什么要关心 Token？** 因为大模型的上下文窗口、API 计费都是按 Token 算的。同样一句话，不同的 Tokenizer 切出来的数量可能差很多，直接影响你的钱包。
>

## 七、能力边界：它能做什么、不能做什么
把能力和局限放在一起看，才能对大模型有个清醒的认知。

### 7.1 核心能力
| 能力 | 说明 | 典型场景 |
| :--- | :--- | :--- |
| **文本生成** | 写文章、写邮件、写文案 | 自媒体运营、商务邮件 |
| **问答对话** | 基于知识库回答各类问题 | 智能客服、知识助手 |
| **多语言翻译** | 多语种互译，质量越来越好 | 跨境电商、学术翻译 |
| **文本摘要** | 把长文压缩成精华 | 论文速读、会议纪要 |
| **逻辑推理** | 分析问题、推导结论 | 数据分析、方案评估 |
| **代码辅助** | 写代码、查 Bug、解释代码 | 程序员的第二大脑 |
| **创意写作** | 写诗、编故事、头脑风暴 | 营销策划、内容创作 |


### 7.2 多模态：不止于文字

### 7.3 已知局限
| 问题 | 说明 | 实际案例 |
| :--- | :--- | :--- |
| **幻觉（Hallucination）** | 生成看起来对但实际编造的内容 | 编造不存在的论文、捏造法律条文 |
| **知识截止** | 训练数据有时间边界，不知道最新的事 | 不了解昨天发布的新闻 |
| **推理失误** | 复杂多步推理容易翻车 | 多步数学证明中途出错 |
| **上下文窗口** | 能处理的文本长度有上限 | 超长文档可能丢失中间细节 |
| **数据偏见** | 训练数据中的偏见会被继承 | 性别、地域刻板印象 |


### 7.4 擅长 vs 不擅长
```plain
大模型干得漂亮的事：          大模型干不好的事：
✅ 语言理解和生成              ❌ 精确的实时计算（它不是计算器）
✅ 知识检索和总结              ❌ 保证 100% 准确（幻觉无处不在）
✅ 创意写作和头脑风暴          ❌ 替代专业判断（医疗、法律请找专家）
✅ 代码辅助                    ❌ 理解真实物理世界（它是纯文本动物）
✅ 多语言翻译                  ❌ 长期记忆（每次对话都是新开始）
```

> 📌 **一句话**：把大模型当成一个知识渊博但偶尔会"一本正经胡说八道"的助手，而不是全知全能的神。用它的长处，对它的短处保持警惕。
>

## 九、小结与思考
### 核心要点回顾
