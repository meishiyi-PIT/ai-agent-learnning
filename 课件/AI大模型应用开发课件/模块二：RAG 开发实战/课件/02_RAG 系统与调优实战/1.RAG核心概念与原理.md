## 一、什么是 RAG
RAG，全称 **Retrieval-Augmented Generation**（检索增强生成），是一种把信息检索和语言生成结合起来的 AI 技术方案,旨在提高LLM在生成响应时的准确性和信息量。它的核心思路很直白：**先从外部知识库里找到和问题相关的资料，再把这些资料塞给大模型当参考，让它给出更靠谱的回答。**

这项技术是 Facebook AI Research（FAIR）团队在 2020 年提出的，如今已经成了大模型落地应用中最主流的架构之一。

简单来说，RAG 就是一个"检索 + 生成"的框架——把传统搜索引擎的查找能力和大模型的理解表达能力揉到了一起。

> **拆解"检索增强生成"这个名字：**
>
> + **检索（Retrieval）**：从知识库中找到与问题相关的参考资料
> + **增强（Augmented）**：把检索到的文档和用户问题拼成 Prompt，让提示词变得更丰富
> + **生成（Generation）**：大模型拿到增强后的提示词，生成最终答案
>

## 二、如何理解 RAG
### 大语言模型（LLM）面临的三个困境
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/svg/21571931/1782353970279-c0b95922-c214-4271-b1a9-d71eceaf0fb1.svg)

**① 知识过时**

每个大模型的训练数据都有一个截止日期。截止日期之后发生的事，模型一无所知。比如一个用 2024 年数据训练的模型，你问它 2025 年的新闻，它只能干瞪眼。

**② 一本正经地胡说八道（幻觉）**

大模型有时候会"自信满满"地给出完全错误的答案。它不是故意骗人，而是基于概率生成文字时，产生了看似合理实则编造的内容。你问它某个冷门 API 的参数，它可能给你编一个根本不存在的。

**③ 隐私与数据安全**

如果把企业内部的敏感数据直接用于训练模型，可能会带来信息泄露的风险。数据一旦进了模型的权重里，就很难完全控制它的流向了。

---

RAG 技术通过引入外部知识库的方式，为上面三个问题提供了有效的解决思路：

+ 针对**知识过时**：只要及时更新知识库中的内容，模型就能获取最新信息，不再受限于训练数据的时间范围
+ 针对**幻觉问题**：模型的回答有了外部资料作为依据，不再完全依赖自己的"记忆"来编造答案
+ 针对**数据安全**：企业可以将私有知识存放在独立的知识库中，无需将其纳入模型训练数据，既保护了隐私又实现了知识利用

> **RAG 的核心价值：用检索替代微调，让模型以最低成本获得最新、最相关、最可信的外部知识。**
>

---

### "检索"、"增强"、"生成"各自承担什么角色
RAG 的核心目标是借助外部知识库的检索结果，帮助大模型生成更加准确、更加丰富的回答。那这三个环节分别干了什么？

+ **检索**：这是 RAG 流程的起始步骤。系统根据用户的提问，从预先搭建好的知识库中找到最相关的资料片段。这一步为后续的生成过程提供了关键的背景信息和知识支撑。
+ **增强**：这一步将检索到的资料整合到用户的原始问题中，形成一个信息更丰富的提示词（Prompt）。经过增强后的提示词，能够让大模型更深入地理解问题的上下文，从而给出更精准的回答。
+ **生成**：这是 RAG 流程的收尾环节。大模型接收增强后的提示词，结合检索到的外部知识，生成最终的回答内容。

**理解 RAG 的关键在于搞清楚"谁做了什么"：知识库提供了检索到的参考资料，这些资料增强了提示词（Prompt），而大模型则基于增强后的提示词生成了最终答案。**

> **一句话总结：RAG 让大模型摆脱了自身知识的局限，通过引入外部知识库的实时信息，显著提升了生成内容的质量和可靠性。**
>

## 三、如何使用 RAG
### 一、数据准备与知识库搭建
**① 数据采集**

第一步是收集所有与业务场景相关的资料。这些资料可以来源于企业内部文档、官方网站、数据库、产品手册等多种渠道。能收的都收，覆盖面越广，知识库越有价值。

**② 数据清洗**

对采集到的原始数据进行整理，剔除无关信息、去除重复内容、修正格式错误，确保进入知识库的数据质量可靠。垃圾进垃圾出，数据清洗这一步省不得。

**③ 知识库构建**

将清洗后的数据加工成可供检索的知识库，核心步骤有三步：

1. **文档切片（Chunking）**：将长文本拆分成适当大小的片段。切片太大会导致检索精度下降，太小又会丢失上下文，需要根据业务场景反复调试。
2. **文本向量化（Embedding）**：利用文本嵌入模型（如智谱 Embedding、通义 Embedding）将这些片段转换为向量表示——可以理解为文本的"数学指纹"，语义相近的文本向量距离也更近。
3. **存入向量数据库**：将向量存入专门的向量数据库（如 FAISS、Milvus、Chroma）中，以便后续高效检索。

### 二、检索模块设计
**① 问题向量化**

当用户输入查询问题时，使用与构建知识库**相同的**文本嵌入模型，将问题也转换为向量表示。必须是同一个模型，否则向量空间不一致，检索结果就乱了。

**② 相似度匹配**

在向量数据库中，通过计算向量之间的相似度（如余弦相似度），找到与问题向量最接近的知识片段。

**③ 结果排序**

按照相似度得分对检索结果进行排序，筛选出最相关的片段作为后续生成环节的输入。通常取 Top-K 个结果（比如最相关的 3 段）。

### 三、生成模块设计
**① 上下文拼接**

将检索到的相关片段与用户的原始问题组合在一起，构成信息量更充足的输入内容。通常还会加一段引导语，比如"请根据以下参考资料回答，如果资料中没有相关信息，请如实说明，不要编造"，以降低幻觉风险。

**② 大语言模型生成**

将拼接后的上下文输入给大模型（如 DeepSeek-V3、通义千问、智谱 GLM），由模型综合分析后生成最终回答。为了让回答更忠实于参考资料，通常会把生成温度（temperature）调低，减少随机性。

## 四、RAG 工作流程
**RAG 的整体流程可以用一句话概括：接收用户问题 → 从知识库中检索相关资料 → 将资料与问题整合 → 交给大模型生成最终回答。**

### 类比理解：开卷考试
可以把 RAG 的工作过程比作一场"开卷考试"——

模型本身是那个能写文章的学生，知识库是那一堆参考书。考试时不靠死记硬背，而是先翻书找到相关段落，再用自己的理解写答案。没有 RAG 的 AI 是闭卷考——它只能答它训练时见过的内容。

| 对比项 | 闭卷考试（纯 LLM） | 开卷考试（RAG） |
| --- | --- | --- |
| 答题方式 | 完全靠记忆作答 | 可以翻阅参考资料后再作答 |
| 优势 | 回答速度快 | 答案有据可查，准确度更高 |
| 劣势 | 容易"编造"不确定的内容 | 答案质量取决于参考资料的质量 |
| 核心差异 | 没有外部信息支持 | 先检索再回答，信息有来源 |


在这个类比中：

+ **闭卷考试** = 纯大语言模型，只能凭借训练时学到的知识来回答，容易出现编造内容的情况
+ **开卷考试** = RAG，允许模型先"翻书"（检索知识库），再组织语言回答问题
+ **书本质量** = 知识库的质量，如果知识库中的内容有误或不相关，最终的答案也会受到影响

RAG 技术将大模型强大的语言理解与生成能力，同外部知识库的精确性和时效性结合在一起。它让模型在回答问题时不再仅仅依赖训练阶段积累的"记忆"，而是能够动态获取最新的外部信息，从而显著提升回答的准确性、相关性和可信度，有效降低生成错误信息的风险。

> **RAG——让 AI 能够读懂并运用你的私有知识。**
>
