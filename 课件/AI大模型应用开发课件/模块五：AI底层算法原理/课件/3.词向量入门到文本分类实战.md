# 词向量入门到文本分类实战
---

## 一、为什么需要词向量
计算机只认识数字，不认识文字。你跟它说"苹果"，它眼里这就是一串编码字符，既不知道这是一种水果，也不知道它和"香蕉"的关系比和"显卡"近。

所以想让它处理文本，第一步就是**把文字翻译成数字**。最笨的办法是字符串匹配：

```latex
文本A: "我喜欢吃苹果"
文本B: "我爱吃苹果"

按字符算相似度: 6/7 ≈ 85%   ← 看起来还行？
```

但换个说法就露馅了："苹果真好吃"和"这水果太赞了"，字符重合度几乎为零，语义上却是一回事。字符串匹配对语义一无所知，这条路走不通。

**词向量（Word Embedding）的思路**：给每个词分配一个固定长度的浮点数向量，让向量在空间中的位置关系去表达语义关系。词不再是符号，而是坐标。
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002692517-f91a0ed3-f1ef-46bc-9ccb-e24ffcdc7f10.png)

比如每个词用 4 维向量表示，那"Are you OK ?"这句话就会变成一个 `4×4` 的矩阵——每行对应一个词。文本从"一串字符"变成了"一块可以喂给神经网络的数字张量"：
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002706812-cabf984f-8cd1-4651-a123-b734d93a6992.png)

可以这么理解每个维度在干嘛（纯属直觉类比，实际维度是模型自己学出来的，人类读不懂）：

| 维度 | 假想含义 |
| --- | --- |
| 维度 1 | 正面 / 负面情感倾向 |
| 维度 2 | 具体 / 抽象程度 |
| 维度 3 | 名词 / 动词属性 |
| …… | …… |
| 维度 N | 某种复杂的语义模式 |


Embedding 这件事不只属于 NLP。一张图片、一个用户、一件商品、一个时间点，都可以被 embedding 成向量。它是整个深度学习世界统一的"入场券"——万物皆可向量化。

## 二、词与词的关系：语义空间里的距离
词嵌入背后的核心假设只有一句话：**语义相近的词，在向量空间里的距离也应该相近。**
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002726045-2d194d68-f36d-4073-8778-d8f0f3afb971.png)

举个中文的例子：「猫」和「小猫」含义接近，它们的向量会紧紧挨着；「狗」和「猫」差得远一点；「房子」跟猫八竿子打不着，就被甩到空间的另一头去了。把高维向量用 PCA 之类的手段压到二维纸面上，肉眼就能看出这种聚类：
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002738396-8ad4e182-0d6d-4003-a347-616f4350637e.png)

### 怎么量化"距离近"
工程上最常用的度量是**余弦相似度（Cosine Similarity）**——不看向量的长短，只看方向的夹角：

![image-20260831174905925](C:\Users\HUAWEI\Desktop\课件\assets\image-20260831174905925.png)

| 取值 | 含义 |
| --- | --- |
| 1.0 | 方向完全一致，语义相同 |
| 0.0 | 互相垂直，毫不相关 |
| -1.0 | 方向相反，语义对立 |


为什么不用欧氏距离？因为词频会让高频词的向量模长普遍偏大，两个语义很近但词频悬殊的词，欧氏距离可能很远。余弦相似度只关心方向，天然免疫这个问题，所以成了文本相似度的标配。

### 向量还能做算术
词向量最出圈的玩法是向量加减法，经典得不能再经典的例子：
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002837062-3da3fe5c-70ef-4b86-bbbb-d005da472c1b.png)

```latex
向量("king") - 向量("man") + 向量("woman") ≈ 向量("queen")
```

「国王」减去「男性」再加上「女性」，结果落在「女王」附近。这说明向量空间不光编码了"相似性"，连"性别"这种语义维度都变成了空间里一个真实的方向。模型从没被教过语法和常识，这些关系全是从海量文本的统计规律里自己长出来的——这也是词向量第一次让很多人觉得"神经网络好像真的理解了点什么"。
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002868711-1cdd90a5-a508-43bc-90a3-2d1fa4a5a71f.png)

## 三、one-hot 与词向量
在词向量之前，主流做法是 one-hot 编码：词表里有 10000 个词，就用 10000 维的向量表示每个词，对应位置是 1，其余全是 0。
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002886560-51d65a5c-5657-4c29-8962-e8ec1bea7f8a.png)

这套方案有两个硬伤：

1. **又高又稀**。10000 维里 9999 个是 0，存储和计算都在做无用功。词表再大一个数量级，维度就跟着爆炸。
2. **语义完全割裂**。任意两个 one-hot 向量都是正交的——点积恒等于 0。在数学上，「猫」和「小猫」的距离 = 「猫」和「挖掘机」的距离。模型无法从表示本身获得任何语义先验。

词向量恰好补上这两个洞：维度从上万压到几百（稠密），语义关系通过训练灌进向量里（有结构）。
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002903027-9e357558-1eed-49bd-acd8-fc7c97f5c462.png)

| 对比项 | one-hot | 词向量 |
| --- | --- | --- |
| 维度 | 等于词表大小（轻松上万） | 通常 100~1024 |
| 稀疏性 | 极度稀疏 | 稠密 |
| 语义信息 | 无，任意两词正交 | 有，距离即语义 |
| 向量来源 | 人工规则 | 神经网络从语料中学出来 |


一句话总结：**one-hot 是给词发"身份证号"，词向量是给词发"性格画像"。** 前者只解决"区分"，后者同时解决"理解"。

## 四、分词 Tokenization
### 4.1 分词在干嘛
词向量的原料是"词"，但原始文本是连续的字串。分词（Tokenization）就是把句子、段落切成一个个 token 的过程，是文本从非结构化数据走向数学问题的第一步。

<!-- 这是一个文本绘图，源码为：flowchart LR
    A["原始文本<br>非结构化数据"] --> B["分词 / Tokenize<br>切成 token 序列"]
    B --> C["映射为 ID<br>结构化数据"]
    C --> D["查表取向量<br>数学问题"] -->
![](https://cdn.nlark.com/yuque/__mermaid_v3/9371271542df0058df83b60816dc2cab.svg)
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788002952647-60a0dd09-9868-4c92-ad90-54e647476814.png)

### 4.2 切多碎是个学问
粒度不是越小越好，也不是越大越好：

+ **按字切**：粒度太碎，单个字撑不起完整语义。一个「鼠」字，到底是「老鼠」还是「鼠标」？
+ **按句切**：粒度太粗，每句话几乎独一无二，无法复用，模型学不到泛化规律。
+ **按词切**：词是表达完整含义的最小单位，是传统 NLP 的主流选择。
+ **按子词切（Subword）**：当代大模型的主流。常见词整个保留，生僻词拆成更小的片段，兼顾语义完整和词表可控。

| 粒度 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 字 / 字符级 | 每个汉字、字母单独成 token | 词表小，再罕见的词也能表示 | 序列拉得很长，语义片段被切碎 |
| 词级 | 按词典切成完整词语 | 符合直觉 | 词表巨大，未登录词（OOV）没法处理 |
| 子词级 | BPE、WordPiece、SentencePiece 等 | 词表可控，常见词与生僻词都照顾到 | 实现稍复杂，需要专门训练 tokenizer |


现在主流的大模型（DeepSeek、通义千问 Qwen、智谱 GLM 等）几乎清一色用子词方案。你在调用大模型 API 时被计费的 "token"，就是这东西——所以写 prompt 时"废话越多越贵"是有数学依据的。

### 4.3 工具怎么选
**中文传统分词**（做特征工程、关键词抽取时还很好用）：

+ **jieba** —— 安装零门槛，社区活跃度最高，日常够用
+ **HanLP** —— 功能全面的工业级工具包

### 4.4 jieba 上手实战
```python
# uv pip install jieba -i https://pypi.tuna.tsinghua.edu.cn/simple
# encoding=utf-8
import jieba

# ========== 精确模式（默认，最常用）==========
# 试图将句子最精确地切开，适合文本分析
seg_list = jieba.cut("我来到北京清华大学", cut_all=False)
print("精确模式: " + " / ".join(seg_list))
# 精确模式: 我 / 来到 / 北京 / 清华大学

# ========== 全模式 ==========
# 把句子中所有可能成词的子串都扫出来，速度快但有冗余
seg_list = jieba.cut("我来到北京清华大学", cut_all=True)
print("全模式: " + " / ".join(seg_list))
# 全模式: 我 / 来到 / 北京 / 清华 / 清华大学 / 华大 / 大学

# ========== 搜索引擎模式 ==========
# 在精确模式的基础上，对长词再做二次切分，提高召回率
# 适合搜索引擎建索引：用户搜"科学院"也能命中"中国科学院"
seg_list = jieba.cut_for_search("小明硕士毕业于中国科学院计算所，后在日本京都大学深造")
print("搜索模式: " + ", ".join(seg_list))
# 搜索模式: 小明, 硕士, 毕业, 于, 中国, 科学, 学院, 科学院, 中国科学院, 计算, 计算所, ...

# ========== 新词识别的局限 ==========
# 词典里没有的专名会被切碎，比如"杭研大厦"这种内部叫法
seg_list = jieba.cut("他来到了网易杭研大厦")
print(", ".join(seg_list))
# 他, 来到, 了, 网易, 杭研, 大厦   ← "杭研大厦"没被认出来

# 补救办法：手动往词典里塞自定义词
jieba.add_word("杭研大厦")
print(", ".join(jieba.cut("他来到了网易杭研大厦")))
# 他, 来到, 了, 网易, 杭研大厦   ← 这次完整了
```

## 五、PyTorch 的 nn.Embedding 层
PyTorch 里负责"查词向量"的就是 `nn.Embedding`——**本质上它就是一个可以训练的查找表（Lookup Table）**。

### 5.1 一句话说清原理
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788158902191-9ec677e9-e548-4275-8a13-cd471e089e44.png)
`nn.Embedding` 内部维护一个 `num_embeddings × embedding_dim` 的权重矩阵。你传给它一个整数索引，它就把矩阵里对应那一行还给你。所谓"训练词向量"，就是让这个矩阵的每个元素跟着反向传播一起更新——它和其他层的权重没有任何特殊待遇。
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788159344967-347c8cba-2730-4c29-81c9-044527ae3952.png)

### 5.2 函数签名与参数
```python
torch.nn.Embedding(
    num_embeddings,        # 嵌入字典的大小，即词表容量（能装多少个不同的 token）
    embedding_dim,         # 每个嵌入向量的维度
    padding_idx=None,      # 指定哪个索引是填充位，该行的梯度恒为 0，训练中永不更新
    max_norm=None,         # 每次更新后若向量范数超过该值就裁剪回去
    norm_type=2.0,         # 配合 max_norm 使用，默认 L2 范数
    scale_grad_by_freq=False,  # True 时按词频缩放梯度，高频词步子迈小一点
    sparse=False,          # True 时使用稀疏梯度，超大词表场景能省内存
    _weight=None,          # 传入预训练权重做初始化（比如别人训好的词向量）
)
```

实际项目里 90% 的情况只用前三个参数：`num_embeddings`、`embedding_dim`、`padding_idx`。

### 5.3 最小可运行示例
```python
import torch
import torch.nn as nn

# 词表里只有 5 个 token，每个 token 用 3 维向量表示
embedding = nn.Embedding(num_embeddings=5, embedding_dim=3)

# 这个 5×3 的矩阵就是全部"知识"，初始化时是随机的
print("权重矩阵：")
print(embedding.weight.data)
# tensor([[...3个数...],
#         [...3个数...],
#         ...共5行...])

# 传入 3 个索引：0、2、4
input_indices = torch.tensor([0, 2, 4])

# 做的事等价于：取出矩阵的第 0、2、4 行
output = embedding(input_indices)
print("Embedding 输出：")
print(output)   # shape: (3, 3) —— 3 个 token，每个 3 维
```

批量输入也一样，索引张量是什么形状，输出就在最后追加一个 `embedding_dim` 维度：

```python
import torch
import torch.nn as nn

embedding = nn.Embedding(num_embeddings=10, embedding_dim=3)

# batch_size=2，每条序列 4 个 token
input_indices = torch.tensor([[1, 2, 4, 5],
                              [4, 3, 2, 9]])

embedded = embedding(input_indices)
print(embedded.shape)   # torch.Size([2, 4, 3])
# (batch, seq_len) --> (batch, seq_len, embed_dim)
```

真实项目中的标准动作就是：**先用 tokenizer 把文本转成整数索引序列，再把索引序列丢给 Embedding 层**——索引是离散的，向量化这一步就交给这个可学习的查找表。

### 6.1 网络结构设计
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788003226443-698628ab-98f1-4b40-958c-69b2e0cfaba0.png)

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788003241749-d3c5150b-0d19-41e6-bdca-c9f40abf451b.png)

模型本身非常简单：Embedding 层负责把每个词变成向量，然后把一句话里所有词向量加起来（也可以取平均）聚合成句向量，最后过几层全连接做二分类。

```python
import torch
import torch.nn as nn

#定义神经网络
class TextClassifier(nn.Module):
    def __init__(self, vocab_size,embed_dim,num_classes,padding_idx):
        super().__init__()
        #定义一个词嵌入层
        #embedding层的大小是vocab_size*embed_dim,表示词表大小乘以词向量的维度
        # 5000*128
        self.embedding = nn.Embedding(vocab_size,embed_dim,padding_idx=padding_idx)
        #定义一个线性层
        #线性层的大小是 embed_dim*num_classes,表示词向量维度乘以类别数量
        #例如 128*4
        self.fc = nn.Sequential(
            nn.Linear(embed_dim,128),
            nn.BatchNorm1d(128),
            nn.ReLU(),
            
            nn.Linear(128,64),
            nn.BatchNorm1d(64),
            nn.ReLU(),
            
            nn.Linear(64,32),
            nn.BatchNorm1d(32),
            nn.ReLU(),
            
            nn.Linear(32,num_classes)
        )
    
    #例如,输入一个2*6的文本序列,表示2个样本,每个样本6个单词
    def forward(self,x):
        #将每个单词都转为词向量
        #例如,输入的x 是2*6的,每个单词用128维表示
        #那么x经过embedding层后,就会变为2*6*128的结果
        x = self.embedding(x)
        #计算一个句子中各个单词的词向量和
        #也就是将每个句子中的单词的词向量相加后,得到每个句子的向量表示
        #例如, 2*6*128的x ，就会被转换为2*128的结果
        #也就是2个句子,每个句子都用128维来表示
        x = torch.sum(x,dim=1)
        #最终的分类结果
        x=self.fc(x)
        return x
    
if __name__== "__main__":
    #定义一个词表大小为5000,词向量维度为128,类别数量为4,填充索引为0的文本分类器
    model = TextClassifier(vocab_size=5000,
                           embed_dim=128,
                           num_classes=4,
                           padding_idx=0)
    #打印模型结构
    print(model)
    #定义一个2*6的输入数据,表示2个样本,每个样本6个单词
    x = torch.randint(0,5000,(2,6))
    
    #打印输入数据
    print(x)
    #将输入数据传入模型中,得到输出结果
    output = model(x)
    #打印输出结果
    print(output)
    print(output.shape)
```

NLP数据的处理过程:

1. 包括数据集Dataset的构造

```python
# uv pip install torchtext==0.18.0 -i https://mirrors.aliyun.com/pypi/simple
# uv pip install torch==2.3.0 torchvision==0.18.0 torchaudio==2.3.0 --index-url https://download.pytorch.org/whl/cpu
from torch.utils.data import Dataset
from torchtext.data.utils import get_tokenizer
import pandas as pd

#无论是计算机视觉任务还是NLP任务,都要继承Dataset
#构造一个用于读取数据的数据集
class NewsDataset(Dataset):
    # data对象中保存了原始数据,包括标签label和新闻描述text
    # data[0] = (3,"Wall St. Bears Claw Back Into the ...")
    def __init__(self,is_train=True) -> None:
        super().__init__()
        if is_train:
            data = pd.read_csv("./text_cls/ag_news_csv/train.csv")
        else:
            data = pd.read_csv("./text_cls/ag_news_csv/test.csv")
        self.examples = list()
        #返回一个内置的英文分词器
        tokenizer = get_tokenizer("basic_english")
        for index, row in data.iterrows():
            label =row.iloc[0]
            text = row.iloc[2]
            #将文本转为小写,并使用tokenizer进行分词
            tokenized_text = [token.lower() for token in tokenizer(text)]
            #将处理好的文本和标签,保存到list中
            self.examples.append((tokenized_text,label))
    
    def __len__(self):
        return len(self.examples)
    def __getitem__(self, index):
        return self.examples[index]

if __name__== "__main__":

from torchtext.vocab import build_vocab_from_iterator
#实现build_vocab函数,基于dataset,建立词汇表
def build_vocab(dataset):
    #unk表示未知词,pad表示填充词
    special=['<unk>','<pad>']
    text_iter=map(lambda x:x[0] , dataset)#文本序列
    #建立文本词汇表text_vocab
    #将min_freq设置为2,也就是至少出现两次的单词,才会添加到词表中
    text_vocab = build_vocab_from_iterator(text_iter,min_freq=2,specials=special)
    #将unk对应的索引,设置为默认索引
    text_vocab.set_default_index(text_vocab['<unk>'])
    return text_vocab
```

3. 不同长度的文本填充padding
   ![不同长度的多个文本,需要填充特殊单词,例如<pad>,使它们的长度变得相同](https://cdn.nlark.com/yuque/0/2026/png/21571931/1788004083925-08aa474d-62b5-4cbc-a41f-4cd8c1341d9b.png)

```python
import torch
from torch.nn.utils.rnn import pad_sequence

#整个collate_batch函数是批量读取文本数据时的回调函数
def collate_batch(batch,text_vocab):
    text_list=list()
    labels=list()
    #每次读取一组数据
    for text,label in batch:
        text_tokens = [text_vocab[token] for token in text]
        text_tensor=torch.tensor(text_tokens,dtype=torch.long)
        text_list.append(text_tensor)
        labels.append(torch.tensor(label - 1,dtype=torch.long))
        
    padding_idx = text_vocab["<pad>"]
    #将batch填充为相同长度文本 
    text_padded = pad_sequence(text_list,batch_first=True,padding_value=padding_idx)
    labels_tensor=torch.stack(labels)
    #返回文本和标签的张量形式，用于后续的模型训练 
    return text_padded,labels_tensor
```
