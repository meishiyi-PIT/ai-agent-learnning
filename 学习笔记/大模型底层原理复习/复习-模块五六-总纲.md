- **追问 Q&A（2026-10-02 ~ 10-04）**
  - **Q：d_k=512 不缩放时 softmax 最大比例 1.000，为什么是坏事？** 比例全押一个词，其他词信息进不来；分数再怎么微调比例都是 1.000，梯度≈0 学不动。缩放后 0.506。
  - **Q：位置编码要解决什么？** 注意力只看内容不看顺序，"狗咬我/我咬狗"算出来只是换行。给每个位置发一块和词向量同维的"号码牌"加上去，同一个词站在不同位置向量就不同（positional.py demo 1 True、demo 5 False）。
  - **Q：号码牌怎么造、每个数是什么？** d_model 就是词表那张表的列数（每个词几个数），号码牌也要这么多个数。两维一组是一个"表盘"，第 i 个表盘除数 10000^{2i/d}，偶数维放 sin、奇数维放 cos。手算 d=4、除数 1 和 100、pos=1：[sin1, cos1, sin0.01, cos0.01] = [0.841, 0.54, 0.01, 1.0]。前两个数是快针的横纵坐标，后两个是慢针的。快针分相邻、慢针防远处撞牌，合起来每个位置唯一。
  - **Q：为什么用 sin/cos 不直接填 pos？** ① 值域 −1~1 和词向量同量级，填 500 会淹没词义 ② 公式现算任意长度都有，不像 BERT 存 512 行的表 ③ 点积只剩距离：sin a·sin b + cos a·cos b = cos(a−b)，结果只和夹角有关。
  - **Q：为什么 PE(pos)·PE(pos+3) 四个数全一样？** 每个表盘的点积 = cos(两角之差)，(0,3)、(1,4)、(2,5)、(3,6) 减出来都是 3，所以都是 cos3；四个表盘相加都是 1.9649。值本身不同、夹角相同，像 12 点和 3 点、1 点和 4 点都隔 3 小时。结果只认差值不认起点 = 相对位置。算它是为了回答"位置编码给打分贡献的是第几个还是离我几格"。
  - **Q：位置信息怎么携带？** 只在底部加一次 x+p，靠残差主干道一路传到顶层。512 维里语义方向和位置方向近似正交，相加像透明网格叠在照片上。打分时 (x+p)W_Q·((x+p)W_K)ᵀ 展开四项：语义×语义、语义×位置、位置×语义、位置×位置，W_Q/W_K 训练后各取所需。
  - **Q：为什么 Embedding（不是位置编码）乘 √d_model？** Xavier 初始化让词向量每个数标准差 ≈ 1/√d_model（512 维时 0.044），位置编码是 sin/cos 约 0.7；直接相加词义被淹没。乘 √d_model（22.6）正好抵消 1/√d_model，拉到标准差 1。位置编码不经过 Xavier、不乘任何东西。计算顺序：查表 → 乘 √d → 加 PE。LLaMA 不加底部 PE，所以不乘。
  - **Q：softmax 不是归一化了吗，为什么注意力支路也让主干变大？** softmax 归一的是比例（和为 1），输出 = 比例 × V，V 多大输出就多大（demo 0：比例 [0.807,0.097,0.097]、输出 [8.55,1.45]）。
  - **Q：softmax 和 LayerNorm 区别？** [2,4,4,6]：softmax → [0.013,0.097,0.097,0.793] 全正、和为 1，用来分比例/选答案，无参数；LayerNorm → [−1.41,0,0,1.41] 和为 0，用来稳数值范围，有 γ、β。前者变概率、后者变标准分。
  - **Q：归一化用什么实现？** nn.LayerNorm(d_model)（原版）、nn.BatchNorm1d/2d（CNN）、RMSNorm（nn.RMSNorm 或手写一行 rsqrt）。差别在"对哪组数统计"和"要不要减均值"。
  - **Q：FFN 4 倍是怎么来的、ReLU 放大维度？** 升维的是 W₁ 不是 ReLU，ReLU 只逐个 max(0,x)。4 倍是原论文经验值，SwiGLU 模型约 8/3。
  - **Q：o_proj 是什么、原版有没有？** 拼完 8 个头后再过的 512×512 Linear，让每个输出维看到全部头的结果（8 份报告揉成一份结论）。原版有，课程代码叫 self.linear、论文叫 W^O，LLaMA 叫 o_proj。四件套 W_Q/W_K/W_V/self.linear ↔ q/k/v/o_proj。
  - **Q：Generator 为什么不做 softmax？** CrossEntropyLoss 内部自带 log_softmax，要的是 logits；先 softmax 等于做两次，[2,1,0] 两次后 [0.45,0.30,0.25] 被压平、梯度小。softmax 只在推理采样时做。
  - **Q：Embeddings 和 PositionalEncoding 谁有参数？** Embeddings 有（nn.Embedding 的 weight，vocab×d_model，最大的一张表）；PositionalEncoding 用 register_buffer，零参数。
  - **Q：温度公式怎么算？** z=[2,1,0]：T=1 → [0.665,0.245,0.090]；T=0.5 先除得 [4,2,0] → [0.867,0.117,0.016] 削尖；T=2 → [1,0.5,0] → [0.506,0.307,0.186] 熨平。排名不变只变差距。s1_sampling：T=0.3 '函数' 0.74、T=1.5 0.26。
  - **Q：Decoder 为什么还要做一遍掩码自注意力？和 Encoder 的区别？能不能只做一次？** Encoder 看源句、双向通读；Decoder 看目标句已写部分、单向回看，交叉注意力只回答"原文看哪"，不知道自己写到哪。两句是不同张量、不同权重，合不成一次。GPT 的做法正是把两句拼成一个序列只做一次掩码自注意力 = Decoder-Only。
  - **Q：Cross-Attention？** self_mha(x,x,x,mask) vs mha(x,memory,memory,src_mask)：Q 来自 Decoder，K/V 来自 Encoder 的 memory，只挡源句 pad。"问题是 Decoder 的，资料库是 Encoder 给的"。LLaMA 没有这一步。
  - **口述版（面试用）**：Encoder–Decoder，各 N=6 层，每层"注意力管谁和谁有关、FFN 管怎么加工"，每个子层外包残差 + LayerNorm。入口：查表 × √d_model + 正余弦 PE。Encoder 一层：自注意力（softmax(QKᵀ/√d_k)V，多头切 8 段再 W_O 融合，pad 用 −1e9）+ FFN（512→2048→512）。Decoder 一层三个子层：掩码自注意力（Q/K/V 全来自目标句、三角掩码、Teacher Forcing）→ 交叉注意力（Q 来自 Decoder、K/V 来自 memory）→ FFN。出口：Linear 到词表得 logits，训练直接进交叉熵，推理按温度采样逐字生成到 eos。
  - **复述校正**：Decoder 是三个子层（不是把掩码自注意力和交叉注意力合一）；Encoder 也有 FFN；出口是先 Linear 再 softmax；归一化是为了稳住每层输入的数值范围。

- **追问 Q&A（2026-10-05）**
  - **Q：为什么选 Pre-Norm？** 盯一件事：梯度从最后一层回传到第一层要穿过几道"门"。Post-Norm 是 x₁ = LN(x₀ + 子层)，主干道每层一个 LN，反向时梯度每过一道按标准差缩一次，假设每道 0.8 倍，28 层后 0.8²⁸ ≈ 0.002，第一层几乎收不到梯度，要靠 warmup 小心起步。Pre-Norm 是 x₁ = x₀ + 子层(RMSNorm(x₀))，主干道只有加法，加法导数是 1，梯度原样直通；RMSNorm 在支路上只影响支路。和 CNN 残差"∂F/∂x + 1 的 +1 永远在"同一个道理，Post-Norm 把 LN 套在 +x 外面等于把 +1 也压了。前向实测（s11）：48 层时输出与最初输入的相似度 Post-Norm 0.25、Pre-Norm 0.50。代价：主干道越加越大（s10 实测 Qwen3 从 0.03 涨到约 105），所以出口前补最后一个 norm。
  - **Q：γ（weight）是什么？** RMSNorm 唯一的参数，长度 d_model 的向量，`nn.Parameter(torch.ones(dim))`，逐元素乘，每层一套、每维一个系数，训练出来存在权重文件里（Qwen3-0.6B 第 0 层平均 0.18、第 20 层平均 5，可为负）。除 RMS 负责"稳"，乘 γ 负责"可调"。与 Linear 的 W 区别：W 是矩阵做混合，γ 是向量做逐维缩放，数量不到万分之一，所以 LoRA 不挂它。
  - **Q：RoPE 为什么比加法好？（10-05）** 传统编码"附带"相对位置、RoPE"只给"相对位置且每层都给。加法三毛病：交叉项混着绝对位置要模型自己拆；只在底部加一次会被稀释；位置加在 Q/K/V 分岔之前，V = (x+p)·W_V 也带上位置。RoPE 在分岔之后只转 Q、K。s13 实测：相隔一样、绝对位置不同 → 打分不变（7.635 ×3）；相隔 0/1/2 格 → 11.8/10.6/7.6，距离影响大；随机 q、k 下不单调，越远越弱只是训练后的整体趋势。
  - **Q：s16 的 14 行怎么读？（10-06）** hidden_size 就是 d_model。head_dim 默认 = d_model ÷ 头数，但新模型可单独设（Qwen3-0.6B 1024 维 16 头 head_dim 128）。proj 输出宽度 = 头数 × head_dim，所以 k/v_proj 384 = 4 头说明 GQA 从第 4、5 步就体现；repeat_kv、RoPE、softmax、残差、SiLU×up 都是函数不是模块，钩子看不到。q_norm/k_norm = Qwen3 的 QK-Norm，Q、K 乘完 W 后又可能变大，按每头再归一化一次防 softmax 饱和。decoder 内部最后一维全是 d_model，只有 lm_head 投到词表大小；Embedding 与 lm_head 共用同一张 6400×768 表。
  - **Q：SwiGLU 为什么两次升维？（10-06）** 门控要每一维有两个数：up 出内容、gate 出开关，一个矩阵只能出一个数。两者都是同一个 x 乘不同矩阵，权重训练出来。ReLU 只能关"自己是负数"的维，门能按另一套判断关任何一维。来历：LSTM 门 → GLU（2016）→ Shazeer 2020 试 GLU 变体、Swish 门最好 → PaLM/LLaMA 采用。代价三矩阵，中间维 4d → 约 8/3·d。
  - **Q：gate 和 up 的数怎么来？** 同一个 x（post_attention_layernorm 输出）乘两个不同矩阵：gate_proj、up_proj 都是 Linear(768→2432, bias=False)，forward = down_proj(SiLU(gate_proj(x)) × up_proj(x))。手算 x=[1,2]：W_up 行 [1,1][1,2][2,1] → up=[3,5,4]；W_gate 行 [0,1][2,−2][2,−1] → gate=[2,−2,0]。两套权重随机初始化、反向传播各自学。和 W_Q/W_K/W_V 同套路。
  - **Q：Norm 层也有参数吗？和 W、b 区别？** 有：LayerNorm γ+β、RMSNorm 只有 γ、BatchNorm γ+β 外加 buffer。W 是矩阵做混合、b 是向量做平移、γ 是向量做逐维缩放（相当于只有对角线的 W）。零参数的：位置编码、Dropout、Softmax、ReLU、MaxPool。
  - **Q：113 个 RMSNorm 怎么来？** 每层 input_layernorm + post_attention_layernorm = 56，出口 norm 1，Qwen3 独有 q_norm/k_norm 56，共 113（2N+1，Qwen3 再加 2N）。
  - **口述版：原版 Transformer vs LLaMA（面试用）**：骨架相同（Embedding → N 层注意力+FFN → Linear 到词表），差别是一砍五换。一砍：去掉 Encoder 和交叉注意力，源句目标句拼成一个序列，只剩掩码自注意力。五换：① 位置 底部加正余弦 → 每层对 Q/K 转 RoPE（相对距离进打分、每层都有、V 不沾位置）② 归一化类型 LayerNorm → RMSNorm（去减均值和 β，少算一轮，效果持平）③ 归一化位置 Post → Pre（主干道只剩加法、梯度直通；代价主干越加越大、出口补一次 norm）④ 注意力 MHA → GQA（几个 Q 头共用一组 KV，KV Cache 缩到几分之一，Decode 读显存跟着缩）⑤ FFN ReLU 两矩阵 → SwiGLU 三矩阵（门按另一套判断开关每一维，同参数量效果更好，中间维 8/3·d）。另：Qwen3 加 QK-Norm，MoE 把 ⑤ 拆成多专家。

  - **Q：缓存池怎么算？**（4090 跑 DeepSeek-R1-Distill-Qwen-7B，28 层、4 个 KV 头、head_dim 128、BF16）① 可用 = 24 × 0.9（`--gpu-memory-utilization`）= 21.6 GB ② 权重 7.62B × 2 = 15.2 GB ③ 预留 = 激活峰值 + 运行时开销，启动时用假请求量出约 1.4 GB ④ 池 = 21.6 − 15.2 − 1.4 = 5.0 GB ⑤ 每 token = 2 × 28 × 4 × 128 × 2 = 57,344 B ≈ 57 KB ⑥ 总 token 上限 = 5e9 ÷ 57,344 ≈ 8.7 万（所有请求合计，每请求占 输入 + 已生成） ⑦ 并发 = 上限 ÷ 每请求长度：4K → 21 个，32K → 2.6 个。对比 LLaMA-2-7B（MHA 32 层 32 KV 头）512 KB/token，同池只装 9,500 token，4K 只能并发 2 个。
  - **Q：前缀缓存怎么命中？** 因果掩码 → 每个 token 的 K、V 只取决于自己和前面 → 开头逐 token 相同则 K、V 相同。按 16 token 一块，指纹 = 哈希(本块 token + 前一块指纹) 串成链；新请求逐块查索引，命中的块直接指过去、引用计数 +1，只 Prefill 剩余部分（system prompt 1000 + 问题 50：复用 62 块 992 token，Prefill 1050 → 58）。只共享写满的块，最多浪费 15 token，前缀越长占比越小。开头一个 token 变（如时间戳）链条全断 → 不变的放前、会变的放后。请求结束块不立即清，计数 0 标记可回收，池满按 LRU。和"语义缓存"不同，结果完全一致。SGLang 用基数树按 token 粒度匹配。
  - **Q：为什么块大小是 16？** 实验折中不是计算：块大则最后一块空位多（21 请求最坏 块16 浪费 0.4% / 块256 浪费 6%），块小则 Block Table 长、注意力 kernel 读显存零碎、并行度差。vLLM 论文（SOSP 2023）第 7 节测 1~256：长对话 16~128 好、短指令 16/32 好 → 默认 16，`--block-size` 一般不调。
  - **复述校正**：公式里是 KV 头数不是 Q 头数；不存 Q 是因为历史 Q 不再被用；缓存池后面还有 ÷每 token 字节 → token 上限 → ÷请求长度 → 并发 两步。

  - **Q：负载均衡？** 路由强者愈强，最后挤到一两个专家。① Switch 辅助损失 = 专家数 × Σ(专家 i 实际 token 比例 × 路由给它的平均概率)，均匀≈1、偏心变大（实测 1.00 vs 3.03），系数 0.001 加进总损失 ② 专家容量：满了去自己 top-k 的下一志愿，都满则溢出、本层输出 0 靠残差传，主要训练用，HF/vLLM 推理不丢 token ③ DeepSeek-V3 无辅助损失：给每个专家路由分加偏置，被选多调低、少调高。
  - **复述校正**：路由的单位是每个 token（不是请求）；top-k 后要归一化并把 k 个专家输出按权重加权求和，再加回主干道 h；省计算不省显存的原因不是"权重不变"，而是选谁要等路由算完、所以全部专家必须常驻显存；负载均衡要先说"强者愈强"的病因，再说三法（含 DeepSeek-V3 偏置）。

  - **Q：全量微调显存账？** 每参数 16 字节 = BF16 权重 2 + BF16 梯度 2 + FP32 主权重 4 + AdamW m 4 + v 4；7B × 16 = 112 GB 起步，加激活 16 GB × 1.25 ≈ 160 GB。冻结（requires_grad=False）后梯度不分配（W.grad 是 None）、优化器不管它，只剩权重一笔。7B 的 B 是十亿、GB 的 B 是字节。
  - **Q：激活值要不要算、能不能省？** 激活值 = 前向每层的中间结果（Norm 输出、Q/K/V、注意力分数、FFN 中间向量）。反向求梯度要用前向输入：y = w·x 时 w 的梯度 = y 的梯度 × x，所以 x 必须存。LoRA 省不掉它：梯度要穿过冻结层传到前面的 A、B，非线性函数反向要用输入；旁路求 A 的梯度要用 x。大小 ∝ batch × 序列长 × hidden × 层数，和权重无关；4090 跑 7B LoRA 约 5 GB。梯度检查点：只存每层入口、反向时重算该层，激活大降、训练慢约三成（时长系数 6 → 8），配 enable_input_require_grads()。推理不做反向，激活用完即扔，只留权重和 KV Cache。

  - **Q：A、B 谁为零谁随机有规定吗？** 没有。B 的梯度 ∝ A·x、A 的梯度 ∝ B，一个为零一个随机都能起步且起点 BA=0；都零锁死、都随机起点被改（demo 偏离 122%）。论文和 PEFT 默认 B 零、A 随机（PEFT 用 kaiming 均匀）。

  - **Q：A、B 量化吗？推理时呢？** 不量化，全程 FP32 存、BF16 算，NF4 只压冻结基座。原因：要更新、太小（4000 万参数 160 MB）、NF4 刻度按预训练权重正态分布设计而 B 从零起步。名字是 NF4 不是 INT4（INT4 是等距那种）。训完先用 BF16 基座 merge 成 W'，A、B 融进 W' 不再单独存在；部署要省显存就量化整个 W'（INT8/NF4/GPTQ/AWQ）。多 adapter 热切换时 A、B 单独存，保持 BF16 即可。

- **追问 Q&A（2026-10-07）**
  - **Q：Prefill / Decode / Roofline？** Prefill 整段输入并行算一次，产出全部输入的 K、V 和第一个 token；Decode 每步送 1 个 token。指标：TTFT（Prefill）、TPOT/ITL（Decode 每步）、E2E = TTFT + 输出长 × TPOT、吞吐。每步都要把全部权重从显存搬到计算核心（7B BF16 14 GB，A100 约 7 ms，1 个 token 的计算只要约 0.05 ms）：Prefill 2048 个 token 共用一趟 → 卡算力；Decode 1 个 token 一趟 → 卡带宽。饺子馆类比：备料卡厨师手速、端盘卡跑堂。I = 计算量 ÷ 搬运字节，A100 平衡点 = 312 TFLOPS ÷ 2 TB/s = 156；Decode 单请求 I≈1，128 请求 I≈124 仍卡带宽，约 160 才过线。推高 I：凑批（分子大，提吞吐、单请求 TPOT 不变）；量化 / 缩缓存（分母小，14 GB → 3.5 GB，一步 7 → 2 ms，单请求也快）。
  - **Q：PagedAttention？** 朴素做法每个请求按最大长度预留一整段连续显存 → 过度预留 + 碎片，利用率 20~40%。本机账（池 5 GB、平均 1134 token）：按 8192 预留每请求 467 MB 只放 10 个、利用率约 15%；按块分配 40 个全放下、99%。启动时把池切成 16 token 一块的物理块（7B 一块约 0.9 MB、5 GB 约 5400 块），每个请求一张 Block Table 记逻辑块 → 物理块，一个块号管全部层。例：40 token 领 [7,2,9]，第 49 个 token 再领一块 → [7,2,9,4]，读时按表拼回，结束全还。浪费只剩最后一块空格。代价：多查一次表，vLLM 自写注意力内核。COW：并行采样共用 [0,1]、计数 2；样本 1 写块 1 前先复制成块 2 → [0,2]；样本 2 计数 1 直接写；写满的块永远共用；计数减到 0 才还。
  - **Q：连续批处理与两个参数？** 静态（HF generate）整批等最长：22/18/372 token 跑 372 步 45 秒，有用 412、实算 1116、白算 63%。连续：等待队列 + 运行集，每步组批 → 执行 → 结算，写完立刻返回并还块、空位立刻补；6 请求每步 3 个：总步数 572 → 372、平均拿到结果 472 → 126 步。依赖 PagedAttention 随时领还块。max_num_seqs 1 → 16：吞吐 11 → 99 token/s、间隔 89 → 161 ms（课件"调大排队更久"不对，等待反而变短，变差的是间隔）。max_num_batched_tokens = 每步 token 预算，先排 Decode 再给 Prefill、放不下切块（Chunked Prefill）；8 个 Decode + 2000 token 新请求：256 → TTFT 13.5 s / 老用户每步卡 1.5 s，1024 → 8.5 / 4.2，2048 → 8.7 / 8.7。调法：硬约束 ≥ max_num_seqs → 聊天取小如 2048、长文/RAG/离线 > 8192 → 压测 P99 TTFT 和间隔对 SLO。
  - **Q：九站？** ① API Server（OpenAI 兼容）② 模板 + 分词（问题 6 token → 套模板 18）③ 调度 ④ GPU 执行 ⑤ Prefill 写块 ⑥ Decode（34 步，缓存 18 → 52）⑦ 采样 ⑧ 增量转文字（整体解码切掉已推部分，"龘" 2 个 token，结尾 "�" 先不推）⑨ SSE 推送；⑥~⑨ 每步循环。CPU 活与 GPU 计算分进程。PD 分离：长 Prefill 拖住所有 Decode 用户，拆成 P 池和 D 池各自扩容调参，代价 KV 跨机搬（RDMA、逐层边算边传）；一两张卡用 Chunked Prefill 就够。启动 vllm serve 路径 --served-model-name --api-key；常用 --gpu-memory-utilization 0.9、--max-model-len、--max-num-seqs、--max-num-batched-tokens、--enable-prefix-caching、--tensor-parallel-size；日志 "GPU KV cache size" 与 1.3 公式对账。
  - **Q：调度器依据什么判断？**（vLLM V1 默认 FCFS）四个依据：token 预算 max_num_batched_tokens、条数 max_num_seqs、空闲块、先来后到（--scheduling-policy priority 可改）。不分 Prefill/Decode，只问"这一步要算几个 token"。顺序：先老请求（各占 1 预算，块写满再领一块；领不到就抢占最晚来的请求：还块、回等待队列头、之后重算）；再新请求（条数满停 → 查前缀缓存 → 剩余 prompt 与预算比：放得下整段、放不下开 Chunked Prefill 只算一截 → 块不够停、不插队）；输出"请求 X 这步算几个 token"清单。例：预算 2048、8 个 Decode 用 8；A prompt 2000 前缀命中 1000 → 算 1000；B prompt 3000 → 本步只算 1040；合计 2048。老请求优先保 token 间隔、切块防长 prompt 吃满一步、抢占踢最晚来的因为它重算损失最小。
  - **复述校正**：Prefill/Decode 对，补成"Prefill 很多 token 共用一趟权重搬运、Decode 每个 token 都要搬一趟（I≈1）"。PagedAttention：浪费的根源是"每个请求按最大长度预留一整段连续空间"，不是"给 KV Cache 划一块池子"（池子本来就要有）；每块存的是 16 个 token 在全部层的 K、V，靠 Block Table 映射；漏了前缀共享 + COW。连续批处理：补上"以步为单位重新组批、写完立刻返回并还块"，漏了两个参数 max_num_seqs / max_num_batched_tokens 及调法。

学每个重点前，先在这三条线里找到它的"站号"，再进代码。导图最后一个分支就是这三条线。

### 2.1 前向线：一个 token 怎么变成下一个 token

| 站 | 原版 Transformer（模块五） | LLaMA / Qwen（模块六） | 代码 |
|---|---|---|---|
| ① 分词 | 词向量课件 子词分词 | 同 | `arch_train/s1_tokenize.py` |
| ② Embedding | nn.Embedding × √d_model | 不乘 | `deepLearning/transformer/embedding.py` |
| ③ 位置 | 底部加正余弦，一次 | 每层注意力里对 Q/K 转 RoPE | `positional.py` ↔ `s13_rope_freq.py` |
| ④ 归一化 | 相加后 LayerNorm（Post） | 进门前 RMSNorm（Pre） | `model.py` ↔ `s7_rmsnorm.py` |
| ⑤ 注意力 | MHA，softmax(QKᵀ/√d_k)V | GQA，公式不变，K/V 头少 → KV Cache 小 | `attention/multi_head.py` ↔ `s12_gqa_cache.py` |
| ⑥ 残差 | x + Sublayer(x) | 同（CNN 课件 F(x)+x 就是它） | — |
| ⑦ FFN | ReLU 512→2048→512 | SwiGLU 三矩阵 → MoE 多专家 + 路由 | `s16_llama_walk.py` ↔ `s14_moe_router.py` |
| ⑧ 输出 | Linear + softmax | 同；训练进交叉熵，推理按温度采样 | `s1_sampling.py` |

> 上表按"零件"分类编号，1.1~1.7 各张卡片里的"前向线第几站"用的是这套编号。下面按**真实计算顺序**完整走一遍（2026-10-09 补讲），站号自成一套，和上表不一一对应。

**按计算顺序走一遍**（MiniMind 尺寸：hidden 768、8 层、Q 头 8 / KV 头 4、head_dim 96、FFN 中间维 2432、词表 6400；输入"猫在睡"）

1. **分词**：切 token、查编号，如 [1, 300, 301]，形状 (1, 3)。
2. **Embedding 查表**：从 6400 × 768 的表取 3 行 → (1, 3, 768)。原版这里要 × √d_model 再加正余弦位置编码；LLaMA 两样都不做，位置留给每层的 RoPE。
3. **RMSNorm**（1.2）：主干道留底，复印一份归一化后送进注意力 = Pre-Norm。原版是相加之后才 LayerNorm。
4. **q/k/v_proj**（三个 Linear = 三个全连接层）：q 出 768 = 8 头 × 96，k/v 各出 384 = 4 头 × 96。
   - **训练线挂在这里**：LoRA 的 A、B 长在这些 Linear 旁边；QLoRA 时这些 W 以 NF4 存（1.5、1.6）。
   - **GQA 从这里开始**（1.3）：k、v 只有 4 个头。
5. **RoPE + 注意力**（1.2、1.3）：Q、K 先 QK-Norm 再按位置转角度（V 不转）→ 4 个 KV 头 repeat_kv 成 8 个 → softmax(QKᵀ/√d)V，带因果掩码只看自己和前面。
   - **推理线挂在这里**：K、V 写进 KV Cache；因果掩码保证旧 token 的 K、V 永远不变，所以能缓存。
6. **o_proj + 残差**：8 个头融合回 768，加回主干道。o_proj 也是 Linear，LoRA 标准四件套 q/k/v/o 到这里齐了。
7. **RMSNorm + FFN + 残差**（1.2、1.4）：再归一化 → gate、up 两路升到 2432 → SiLU(gate) × up → down 降回 768 → 加回主干道。
   - **MoE 换在这里**：一个 FFN 换成 N 个专家 + 路由，每个 token 选 k 个。
   - 这里 3 个 Linear，LoRA "豪华型"把它们也挂上。
   - 第 3~7 步重复 8 次（8 层）。
8. **出口**：最后一次 RMSNorm → lm_head（768 → 6400）给每个词打分得 logits。
   - **训练时**：logits 直接进交叉熵，对下一个 token 的标签，prompt 部分标签是 −100。
   - **推理时**：按温度 softmax → 采样出一个 token → 回到第 1 步进下一轮。

**六个重点在这条路上的位置**：1.1 Transformer 是整条路的骨架；1.2 RoPE/RMSNorm 是第 3、5、7 步的零件；1.3 GQA/KV Cache 在第 4、5 步；1.4 MoE 在第 7 步；1.5/1.6 LoRA/QLoRA 是第 4、6、7 步那 7 个 Linear 的"改法"和"存法"；1.7 vLLM 管第 5 步的缓存放在哪、以及第 8 步之后谁先进下一轮。

一句话：**一个 token 走"查表 → 8 次（归一化、注意力、归一化、FFN）→ 打分"这一条路，六个重点全钉在这条路的某一站上**。

### 2.2 训练线：哪些参数被改、用什么精度存

1. 骨架永远是模块五那五句：前向 → loss → zero_grad → backward → step。
2. 预训练和 SFT 的 loss 都是交叉熵（下一词）；SFT 只换数据、加模板、加 -100 掩码。
3. 全量微调显存 = 权重 + 梯度 + AdamW 8 字节 + 激活 ≈ 16~20 倍参数字节。
4. LoRA 冻结 W 只训 B·A → 梯度和优化器状态砍 99%。
5. 精度规则：被更新的 FP32 存；不更新的 BF16 → INT8 → NF4；计算永远 BF16。
6. QLoRA = 4bit 基座 + LoRA；量化只在 from_pretrained 那一行，LoRA 只在 get_peft_model 那一行。
7. 还装不下：梯度检查点换时间、ZeRO 把梯度/优化器/参数摊到多卡。
8. 训完 merge_and_unload 回 BF16 基座，变普通模型进推理线。

**按训练一步的真实顺序走一遍**（2026-10-09 补讲；以 `lora_train_fixed.py` 为例，同时写出全量 / LoRA / QLoRA 三种做法在每站的差别）

1. **备数据**（1.5 第 2 节）：一条 SFT 样本套对话模板 → input_ids；labels 里 prompt 部分填 −100、回答照抄（第 1 条 103 + 528 = 631）。预训练和 SFT 的区别只在这里。
2. **加载基座**（1.6）：决定 W 以什么精度进显存，**显存账第 1 笔"权重"在这一站定下**。
   - 全量：FP32 加载（或 BF16 + FP32 主副本），每参数 4~6 字节
   - LoRA：BF16，每参数 2 字节（7B 15 GB）
   - QLoRA：NF4，每参数约 0.5 字节（7B 约 5 GB）；**量化只在这一站发生一次**；接着 prepare_model_for_kbit_training（冻结、未量化层升 FP32、开梯度检查点）
3. **挂 LoRA**（1.5）：get_peft_model 冻结全部 W，在选中的 Linear 旁边长出 A（随机）、B（零），A、B 以 FP32 存。全量微调没有这一站。
4. **前向**（= 2.1 那条前向线 = 模块五的 `logits = model(x)`）：每个 Linear 算 W·x + (α/r)·B·A·x；QLoRA 的 W 每次临时解压成 BF16、乘完就丢；计算一律 BF16。**显存账第 2 笔"激活值"在这一站产生**：沿路存下每层中间结果给反向用；开了梯度检查点只存每层入口。训练时 use_cache=False，不写 KV Cache。
5. **算 loss**（2.1 第 8 步）：logits 和错开一位的 labels 做交叉熵，−100 的位置跳过。
6. **反向**（模块五的 `loss.backward()`）：链式法则从 loss 往回走，要用第 4 站存的激活。梯度沿 Pre-Norm 的残差主干道直通回第 1 层（1.2 选 Pre-Norm 的原因）。**显存账第 3 笔"梯度"在这一站产生**：全量给每个参数都算；LoRA/QLoRA 只给 A、B 算，冻结的 W 梯度是 None，但梯度要穿过它们往前传。
7. **更新**（模块五的 `optimizer.step()` + `zero_grad()`）：**显存账第 4 笔"优化器状态"在这一站**：AdamW 给每个被更新的参数存 m、v（各 4 字节）+ FP32 主权重。全量是 76 亿个参数，LoRA 只有 A、B 那几百万到几千万。QLoRA 可选分页优化器，显存快爆时把这些状态挪到内存条。梯度累积 8 步才更新一次（等效 batch 16）。
8. **循环与收尾**：3 个 epoch，每个 epoch 评估一次 eval_loss；保存只存 A、B（几十 MB）；训完 merge_and_unload 用 BF16 基座算 W' = W + (α/r)·B·A，变成普通模型交给推理线。

**显存四笔账 = 四个站**：权重（第 2 站）、激活（第 4 站）、梯度（第 6 站）、优化器状态（第 7 站）。三种省法各管一站：量化 / 低精度管第 2 站，梯度检查点管第 4 站，LoRA 管第 6、7 站；还装不下就用 ZeRO 把第 6、7 站（再加第 2 站）切到多张卡上。

一句话：**训练一步 = 备数据 → 按某种精度加载 → 挂旁路 → 前向存激活 → 交叉熵 → 反向算梯度 → AdamW 更新；四笔显存分别生在第 2、4、6、7 站，三种省法各管一站**。

**Transformer 和训练线怎么结合**（2026-10-09 追问）

Transformer 是被训练的那个函数（训练线第 4 站的 `model(x)`），训练线是改它的循环。训练只在三处碰它：前向跑一遍、反向梯度倒着穿过每个零件、更新改它的参数。

- **零件在训练里的角色**：有参数的 = Embedding、7 个 Linear（q/k/v/o、gate/up/down）、RMSNorm 的 γ、lm_head；没参数的 = RoPE、softmax、SiLU、残差（不更新，但输入要存成激活给反向用）。全量微调：有参数的全部更新。LoRA：全部冻结，只更新 7 个 Linear 旁边的 A、B。QLoRA：同 LoRA，且 7 个 Linear 的 W 以 NF4 存，Embedding/lm_head/γ 升 FP32 但仍冻结。
- **Teacher Forcing = SFT 的 labels**：模块五 tgt_x = `<bos> 我 爱 你`、tgt_y = `我 爱 你 <eos>`，右移一位 + 三角掩码并行训练；SFT 是 input_ids = prompt + 回答 + EOS、labels = [−100]×prompt + 回答。区别只有两点：错一位放进模型内部做；原文和译文拼成一个序列（Decoder-Only），prompt 段 label 填 −100 = 只读不考。
- **为训练服务的设计**：因果掩码让整段回答一次并行训；残差 + Pre-Norm 让梯度直通回第 1 层；√d_k 缩放和 RMSNorm 防 softmax 饱和梯度归零；Generator 训练时输出 logits 直接进交叉熵。Xavier 初始化、标签平滑是从零训练用的；微调从训好的权重出发，只有 A 随机、B 置零要初始化。

### 2.3 推理线：一个请求在服务里怎么跑

1. Prefill 并行读输入（卡算力）→ Decode 逐 token（卡带宽，I≈1）。
2. 每步只算新 token 的 Q/K/V，历史 K/V 在 KV Cache 里；GQA 决定它多大。
3. KV Cache 按 16 token 一块分页，Block Table 映射，前缀共享 + COW。
4. 连续批处理每步重新组批；两个调度参数定吞吐 / 延迟。
5. 推理精度 BF16 → INT8 → INT4，缩小分母推高 I。
6. 采样 温度 / top_k / top_p → 下一个 token → 回到 2。
7. 大规模：PD 分离、TP/DP、KV 搬家。

**按一条请求的真实顺序走一遍**（2026-10-11 补讲；4090 跑合并后的 7B，vLLM 服务，用户问"用两句话介绍长城。"）

0. **启动时一次性做的**（1.3 缓存池七步）：把 BF16 权重 15.2 GB 搬进显存；用假请求量出激活峰值约 1.4 GB；剩下的 24 × 0.9 − 15.2 − 1.4 ≈ 5 GB 切成 16 token 一块的物理块（约 5400 块）进空闲列表。日志 "GPU KV cache size" 就是这一步的结果。
1. **进门**（1.7 九站 ①②）：API Server 收 HTTP → 套对话模板 → 分词，6 个字的问题变成 18 个 token。查前缀缓存：开头若和之前请求逐块相同，命中的块直接引用不再算。
2. **调度**（1.7 卡 3、调度器依据）：进等待队列。每一步调度器先排运行集里正在 Decode 的老请求（各占 1 个 token 预算、块写满就再领一块），再用剩余预算放新请求；18 个 token 放得下就整段 Prefill，放不下切块。三个硬限制：max_num_batched_tokens、max_num_seqs、空闲块。
3. **Prefill**（1.7 卡 1、2.1 前向线）：18 个 token 并行走完 2.1 那条前向线。每层第 5 站算出的 K、V 按 Block Table 写进领到的块（18 个 token 占 2 块）。这一步卡算力，耗时 = TTFT 的主体。出口 logits 经采样得到第 1 个 token。
4. **Decode 循环**（1.3 卡 2、1.7 卡 1）：每步只把上一步采出的 1 个 token 送进前向线；第 4 站只算它自己的 Q/K/V，第 5 站用它的 Q 和缓存里全部历史 K 打分、按分数加权全部历史 V，新 K/V 追加进当前块。每步都要把 15 GB 权重从显存搬一遍只配 1 个 token，I≈1，卡带宽，耗时 = TPOT。写了 34 步，缓存 18 → 52 个 token，第 4 块领到一半。
5. **凑批**（1.7 卡 3）：第 4 步不是一个人在跑。运行集里 16 个请求的"当前 token"拼成一批一起过前向线，一趟权重搬运配 16 个 token，吞吐 ×16，每个人的 TPOT 略变长。这就是推高 I 的分子法。
6. **采样 + 出字**（1.1 温度卡、1.7 九站 ⑦⑧⑨）：logits ÷ T 再 softmax，top_k / top_p 砍长尾，抽一个 token；把到目前为止全部 token 整体转文字、切掉已推的部分（生僻字拆成多 token 时结尾 "�" 先不推）；SSE 推给用户。然后回到第 2 步参加下一步组批。
7. **结束**：采到 EOS。调度器把这个请求的 4 个块引用计数减 1；没别人共用就还回空闲列表，前缀缓存开着时先留作"可回收"等别人命中。
8. **装不下 / 不够快时的手段**：显存不够 → 量化整个 W'（INT8 / INT4，分母法，单请求也变快）、GQA 本身已把每 token 的 KV 从 512 KB 压到 57 KB；并发不够 → PagedAttention 把利用率从 20~40% 提到 99%；长 prompt 拖住所有人 → Chunked Prefill；再大规模 → PD 分离两池各自扩容，KV 走 RDMA 搬家；单卡放不下 → TP 切到多卡。

**六个重点在这条线上的位置**：1.1 Transformer 的前向在第 3、4 步被反复调用；1.2 RoPE/RMSNorm 在前向线内部不变；1.3 GQA 决定第 0 步每 token 占多少字节、KV Cache 是第 3、4 步的产物和原料、前缀缓存在第 1 步；1.4 MoE 在前向线第 7 站，推理时每 token 只算 k 个专家、显存仍装全部；1.5/1.6 的产物（merge 后的 W'）在第 0 步被加载，QLoRA 的 NF4 和这里的 INT8/INT4 同一条规则"只读的才能量化"；1.7 vLLM 就是第 0~8 步本身。

**训练线和推理线的三处对照**：① 训练第 4 站前向时 use_cache=False、不写 KV Cache，推理必写；② 训练存激活给反向用，推理激活用完即扔，显存只剩权重 + KV Cache；③ 训练是 Teacher Forcing 整句并行，推理是 Prefill 一次并行 + Decode 逐字串行，所以推理的瓶颈分成算力和带宽两段，训练没有这个分裂。

一句话：**一条请求 = 启动时切好缓存池 → 进门分词查前缀 → 调度分配预算和块 → Prefill 并行写缓存出首字 → Decode 每步一字、和别人凑批 → 采样出字推送 → 结束还块；六个重点全在其中某一步，而训练线和推理线只差"写不写缓存、存不存激活、并行还是串行"三件事**。
