# 1.神经网络从入门到实战(基础架构篇)

- 一、深度学习
  - 定义：利用多层神经网络，从原始数据中自动学习特征，并完成预测或决策
    - 三个关键词：多层神经网络（逐层堆叠、逐级抽象）/ 自动学习特征 / 原始数据（图像、文字、语音）
    - 【结论】机器学习 vs 深度学习：人工设计特征、模型学习规律 vs 模型自动学习特征和规律
    - 典型领域：计算机视觉 CV、自然语言处理 NLP、智能语音、推荐系统
  - 1.1 传统编程 vs 深度学习
    - 【结论】传统编程：工程师手动编写规则，规则固定难以覆盖所有情况；深度学习：不给规则，给数据和答案，让计算机自己从样本中寻找规律，数据越多识别越准
  - 1.2 两大学习范式（按训练数据带不带标准答案）
    - 1.2.1 监督学习：有输入（题目）和标签（标准答案），目标是让预测无限逼近标准答案，在新题上也能拿分
    - 1.2.2 无监督学习：无标签，靠相似性自动发现"团伙"——最常见是聚类
  - 1.3 分类 vs 回归
    - 【结论】分类输出离散的类别标签（好评/差评）；回归输出连续数值（明天气温）
    - 容易搞混：目标检测预测框坐标 (x1, y1, x2, y2) 是回归不是分类
    - 同一问题可两边看：票房预测金额=回归，分"扑街/回本/爆款"=分类；评分 4.3=回归，好/中/差评=分类
  - 1.4 深度学习：当网络变深之后
    - 端到端：图片和标签一起丢给网络，从像素到语义一层层自己学
    - 特征层级：底层特征（像素、边缘、颜色块）→ 中层特征（局部形状：眼睛轮廓、嘴巴弧线）→ 高层特征（完整人脸、物体）
- 二、神经网络：逐层拆解
  - 2.1 感知机（人工神经元）——一切的源头
    - 2.1.1 直觉：信贷员决策 = 加权打分 + 阈值判断；权重不是人定的，而是从数据中自动学出来的
    - 2.1.2 生物神经元（树突接收、细胞体处理、轴突输出、突触有强弱）→ 感知机是极度简化的数学模型；人脑约 860 亿个神经元
    - 2.1.3 感知机五个核心要素
      - 输入 x1..xn（样本数据）；权重 w1..wn（重要程度，决定影响方向和强度）；偏置 b（决策的基础倾向 / 调整决策阈值，早期文献写成 -θ）；求和 z（综合得分）；激活函数 f(z)（把得分变成分类结果）
      - 偏置让决策边界不必经过原点，可平移到任意位置；b 大=激进易放贷，b 小=保守
    - 2.1.4 感知机的数学模型
      - 求和：$z = \sum w_i x_i + b$
      - 向量形式：$z = w^T x + b$，$y = \text{sign}(z)$；z > 0 输出 1，z < 0 输出 0
      - 两步：第一步 输入乘权重加偏置（线性变换）；第二步 送入非线性函数（激活函数）
    - 2.1.5 几何视角：感知机在画一条线，高维时是一个超平面——自动找到一条决策边界把不同类别区分开
    - 2.1.6 判断苹果还是橘子
      - 特征 x1 甜度 0-10、x2 红色程度 0-10；已学到 w1=0.6, w2=0.8, b=-7
      - 【结论】感知机决策三特点：权重 = 特征重要性；偏置 = 决策门槛；|z| = 确信度（z 离 0 越远越确信，接近 0 是边界样本）
      - 工作原理：加权求和 → 与阈值比较 → 根据错误反馈微调权重 → 直到学会正确分类
  - 2.2 激活函数——引入非线性，给直线"掰弯"
    - 2.2.1 线性可分与线性不可分
      - 线性可分：一条直线（二维）/一个平面（高维）能完全分开两类；线性不可分：不存在这样的直线或平面
      - 【结论】没有激活函数：无论多少层，输出都是输入的线性组合 W总·x+b总，只能解决线性可分问题；有激活函数：每层输出后加一道"弯折"，层层叠加可拟合任意复杂曲线
      - 每个神经元两步：先做线性变换，再做独立非线性激活
    - 2.2.2 Sigmoid
      - 【代码】torch.sigmoid；$\text{Sigmoid}(x) = \frac{1}{1 + e^{-x}}$，输出范围 (0, 1)，S 型曲线；输入 0 → 输出 0.5
      - 早期受欢迎：输出可当概率；形状像生物神经元"抑制-兴奋"开关
      - 现在几乎不用：致命缺陷梯度消失——S 曲线两端平坦，梯度一层层乘回去接近零，前面层参数更新不动
    - 2.2.3 Tanh
      - 【代码】torch.tanh；$\tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}$，输出范围 (-1, 1)，零均值；示例输出 tensor([-0.9640, -0.7616, 0.0000, 0.7616, 0.9640])
      - 零均值优点：输出有正有负，权重更新方向更自由，收敛更快（Sigmoid 全正输出会让更新方向"绑在一起"）
      - 致命伤同 Sigmoid：两端导数趋近零，梯度消失；现在主要活在 RNN / LSTM 里
    - 2.2.4 ReLU（线性整流单元）
      - 【代码】torch.relu；$\text{ReLU}(x) = \max(0, x)$：负数全变零，正数照常过
      - 统治深度学习三原因：根治梯度消失（正半轴梯度永远是 1）；计算快到几乎免费（判断正负 + 赋值）；天然产生稀疏性（约一半输入为负 → 输出 0 → 神经元休眠，模拟人脑同时激活仅 1%~4%）
      - 大坑 Dead ReLU：某神经元对所有输入输出 0，梯度永远 0，参数再也更新不了
      - 补救：LeakyReLU（负数乘以很小斜率如 0.01）、PReLU（斜率由网络自己学）
      - 【结论】直接用 ReLU 或其变体，90% 的情况稳得很
  - 2.3 为什么"深"才有意义
    - 神经网络符合函数定义：输入（如 28x28=784 个像素值）→ 映射规则（权重和偏置）→ 输出（分类标签概率或房价）
    - 表达能力：网络能"画"出多复杂的数据分界线 / 模拟多扭曲的函数
    - 全连接：每一层的每一个节点都和下一层的每一个节点连着
    - 层级抽象：输入层原始像素 → 隐藏层1 边缘、颜色块 → 隐藏层2 形状、纹理 → 隐藏层3 眼睛轮廓、鼻子形状 → 输出层"这是一只猫"
    - 参数量计算：3 输入 → 4 隐藏 → 2 隐藏 → 3 输出，总参数 = 3×4 + 4×2 + 2×3 = 26；调成 3→3→4→3 变 33 个
    - DeepSeek 旗舰版本参数量数千亿
    - 【结论】参数总量相同时，更深的网络通常比更宽的网络表现更好——"深度学习"重点在"深"
  - 2.4 万能逼近定理——神经网络的数学原理
    - 定理：对于有限区间内的任意连续函数，只要神经元数量足够多，神经网络就能无限逼近
    - 通俗理解：任意复杂的连续函数，可以通过多个简单函数的组合进行无限逼近（比如泰勒展开）；只用 Sigmoid 做基础元件，堆叠组合即可
    - 参数作用（图注）：调节 w21 决定函数上下界，b21 整体上下平移，w11 决定中间部分斜率，b11 平移中间部分
    - 神经元越多，中间部分可调节的锯齿阶梯越多，逼近精度越高
    - 演示链接 https://ricklamers.github.io/univeral-approximation-theorem-tfjs/
  - 2.5 前向传播——数据怎么流
    - 定义：数据从输入层开始，逐层乘以权重加偏置、经激活函数非线性变换，层层传递抽象，直到输出层生成预测结果；信息严格从前往后流动，不涉及参数调整；是神经网络推理的核心过程
    - 类比：工厂流水线
  - 2.6 用矩阵重新理解一切
    - 前一层所有输出打包成列向量；该层所有权重排成矩阵（行数 = 本层神经元数，列数 = 前层神经元数）；矩阵乘法自动完成加权求和；最后统一过激活函数
    - 关键在硬件：GPU 成千上万核心专为矩阵乘法优化，1000×1000 矩阵乘法可同时计算所有位置；CPU 逐个循环慢一个数量级以上
    - 【结论】一层网络 = 矩阵乘法 + 激活函数——现代深度学习框架的核心抽象
  - 2.7 使用 PyTorch 搭建全连接神经网络
    - PyTorch 解决把数学公式、模型结构、训练流程转换成可运行程序；数学回答模型为什么能学到规律
    - 入门需掌握：定义模型 API（Tensor 基本操作、nn.Module）；训练模型 API（Dataset 和 DataLoader、损失函数、优化器、自动求导机制）
    - 标量（一个数）/ 向量（一维数组）/ 矩阵（二维数组）/ 张量（n 维数组）；向量表示一个对象，矩阵把很多向量组织成表（3 行 2 列 = 3 个人 × 身高体重），张量表示更高维数据
    - 张量 shape：每一个维度上分别有多少个元素
    - 【代码】torch.tensor、.shape、.device、torch.device('cuda' if torch.cuda.is_available() else 'cpu')、.to(device)
    - 【代码】torch.zeros(2,3,4)、torch.ones(2,3,4)、torch.randn(3,4)、torch.eye(3,3)
    - 【代码】NumPy ↔ Tensor：torch.tensor(arr)、t.numpy()、GPU tensor 先 .cpu() 再 .numpy()
    - 广播机制：a 形状 (3,1) + b 形状 (1,2)，a 按 b 的列数复制、b 按 a 的行数复制；(2,3) * (3,) → b 变为 (2,3)

    - 【代码】余弦相似度：torch.linalg.norm；cos = dot(a,c) / (a_norm * c_norm)
    - 【代码】转置 M.t()；矩阵相乘 M1 @ M2.t()、torch.matmul；批量乘法 torch.bmm（要求三维 [batch, m, n] × [batch, n, p]，二维会报错）、torch.matmul 也可

      - 换轴不改变数据本身，改变的是访问数据的索引顺序；permute(2,0,1) 把形状 (2,3,4) 变为 (4,2,3)

  - 2.8 输出函数
    - 核心作用：决定模型最终输出的数值范围和物理意义，把原始分数转换为概率
    - 变成概率的三个好处：统一尺度结果直观可比（[0,1] 且和为 1）；提供置信度区分"确信"与"猜测"（肿瘤 99.9% 直接手术 vs 51% 要求复查）；支持灵活策略阈值（垃圾邮件 >90% 拦截、70%~90% 人工复核、<70% 放行）
    - 置信度：模型为最终选中的类别所分配的概率值
    - Softmax：分类任务使用；把每个结果限制在 0 到 1 之间；所有类别概率之和等于 1
      - $\text{Softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}}$：以 e 为底对每个得分做指数运算作分子，分母为各分类指数之和
      - 【结论】softmax 不会改变模型输出之间的大小顺序，只会为每个类别分配相应的概率
      - 手算示例：logits [2, 1, 0.1] → exp ≈ 7.389, 2.718, 1.105，和 11.212 → softmax ≈ [0.659, 0.242, 0.099]，和为 1
    - 【代码】torch.softmax(x, dim=0)；nn.Softmax(dim=1) 加在网络最后一层后

# 2.神经网络从入门到实战(训练优化篇)

- 2.9 模型参数初始化
  - 两种情况：框架默认初始化（nn.Linear 的 __init__ 自动调用 reset_parameters 初始化 weight 和 bias）；通过 torch.nn.init 自定义初始化
  - 【代码】nn.init.xavier_uniform_(layer.weight)、nn.init.zeros_(layer.bias)
  - 常见初始化方法：uniform_ 均匀分布、normal_ 正态分布、constant_ 常量、Xavier 均匀/正态分布、kaiming 均匀/正态分布
  - 全连接层 nn.Linear 权重通常用 kaiming 正态分布初始化（适合 ReLU 及变体 Leaky ReLU）：从均值 0、标准差 $\sqrt{2/\text{fan\_in}}$（fan_in = 输入数据维度）的正态分布采样，目的是让数据稳定传播、避免梯度消失或爆炸；偏置通常初始化为 0
  - 正态分布 X~N(μ, σ²)：μ=0, σ=1 为标准正态分布；-1σ 到 1σ 概率 68.2%，-2σ 到 2σ 概率 95.4%
    - 均值 $\mu = \frac{x_1 + x_2 + \cdots + x_n}{n}$：数据集中在哪个位置，决定曲线在哪儿
    - 标准差 $\sigma = \sqrt{\frac{(x_1-\mu)^2 + \cdots + (x_n-\mu)^2}{n}}$：数据有多分散，决定曲线是胖是瘦（越分散越矮胖）
- 2.10 损失函数——模型怎么知道自己错了
  - 作用：对前向传播输出的预测值做量化打分
  - 均方差损失函数 MSE——万能损失函数（公式课件为图片）：预测值与真实值一一相减、平方、取平均
    - 为什么平方不用绝对值：消去正负号（避免正负误差抵消）；放大大误差（误差 3 → 9，误差 0.4 → 0.16）
    - 奶茶销量例：真实 100、150、80，预测 110、140、90，MSE = (10² + 10² + 10²) / 3 = 300 / 3 = 100
    - 【结论】MSE 对离群点特别敏感（100 预测成 500 贡献 160000）——既是优点（绝不姑息大错误）也是缺点（可能被噪声带偏）
- 2.11 梯度下降——模型训练的实质
  - 目标：让损失值越来越小；问题是参数 w、b 该往哪个方向改
  - 导数：自变量动一点点，函数值跟着动多少；割线斜率 → B 无限逼近 A 变成切线 → 切线斜率 = 导数
    - 【结论】导数 = 切线斜率 = 函数在这一点的"瞬时变化率"；导数 +3 意味着自变量右走 1 小步函数值上升约 3 小步
    - 曲线陡峭处导数绝对值大；越靠近波谷越平缓；波谷正中心切线水平，导数为零
    - 一元函数 f(x) 梯度就是导数；导数为正向右上升，导数为负向右下降
    - 【结论】几何结论：负导数 −f′(w) 像方向盘，无论在谷底哪一侧都把 w 往谷底推；梯度下降的方向是负导数的方向
    - 迭代示例：初始 W=1.0, y=2.0, L=16.0 → 第 1 轮 W=2.6, y=5.2, L=0.64 → 第 2 轮 W=2.92, y=5.84, L=0.0256 → 第 3 轮 W=2.984, y=5.968
  - 学习率——最容易被低估的超参数：控制每次参数更新的步长，训练神经网络最重要的超参数
    - 【结论】太大：参数震荡甚至发散，Loss 不降反升（一脚踩到对面山上）；适中：稳定快速收敛；太小：收敛慢（高跟鞋小碎步下山）
    - 实践：从 0.01 或 0.001 开始试；Loss 忽高忽低不降——减半；平稳下降但太慢——翻倍；Adam、AdamW 自带自适应学习率，是大多数任务首选
  - 偏导数：多元函数在固定其他变量不变时，只随其中一个变量变化的变化率（把其他变量当常数按普通导数求）；∂f/∂x 是 x 方向变化率，∂f/∂y 是 y 方向变化率
  - 梯度：把函数关于所有参数的偏导数打包成一个向量，指向函数增长最快的方向，负梯度是下降最快的方向
    - 【结论】沿着梯度方向走函数值增加得最快；沿梯度反方向走函数值下降得最快；负梯度并不一定直接指向函数图像最低点
    - 流程：损失函数计算各偏导（反向传播）→ 组合成向量（梯度）→ 梯度下降调整 w 与 b（参数更新）→ 多轮训练直至损失趋于平缓
    - 【结论】梯度 = 对损失函数每个参数求偏导组成的向量；梯度下降 = 让参数沿梯度反方向减小一点点，多小由学习率决定
  - 梯度下降算法本身
    - 更新规则：$\text{新参数} = \text{旧参数} - \text{学习率} \times \text{梯度}$；梯度为正就减小参数，梯度为负就增大参数
    - 类比：盲人下山，用脚跺地面感觉坡向，朝低的方向迈一步
    - 【代码】手写房价预测梯度下降：价格 = w * 面积 + b，真实行情 3*面积 + 10 + random；loss = (y-h)**2；dw = -2 * x * (y-h)，db = -2 * (y-h)；w -= dw * 0.01，b -= db * 0.01（0.01 是学习率）；matplotlib plt.ion/plt.cla/plt.pause 动态画图
- 2.12 反向传播与链式法则
  - 反向传播：比较预测结果和真实答案算出误差，逐层回传，算出每个权重该怎么调（根据预测误差计算梯度，更新模型权重）
  - 复合函数求导（链式法则）：复合函数 (f∘g)(x) = f(g(x))，把一个函数的输出当另一个函数的输入
    - 【结论】链式法则核心思想：外层函数求导，乘以内层函数的导数
    - 【结论】神经网络是一个由大量简单函数（线性变换与非线性激活）复合而成的、可导的、带有可学习参数的巨大复合函数
  - 反向传播完整分步示例（课件为图）：前向算预测值和损失 → 从损失出发逐层回传梯度 → 完成一次参数更新
  - 【代码】Autograd 自动微分：requires_grad=True 的张量才记录运算流程、支持求梯度；w = torch.tensor([2.0], requires_grad=True)，y = w*3，loss = (y-9)**2，loss.backward()，w.grad
- 2.13 优化器
  - 优化器（Optimizer）：根据当前损失和梯度，计算下一步如何调整模型参数
  - 【结论】损失函数：负责打分；反向传播：负责算梯度；优化器：负责真正更新参数
  - 伪代码：for 每一个参数 in 模型的所有参数: 参数.数值 = 参数.旧数值 - 学习率 × 参数的梯度
  - 默认首选优化器 Adam：【代码】torch.optim.Adam(model.parameters(), lr=0.001)
    - 三个理由：极度省心默认参数就能跑；对学习率不敏感（给每个参数自适应调节步长，梯度大的参数步长自动缩小防震荡）；收敛速度快（训练初期像坐火箭）
- 2.14 完整训练循环
  - 2.14.1 数据预处理
    - 2.14.1.1 归一化：把不同尺度的数据统一到 [0, 1]；目的是让模型更容易、更稳定地学习
      - 不归一化的问题：计算溢出（输入量级 >100 多层累乘膨胀到 inf，过小下溢到 0）；Sigmoid/Tanh 直接饱和梯度消失；量级大的特征碾压量级小的特征，权重更新被大尺度特征主导
      - Min-Max 归一化：$x_{norm} = \frac{x - x_{min}}{x_{max} - x_{min}}$
      - 【代码】numpy：(data - data.min(axis=0)) / (data.max(axis=0) - data.min(axis=0))；示例视频时长 [60,180,15] 与粉丝数 [500000,20000,1200000] → [[0.273,0.407],[1.0,0.0],[0.0,1.0]]
    - 2.14.1.2 one-hot 编码：把类别变成向量
      - 绝对不要直接把"红色=1，绿色=2，蓝色=3"喂给网络：强加"大小顺序"（蓝 > 绿 > 红）；制造"距离假象"（蓝红差异是绿红差异两倍）
      - 规则：向量长度 = 类别总数，属于哪一类对应位置为 1，其余为 0
      - 【代码】F.one_hot(labels, num_classes=4)
  - 2.14.2 训练流程：不断重复的循环
    - 早停法：每训练完一轮在测试集上测一次；测试集表现连续多个轮次不再变好就立即终止训练
    - 【代码】TensorBoard：uv pip install tensorboard；tensorboard --logdir=./mlp_mse/logs；SummaryWriter(log_dir)、writer.add_scalars('Loss/train', {...}, epoch)、writer.add_scalar('Accuracy/test', ...)
    - 【代码】MNIST + MSE 版训练脚本：datasets.MNIST(root, train, download, transform=transforms.ToTensor())、DataLoader(dataset, batch_size=100, shuffle=True)、model.to(device)、nn.MSELoss()、torch.optim.Adam(model.parameters())、tqdm.tqdm、model.train()、F.one_hot(labels, num_classes=10).float()、opt.zero_grad() / loss.backward() / opt.step()、model.eval()、torch.inference_mode()、torch.argmax(outputs, dim=1)、torch.eq(pred, target).float().mean()、torch.save(model.state_dict(), path)；早停 patience=5、best_test_loss=float('inf')、no_improve_count
    - 【结论】代码对应过程：logits = model(features) 前向传播（模型做出什么预测）；loss = loss_fn(outputs, labels) 计算损失（相差多少）；optimizer.zero_grad() 清空梯度（避免上一轮梯度影响）；loss.backward() 反向传播（每个参数承担多少错误）；optimizer.step() 参数更新（如何变化才能降低损失）
    - 【结论】六步：① 初始化（随机初始值，不能让所有参数一样否则梯度一样网络就废了）② 前向传播（矩阵乘法 + 激活函数逐层计算）③ 算损失（用 MSE）④ 反向传播（链式法则，自动求导引擎包办）⑤ 更新参数（步长 = 学习率 × 梯度，沿梯度反方向）⑥ 判断收敛（Loss 不再明显下降或达到预设轮数，可用早停法）
  - 2.14.3 模型预测

- 2.15 交叉熵损失函数
  - 概率分布：把随机事件所有可能结果列出来并告诉每个结果发生的可能性；取值范围 [0,1]；所有取值概率之和为 1；离散分布（取值有限或可数）
  - 【结论】分类任务的本质，是让模型输出的概率分布尽量接近真实标签的概率分布
  - 交叉熵损失函数：衡量模型输出的概率分布和真实世界概率分布之间的差异性；差距越小越好，即交叉熵越小越好（公式课件为图片）
  - 【代码】nn.CrossEntropyLoss()；示例 logits [[2.0, 1.0, 0.1], [0.5, 2.5, 0.3]]，labels = tensor([0, 1])（类别索引，不是 one-hot）；loss.item()

# 1.卷积神经网络深度解析

- 1. 全连接神经网络的"两大致命伤"
  - 1.1 空间信息被"拍平"了——丢失了空间结构
    - 200×200 彩色自拍拉成 120000 维一维向量，像素之间的空间邻居关系全丢；左眼像素索引 0~99，右眼跑到 50000~50099
    - 【结论】图像不是一串彼此独立的数字，而是一种具有空间组织关系的数据
  - 1.2 参数爆炸——模型根本训不动
    - 参数数量随图像尺寸平方级增长；1000×1000 彩色 3 通道 → 展开 3,000,000 维，隐藏单元 1,000,000 个 → 参数 3,000,000 × 1,000,000 = 3×10^12（3 万亿）
- 2. 卷积运算
  - 2.1 卷积运算的本质——"滑动窗口 + 加权求和"
    - 直觉：拿一个小方框（卷积核）在图片上从左到右、从上到下滑动，每停一处把方框里数字和对应像素相乘再全加起来，作为新图片该位置的像素
    - 卷积五步：K×K 卷积核（滤波器、kernel）放左上角 → 逐元素相乘 → 乘积求和得输出特征图该位置的值 → 向右滑动一个步长重复 → 滑完一行向下移动直到扫完整图
    - 定义：利用一个可学习的"特征提取器"（卷积核）在图像上滑动，对局部像素"对应相乘再求和"（加权求和）以提取图像特征
    - 【结论】卷积不是"整张图一起看"，而是先从局部开始找规律；不同卷积核找不同模式（横向边、竖向边、颜色、纹理）；层数越深，简单模式被组合成形状、部件与语义概念
    - 【代码】nn.Conv2d(1, 8, kernel_size=3)：输入 [1, 1, 32, 32] → 卷积核权重 [8, 1, 3, 3] → 输出 [1, 8, 30, 30]；常见卷积核 3x3 或 5x5
  - 2.2 偏置项——卷积也有 bias
    - 卷积层 bias 是每个输出通道对应的可学习标量；卷积核完成局部加权求和后，bias 广播加到该输出通道的所有空间位置；out_channels=16 就有 16 个 bias
    - 【结论】每个输出通道对应一个偏置值——有多少个卷积核（输出通道），就有多少个偏置
    - 卷积与全连接对比——卷积的优点
      - 权重共享：同一个卷积核在输入不同位置滑动时权重完全相同；一个检测"边缘"的卷积核在整张图所有位置找边缘
      - 局部连接（减少参数量）：卷积核每次只看很小一块区域（如 3×3）；全连接 1000×1000 图像 100 万像素接 1000 个神经元参数达 10^9（10 亿）
      - 结果：参数数量急剧减少，大幅降低内存和计算量，使训练深层网络成为可能
    - 【代码】参数量对比：nn.Linear(3*200*200, 10) vs nn.Conv2d(3, 1, kernel_size=3)；sum(param.numel() for param in layer.parameters())；4x4 单通道图：3x3 卷积核 weight 9 个 + bias 1 个 vs nn.Linear(16, 4)
  - 2.3 填充（Padding）——别让特征图越卷越小
    - 定义：在输入图像（或特征图）外围补上一层或多层额外的"假像素"（通常是 0）；目的是防止特征图越变越小，同时让边缘像素被充分计算
    - 【结论】padding 的核心价值是"保护边缘"和"控制尺寸"；边缘像素被卷积核覆盖次数更少（手机边框、衣服袖口、鞋底轮廓常在边缘）；让多层卷积可连续堆叠
    - 【代码】nn.Conv2d(1, 1, kernel_size=5)（4x4 输入无法卷）、kernel_size=5, padding=1；kernel_size=3, padding=0 输出 [1,1,2,2]；kernel_size=3, padding=1 输出 [1,1,4,4]（尺寸不变）
  - 2.4 步长（Stride）——一次滑多远
    - 步长：卷积核在输入图像上每次滑动移动的像素个数；步长越大输出越小、计算量越小，代价是丢掉更多细节
    - 【结论】卷积核大小决定"一次读取几个点"，步长决定"这些点在原图上相隔多远"；stride 控制特征图缩小速度
    - 【代码】输入 [1,3,32,32]：Conv2d(3, 8, kernel_size=3, stride=1, padding=1) → [1,8,32,32]；stride=2, padding=1 → [1,8,16,16]
  - 2.5 感受野——"站在越高的地方，看得越远"
    - 定义：输出特征图上的一个点，对应到原始输入图像上的区域大小；输出层一个像素能"看到"输入层多大范围
    - 一层 3×3 卷积感受野 3×3；两层 3×3 卷积后感受野增加到 5×5
    - 【结论】网络越深，感受野越大，单个神经元"知道"的上下文越丰富——浅层看纹理，深层看"整个物体的概念"
  - 2.6 多通道卷积——彩色图的卷积该怎么算
    - 单通道输入：1 个通道进，1 个卷积核 → 1 个通道出，二维矩阵逐元素乘加
    - 双通道输入：两个输入通道各配一个 2*2 卷积核，两个结果逐元素相加得单通道输出——"逐通道卷积 → 求和"
    - 三通道输入（RGB）核心原则：卷积核的通道数 = 输入特征图的通道数；卷积核的个数 = 输出特征图的通道数
      - RGB 图卷积核扩展为 3×3×3（每个输入通道配一个 3×3 二维核，三个结果求和成单通道输出）
    - 多通道输出：增加卷积核数量；每个卷积核独立运算，各自产生一个输出通道；2 个卷积核 × 3 个输入通道 → 2 通道输出
    - 【代码】nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3)：输入 [1,3,32,32] → 权重 [16, 3, 3, 3]（[输出通道数, 输入通道数, 核高, 核宽]）→ 输出 [1,16,30,30]
  - 2.7 批量操作——一次算一批
    - mini-batch 输入形状 N × C_in × H_in × W_in；卷积核张量形状 C_out × C_in × K × K，对批次每张图用同一套参数
    - 例：32 张 224×224 RGB 图 X.shape = 32 × 3 × 224 × 224（32 张、3 通道、高 224、宽 224）；32 张图作为独立样本沿 batch 维堆叠
    - 卷积核参数：nn.Conv2d(in_channels=3, out_channels=64, kernel_size=3) → 64 × 3 × 3 × 3（64 个完整卷积核、每个含 3 个输入通道切片、每切片 3×3）
    - 【结论】卷积核形状中没有 N 维；无论一次输入 1 张、32 张还是 64 张，卷积层参数数量都不变
    - batch 维度上的权重共享：图片 1..N 都使用同一个 W；32 张图片 × 同一套卷积核参数；GPU 并行执行
    - 输出形状 Y.shape = 32 × 64 × H_out × W_out，每张输入图都有自己独立的 64 通道输出
    - 【结论】批次中的图片彼此独立计算，但共享同一套卷积核参数；N 决定一次处理多少张图片，不改变卷积层的参数形状和数量
    - 【代码】10 张 [10,3,32,32] 过 Conv2d(3,16,3)：weight 16*3*3*3，bias 16，conv.weight.numel() + conv.bias.numel()
  - 2.8 特征图尺寸怎么算
    - 特征图尺寸 H_out x W_out 由输入尺寸、卷积核大小、padding、stride 共同决定；后一层输入形状必须和前一层输出对齐，否则 shape mismatch
    - 尺寸公式（课件为图片）：符号 H_in/W_in 输入高宽、K 卷积核尺寸 kernel_size、P 填充圈数 padding、S 步长 stride、H_out/W_out 输出高宽；本质是问"窗口能放下几次"（货架 / 尺子 / 空位 类比）
    - 【结论】常用速查（stride=1）：32×32 + 3×3 + padding 1 → 32×32 不变；32×32 + 5×5 + padding 2 → 32×32 不变；32×32 + 3×3 + padding 0 → 30×30；32×32 + 5×5 + padding 0 → 28×28
    - 【结论】口诀：pad = kernel//2 时尺寸不变（对奇数卷积核有效）
    - 卷积层有多少参数
      - 【代码】nn.Conv2d(3, 8, kernel_size=3) → conv.weight.shape = [8, 3, 3, 3]（8 个完整卷积核、每核 3 个输入通道、每切片 3×3）
      - 权重参数量公式、正方形 K×K 版、偏置数 = 输出通道数、总参数量公式（课件均为图片）；该层 8×3×3×3 + 8 = 224 个可训练参数；conv.bias.shape = [8]
      - 【结论】卷积层参数量与输入图片高宽和 batch size 无关，只与输入通道数、输出通道数、卷积核大小以及是否使用偏置有关
      - 多层：第 L 层参数量公式与总和公式（课件为图片）；无偏置则去掉偏置项
      - 三层卷积例：conv1 = Conv2d(3,8,3) → 8×3×3×3+8 = 224；conv2 = Conv2d(8,16,3) → 16×8×3×3+16 = 1168；conv3 = Conv2d(16,32,3) → 32×16×3×3+32 = 4640；总 224+1168+4640 = 6032
- 3. 池化：给特征图做一次"瘦身"
  - 池化：把特征图一小块区域用一个统计量（最大值或平均值）概括，压缩空间尺寸
  - 最大池化（Max Pooling）：每个滑动窗口取最大值，更关注局部最显著特征（边缘、纹理）；CNN 最常用
    - 核心作用：在局部区域内只保留响应最强烈、最显著的特征，忽略较弱信息；2×2 窗口 stride=2 空间尺寸直接减半
    - 【结论】三个关键特性：零参数（无权重无偏置不需训练）；通道独立（每通道单独池化，C_in = C_out）；保留显著特征（只留最强信号，微弱噪声被丢掉）
    - 【代码】nn.MaxPool2d(kernel_size=2)：[1,3,32,32] → [1,3,16,16]

- 5. CNN vs 全连接网络：核心差异总结
  - 【结论】连接方式：FCNN 每个输出连到所有输入 / CNN 每个输出只连局部窗口；参数数量：FCNN 输入维 × 输出维随图片尺寸平方增长 / CNN C_out × C_in × K × K 与图片尺寸无关；权重共享：FCNN 每连接独立参数 / CNN 整张图共用同一组卷积核；空间结构：FCNN 拍平后丢失 / CNN 天然保留二维结构；通道概念：FCNN 无（N×V 二维）/ CNN 有（N×C×H×W 四维）；计算量：FCNN 参数多计算密集 / CNN 参数少但中间特征图占显存；适用场景：FCNN 表格数据、文本分类 / CNN 图像、视频
  - 【结论】记忆方式：全连接 = 每个人看整张图然后投票；卷积 = 几千个人各自看一小块然后用同一套标准打分，最后汇总

# 2.卷积神经网络深度解析（标题级要点）

- 过拟合、欠拟合与 Dropout
  - 泛化能力：不仅拟合训练数据，还能对从未见过的新数据准确预测
  - 欠拟合：训练集和测试集表现都差；原因是模型太简单、训练轮数太少、学习率不合适、特征处理太粗
  - 过拟合：把噪声也记住了；训练集好、测试集/线上明显变差
  - 【结论】过拟合的本质：模型的"容量"（层数、神经元个数、参数量；类比行李箱）> 数据集的"信息量"
  - LeNet-5 参数量：conv1 3×6×5×5 = 450；conv2 6×16×5×5 = 2,400；fc1 400×120 = 48,000；fc2 120×84 = 10,080；fc3 84×10 = 840；总计 ≈ 61,770；CIFAR-10 训练集 50,000 张；参数/样本 = 61,770 / 50,000 ≈ 1.24，模型参数比训练样本还多
  - Dropout：防止过拟合；每次训练迭代随机丢弃一些神经元，被丢弃的不参与前向和反向传播；nn.Dropout(p=0.5) 表示 50% 神经元输出乘以 0，每次迭代换一批
  - 【代码】LeNet5 fc1/fc2 后加 nn.Dropout(p=dropout_rate)
- 梯度消失与梯度爆炸
  - 2.1 梯度消失：网络越深训练误差不降反升；本质是反向传播时梯度连乘导致指数级衰减，浅层参数几乎无法更新
    - 残差连接：将某一层的输入直接与经过该层变换后的输出逐元素相加；输出 = F(x) + x；反向传播梯度为 ∂F/∂x + 1，"+1"提供无损传播捷径
    - 恒等映射 f(x) = x：输入是什么，输出原封不动是什么
    - 【结论】残差连接从根本上缓解梯度消失，解决深层网络退化问题，使训练成百上千层超深网络成为可能，是 Transformer 等现代大模型能成功训练的核心设计
    - 类比：递文件，普通网络每人重新手抄，残差网络把原件和抄写本装订在一起递下去
    - 【代码】ResBlock：conv1 Conv2d(c,c,3,padding=1) → F.relu → conv2 → F.relu(y + x)；Net 中 Conv2d(3,64,3,1) → ResBlock(64) → Conv2d(64,128,1,1)
  - 2.2 梯度爆炸：梯度像滚雪球越滚越大变成无穷大（NaN），权重剧烈更新崩溃
    - 50 层网络梯度是 50 个数连乘：每个因子 <1（如 0.5）→ 0 梯度消失；每个因子 >1（如 2.0）→ ∞ 梯度爆炸
    - 本质是连乘效应，每层输出 y = Wx 数值范围不断膨胀；解决核心是控制每层输出数值范围
    - BN（Batch Normalization 批归一化）：把每一层中间结果数值范围拉回稳定区间，数值不过大不过小；每过一层先把这一批数据的队形整理一下再交给下一层
    - 【代码】nn.BatchNorm2d(6) / nn.BatchNorm1d(120) 在激活函数之前使用；配合 Conv2d/Linear 的 bias=False

# 3.词向量入门到文本分类实战

- 一、为什么需要词向量
  - 计算机只认数字；字符串匹配走不通："我喜欢吃苹果" vs "我爱吃苹果" 字符相似 6/7 ≈ 85%，但"苹果真好吃"和"这水果太赞了"字符重合几乎为零却语义相同
  - 词向量（Word Embedding）思路：给每个词分配固定长度的浮点数向量，用空间位置关系表达语义关系；词不再是符号，而是坐标
  - 每个词 4 维向量，"Are you OK ?" 变成 4×4 矩阵，每行一个词
  - 维度假想含义（纯直觉类比，实际维度是模型学出来的）：正面/负面情感、具体/抽象、名词/动词……
  - 【结论】Embedding 不只属于 NLP：图片、用户、商品、时间点都可以 embedding——万物皆可向量化，整个深度学习世界统一的"入场券"
- 二、词与词的关系：语义空间里的距离
  - 核心假设：语义相近的词，在向量空间里的距离也应该相近；「猫」「小猫」紧挨，「狗」远一点，「房子」在另一头；PCA 压到二维可见聚类
  - 怎么量化"距离近"：余弦相似度（Cosine Similarity）——不看向量长短只看方向夹角（公式课件为图片）
    - 取值：1.0 方向完全一致语义相同；0.0 互相垂直毫不相关；-1.0 方向相反语义对立
    - 【结论】不用欧氏距离：词频让高频词向量模长偏大，语义近但词频悬殊的词欧氏距离可能很远；余弦只关心方向天然免疫，成为文本相似度标配
  - 向量还能做算术：向量("king") - 向量("man") + 向量("woman") ≈ 向量("queen")；"性别"成了空间里一个真实方向，关系全是从海量文本统计规律里自己长出来的
- 三、one-hot 与词向量
  - one-hot：词表 10000 个词就用 10000 维向量，对应位置 1 其余 0
  - 两个硬伤：又高又稀（9999 个 0，词表大一个数量级维度跟着爆炸）；语义完全割裂（任意两个 one-hot 正交、点积恒为 0，「猫」-「小猫」距离 = 「猫」-「挖掘机」距离）
  - 【结论】对比：维度 one-hot 等于词表大小（上万）vs 词向量通常 100~1024；稀疏性 极度稀疏 vs 稠密；语义信息 无、任意两词正交 vs 有、距离即语义；向量来源 人工规则 vs 神经网络从语料中学出来
  - 【结论】one-hot 是给词发"身份证号"，词向量是给词发"性格画像"；前者只解决"区分"，后者同时解决"理解"
- 四、分词 Tokenization
  - 4.1 分词在干嘛：把句子、段落切成一个个 token；流程 原始文本（非结构化）→ 分词切成 token 序列 → 映射为 ID（结构化）→ 查表取向量（数学问题）
  - 4.2 切多碎是个学问
    - 按字切：粒度太碎，单字撑不起语义（「鼠」是老鼠还是鼠标）；按句切：粒度太粗无法复用；按词切：传统 NLP 主流；按子词切（Subword）：当代大模型主流，常见词整个保留，生僻词拆成片段
    - 【结论】粒度对比：字/字符级 词表小、再罕见也能表示，但序列拉长、语义被切碎；词级 符合直觉，但词表巨大、未登录词 OOV 没法处理；子词级 BPE、WordPiece、SentencePiece，词表可控兼顾常见词与生僻词，但实现稍复杂需专门训练 tokenizer
    - DeepSeek、Qwen、GLM 几乎清一色用子词方案；API 计费的 "token" 就是这东西——prompt 废话越多越贵
  - 4.3 工具怎么选（中文传统分词）：jieba（零门槛、社区最活跃）、HanLP（工业级）、LTP（哈工大）、THULAC（清华）

- 五、PyTorch 的 nn.Embedding 层
  - 5.1 原理：本质是一个可以训练的查找表（Lookup Table）；内部维护 num_embeddings × embedding_dim 权重矩阵，传整数索引返回对应那一行；"训练词向量"就是让这个矩阵跟着反向传播一起更新，和其他层权重没有特殊待遇

# 4.注意力机制

- 一、注意力到底是干嘛的
  - 1.1 先看人是怎么"看"的：刷短视频视线钉在人脸和标题；视觉系统先扫全局、圈出高价值区域，把有限"计算预算"集中砸过去；热力图颜色越深越是大脑愿意花力气的地方
    - 【结论】人的注意力和模型的注意力本质一样，是一个有限的资源，就看怎么分配；注意力机制就是一种有限分配的资源
  - 1.2 把这套思路搬进神经网络："眼力见"换成"权重"
    - 【结论】输入里每个位置都分到一个权重，重要的拿大头，无关的拿零头，模型按这个分配方案去整合信息
    - 给谁注意力多少和模型参数有关，是模型训练/学习到的结果；注意力是一场资源分配游戏
    - 核心作用：让模型学会聚焦关键信息，忽略无关信息
  - 1.3 生活里的注意力：逛淘宝先被主图和价格锚住；开会听到"预算""裁员"耳朵立马竖起来；人靠本能，机器靠训练出来的权重
- 二、公式拆解：Query、Key、Value
  - 注意力公式（课件为图片）
  - 2.1 数学工具：点积（公式课件为图片）：把"两个向量像不像"翻译成一个数
    - 方向差不多（夹角小，cosθ 接近 1）→ 点积很大；互相垂直 → 约等于 0；方向完全拧着 → 负数
    - 对 NLP 重要：词嵌入核心假设"语义相近的词在高维空间向量方向也相近"，点积成为测量"两个词关系近不近"的现成尺子
  - 2.2 三个角色（搜索引擎类比）
    - Query（查询向量）：搜索框里敲的那句话——"我现在想找什么"
    - Key（键向量）：每条搜索结果的标题和摘要——专门跟搜索词对暗号
    - Value（值向量）：点进去看到的正文——真正想搬走的内容
    - 过程：Query 和每条 Key 对暗号（算相似度），对得越上对应 Value 搬得越多，所有 Value 按"搬运比例"搅和在一起就是输出
    - 【结论】注意力的精髓不是"选最优"，而是"分蛋糕"：每个候选都有份，只是切的大小不一样；这让整个计算过程处处可导，梯度畅通回传，模型才能学得动
  - 2.3 三步走战略：① 算分（Query 和每个 Key 点积，得原始相关性分数）② 归一（送进 softmax 压成总和为 1 的分布，从"谁更相关"变成"每家各占几成"）③ 混合（按占比对 Value 加权求和）
  - 2.4 √d_k 是干嘛的：点积之后除以 $\sqrt{d_k}$（$d_k$ 是 Key 向量的维度）
    - 问题：维度越高点积绝对值越大，分数一大导致 softmax 进入饱和区，梯度消失；引入缩放因子 $\sqrt{d_k}$ 缩小点积结果，使 softmax 保持敏感；实验表明可有效防止梯度消失
  - 2.5 softmax：从"打分"到"分账"：把一堆可正可负、有大有小的原始分数，变成加起来正好 100% 的"分账方案"（公式课件为图片）
- 三、注意力机制代码实现
  - 【代码】def attention(q, k, v, dropout=None)：d_k = k.size(-1)；scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)（(..., seq_q, d_k) @ (..., d_k, seq_k) → (..., seq_q, seq_k)，第 i 行第 j 列是第 i 个 query 对第 j 个 key 的原始得分）；p_attn = torch.softmax(scores, dim=-1)（每个 query 分给所有 key 的权重和为 1）；可选 dropout(p_attn)；return torch.matmul(p_attn, v)（按份搬运信息，每个位置混入全序列上下文）
  - 【结论】Attention 是挑重点，就算文本比较长，也能从中间抓住重点，不丢失重要信息
- 四、自注意力机制(Self-Attention)
  - 4.1 和前面注意力的区别：前面 Query 和 Key 通常来自两拨数据（机器翻译：解码端状态当 Query 查编码端中文句子特征 Key/Value，跨序列）；自注意力只有一个改动：Q、K、V 全部来自同一个输入，每个词既是提问者也是被提问者——也叫"内部注意力"
  - 4.2 为什么需要"互相打听"
    - 经典坑：The trophy didn't fit into the suitcase because it was too big. ——it 指 trophy 而非更近的 suitcase；中文："快递放进了储物柜，因为它实在太大了"
    - 【结论】自注意力让每个词都和全句所有词算一遍相关性，不管目标隔多远都能直接建立联系
  - 4.3 为什么要先做一次线性变换
    - 算注意力前每个词向量先分别乘三个权重矩阵 $W_Q$、$W_K$、$W_V$，而不是拿原始 embedding 直接点积
    - 核心原因：同一个词，"出门提问"和"在家被问"时应该拿出两副面孔（「它」做 Query 要携带"找前文出现过的事物"；「快递」做 Key 要亮出"我是实体名词、前面提到过我"）
    - 每个词被加工成三个向量 = 原始词向量 × 对应权重矩阵
    - 三个好处：特征提取（转换为更高级语义表示）；参数学习（通过训练优化）；注意力权重（更准确捕捉重要信息，增强表达能力和灵活性）
  - 4.4 完整的计算链路：① 每个词编码为 Query、Key、Value 三个向量（词嵌入分别乘三个权重矩阵）② 用某词（如 it）的 Query 和其他所有词的 Key 点积，除以缩放因子（根号下 Key 向量维度）③ 相关性分数过 softmax 转成概率分布（和为 1，解释为 it 与其他词的相对重要性）④ 乘以对应的 value v1-v4 求和
  - 4.5 自注意力代码实现
    - 【代码】class SelfAttention(nn.Module)：q_linear/k_linear/v_linear = nn.Linear(hidden_dim, hidden_dim)（三个互不共享参数的线性层，分别学"怎么提问 / 怎么应答 / 怎么贡献内容"）；forward 同一份 x 走三条路得 q,k,v，复用 attention(q,k,v)；x = torch.rand(3, 2, 4)（batch=3，每句 2 个词，词向量 4 维）→ 输出 torch.Size([3, 2, 4])
- 五、多头自注意力机制(Multi-Head Self-Attention) 多角度看问题，信息更全面
  - 5.1 单个注意力头的盲区：一个头只学一套 $W_Q$、$W_K$、$W_V$，只擅长捕捉一种词与词的关系
    - 例句「老王昨晚在群里发了个两百块的红包」至少三层结构：动作链（发 连着 老王 和 红包）；限定信息（昨晚 时间、群里 地点）；属性描述（两百块 说明额度）
    - 多头方案：派一组"专员"每人盯一块，最后开会汇总；头 A 锁定 老王→发→红包 主谓宾主线，头 B 盯 昨晚、群里 时空状语，头 C 关心 两百块 对 红包 的修饰
    - 【结论】多个视角并行开工，模型的表达容量直接翻倍
  - 5.2 "多头"的实现：就是切蛋糕
    - 在 $d_{model}$ 维度上均匀切分：Q、K、V 各自切成 n 段，每段独立跑一遍注意力互不干扰；减少单次计算量，提升并行速度
    - 数值例：词向量 512 维、4 个头 → 512 除以 4，每个头 128 维，四个头单独计算 QKV
    - 每个头输出一个结果（某个角度看到的词与词关系），所有结果沿特征维拼接（concat），再过一层线性变换做融合（公式结构课件为图片）
  - 5.3 手写多头注意力
    - 【代码】class MultHeadedAttention(nn.Module)(d_model, n_head, dropout=0.1)：assert d_model % n_head == 0；self.d_token = d_model // n_head（每头维度）；q_linear/k_linear/v_linear = nn.Linear(d_model, d_model, bias=False)（bias=False 是 Transformer 通行做法）；self.linear = nn.Linear(d_model, d_model, bias=False)（拼接后融合）
    - forward：(batch_size, seq_len, d_model) → .view(n_batchs, seq_len, n_head, d_token).transpose(1,2) → (batch_size, n_head, seq_len, d_token)（头的维度移到前面，matmul 对最后两维操作）；att = attention(q,k,v,self.dropout)；concat = att.transpose(1,2).contiguous().reshape(n_batchs, -1, n_head * d_token)（contiguous 确保内存连续）；output = self.linear(concat)
    - 测试：MultHeadedAttention(8, 2)，q=k=v=torch.randn(2,3,8)
  - 5.4 工程建议：理解归理解，生产环境别手搓
    - 【代码】方案一 nn.MultiheadAttention(embed_dim=256, num_heads=8, batch_first=True)：PyTorch 2.x batch_first=True 输入直接 (batch, seq, d_model)；q=k=v=torch.randn(4, 30, 256) → out torch.Size([4, 30, 256])，attn_weights torch.Size([4, 30, 30])（batch 和 head 拍到一个维度）
    - 【代码】方案二 F.scaled_dot_product_attention(q, k, v, dropout_p=0.1)（PyTorch 2.0+ 首推，底层按硬件自动挑 FlashAttention、内存高效注意力等最优内核）
- 六、动手实战：给 CNN 装上注意力（在 CNN 里嵌入多头自注意力完成图像分类）
  - 6.1 核心思路：把特征图"读"成一句话
    - CNN 特征图 (N, C, H, W) vs 注意力要的 (batch, seq_len, d_model)：特征图每个空间位置 (h, w) 看成一个"词"，该位置 C 维通道特征看成词向量 → 长度 H × W、维度 C 的"句子"
  - 6.2 模型搭建
    - 【代码】CNNWithAttention(num_classes)：conv_layers 五层 nn.Conv2d(3,16,3,bias=False)+nn.BatchNorm2d(16)+ReLU+MaxPool2d(2) → Conv2d(16,32,3)+BN+ReLU+MaxPool2d(2) → Conv2d(32,64,3)+BN+ReLU → Conv2d(64,128,3)+BN+ReLU → Conv2d(128,256,3)+BN+ReLU；self.attention = MultHeadedAttention(d_model=256, n_head=4)（也可 nn.MultiheadAttention(embed_dim=256,num_heads=4)）；self.fc = nn.Linear(400*256, num_classes)
    - forward 形状：[1,256,20,20] N C H W → x.permute(0,2,3,1) → [1,20,20,256] N H W C → reshape(x.size(0), -1, x.size(-1)) → [1,400,256] → self.attention(x,x,x)（q=k=v=x）→ [1,400,256] → reshape(-1, 400*256) → [1,102400] → fc；输入 torch.randn(1,3,112,112)，6 类
    - 【结论】为什么加注意力：卷积核天生"近视眼"（3×3 一次只看一小片，远距离联系要靠很多层堆感受野），注意力一步让图上任意两个位置直接交互，等于给 CNN 补上全局视野（如判断"果皮颜色和果柄形状是否属于同一个水果"）

# 5.Transformer

- 第一章 架构全景：从 Seq2Seq 困境到自注意力革命
  - 1.1 一个比模型更古老的问题：Seq2Seq
    - Seq2Seq（Sequence-to-Sequence）是一类问题的抽象：给定一个序列产出另一个序列——机器翻译、文本摘要、智能客服、代码生成
    - Transformer 之前的主角是 RNN：一个词一个词读，边读边压缩进隐藏状态；是串行的"传话游戏"（二十个人传话到队尾失真）→ 长序列依赖丢失；串行结构天生没法并行，必须算完第 t 步才能算 t+1
    - 2017 年 Google《Attention Is All You Need》：把循环结构整个扔掉，只用注意力机制
    - 【结论】Transformer 是一种完全基于自注意力机制的序列建模架构，设计初衷是解决 RNN 搞不定的长距离依赖和并行计算问题；DeepSeek、Qwen、豆包骨子里全是它的变体
  - 1.2 注意力机制：学会给信息"分轻重"
    - 【结论】Transformer 本质：基于自注意力机制的深度学习模型，为解决 RNN 无法处理长序列依赖问题而设计
    - 注意力机制：通过计算样本与样本之间相关性判断每个样本在序列中的重要程度并赋予权重；跨序列算相关性是经典注意力（Attention），序列内部算相关性是自注意力（self-attention）
    - 为什么判断重要性：一个序列里不同样本对理解整体的贡献不平等（外卖评价"慢了半小时"无关紧要，"软烂入味""非常好吃"定调）
    - 重要性如何定义：用样本之间的相关性来衡量；例句"老板在会议上宣布了重大的公司重组计划……"——"重组"与"公司""计划""会议""宣布""未来"都高度相关，对所有提问的答案都是"重组"
    - 【结论】与其他样本高度相关的样本，大概率会对序列整体的理解有重大影响；样本与样本之间的相关性可以用来衡量一个样本对于序列整体的重要性
  - 1.3 样本的相关性怎么算：点积、矩阵与 Q/K/V
    - 点积：同向（夹角 0°）→ 最大正数、完全正相关；垂直（90°）→ 0、互不相关；反向（180°）→ 最大负数、完全负相关
    - 三维向量点积：$\mathbf{A} \cdot \mathbf{B}^T = \begin{pmatrix} a_1, a_2, a_3 \end{pmatrix} \cdot \begin{pmatrix} b_1 \\ b_2 \\ b_3 \end{pmatrix} = a_1 b_1 + a_2 b_2 + a_3 b_3$；形状 (1,3) × (3,1) → (1,1) 塌缩成标量
    - 相关性的计算是有方向的："我给我家猫开了个罐头"——站在"我"视角 开罐头、猫 都重要；站在"猫"视角 "我"贡献寥寥；A、B 两个样本要算 AA、AB、BA、BB 四组；发起询问方是 Query，应答方是 Key
    - 推广到整个序列 = 一次矩阵乘法：特征矩阵 X 和它自己的转置相乘，得所有样本两两相关性矩阵
    - 工程上先给 X 乘三块可学习参数矩阵 $W^Q$、$W^K$、$W^V$ 投影成 Q、K、V：Q 每个位置"想问什么"；K 每个位置"能回答什么"；V 每个位置"实际携带的内容"；W 矩阵在训练中被梯度下降打磨
    - 【结论】自注意力核心三板斧：相关性分数在 Q 和 K 之间算，算出的权重再加权混合 V
  - 1.4 整体架构一览
    - 左边一摞 Encoder（负责"读懂"输入），右边一摞 Decoder（负责"生成"输出），中间靠交叉注意力搭桥
    - 【结论】Transformer 核心思路三句话：用注意力替代循环（直接计算任意两个位置关联，长距离依赖一步到位）；用位置编码补顺序（注意力本身"无序"，打乱输入顺序相关性不变，必须额外注入位置信息）；全并行计算（所有位置同时处理，吃满 GPU 矩阵乘法能力）
- 第二章 Embedding 与位置编码：给词向量打上位置标记
  - 2.1 文本向量化
    - Embedding 层位于 Encoder 和 Decoder 最前端，两步：查索引（每个 token 在词表里有唯一整数索引）；取向量（拿索引去 lookup table 取对应向量行）
    - 查找表是 (vocab_size, d_model) 参数矩阵：词表 10000 个词、每词 512 维 → 10000 × 512 大表；初始随机，训练后沉淀语义
    - 【代码】nn.Embedding(num_embeddings=10, embedding_dim=8)：emb.weight.shape = [10, 8]；查单 token → [1, 8]；batch 两句话每句 3 token → (2, 3, 8) 即 (batch, seq_len, d_model)；0 预留给 padding
    - 【代码】class Embeddings(nn.Module)(vocab_size, d_model)：self.lut = nn.Embedding(vocab_size, d_model)；forward 返回 self.lut(x) * math.sqrt(self.d_model)（原版论文写法）
  - 2.2 为什么要乘 √d_model
    - Transformer 采用 Xavier 初始化，Embedding 每个维度取值大致服从 $N(0, \frac{1}{d_{model}})$——d_model 越大方差越小，向量缩在 0 附近；位置编码值域 [-1, 1] 标准尺度；两边量纲差一大截，直接相加词向量信息会被位置编码"淹掉"
    - 乘上 $\sqrt{d_{model}}$ 后词向量分布拉回 $N(0, 1)$ 附近，和位置编码同一量级
    - 正态分布经验法则：约 68% 落在 ±1σ 内，95% 落在 ±2σ 内，99.7% 落在 ±3σ 内
  - 2.3 自注意力的"脸盲症"：它分不清语序
    - 实验：两组 Q、K、V，第二组是第一组前两行对调；simple_attention（QK^T → softmax → 加权 V）输出 out2 就是 out1 的行跟着对调，注意力分数本身毫无变化
    - 【结论】交换词的顺序，自注意力的计算结果只是跟着平移，数值本身不变；但自然语言里语序就是语义——"狗咬我"和"我咬狗"完全是两个故事
    - 位置信息两类：绝对位置（第 1 个、第 2 个 token……每个位置唯一编号）；相对位置（a₂ 在 a₁ 后面一位，a₄ 在 a₂ 后面两位，词与词间距）
  - 2.4 正余弦位置编码：给每个位置造一枚"多刻度指纹"
    - 作用：给不同位置的 token 向量"打上位置标记"，让模型知道谁在前谁在后
    - 正余弦位置编码公式（课件为图片）：pos 是 token 在句子里的位置索引（0 到 max_len-1），i 是维度对编号，2i 和 2i+1 分别对应偶数维和奇数维；给每个位置生成一个独一无二的 d_model 维向量，加到词向量上
    - 代码注释里的数值：max_len=128 则索引 0,1,...,127；d_model=512 时 i 从 0 取到 255，2i 取 0,2,4...510，2i+1 取 1,3,5...511
    - 【代码】class PositionalEncoding(nn.Module)(d_model, max_len=5000, dropout=0.1)：pe = torch.zeros(max_len, d_model)；pos = torch.arange(0, max_len).unsqueeze(1)；div_term = torch.pow(10000, torch.arange(0, d_model, 2).float() / d_model)；pe[:, 0::2] = torch.sin(pos / div_term)（偶数位置）；pe[:, 1::2] = torch.cos(pos / div_term)（奇数位置）；pe.unsqueeze(0) 升维；self.register_buffer("pe", pe)；forward：x = x + self.pe[:, :x.size(1)]，return self.dropout(x)
    - 【代码】register_buffer 定位：nn.Parameter 会被优化器更新的可训练参数；buffer 不训练但需持久化的张量（位置编码、BatchNorm 的 running_mean），出现在 state_dict 里随模型保存/加载/迁移设备
    - 【结论】设计优点三点：每个位置的编码全局唯一（不同位置在所有维度上不会撞车）；相对位置可推（数学上 $PE_{pos+k}$ 能表示成 $PE_{pos}$ 的线性变换）；天然外推（函数对任意 pos 都有定义，训练没见过更长序列也能现算）
    - 【代码】可视化：PositionalEncoding(d_model=512, max_len=100)，pe = pos_encoder.pe.squeeze(0) → (100, 512)，plt.imshow(pe.numpy(), cmap='viridis', aspect='auto')
  - 2.5 位置编码设计的优点
    - 1. 捕捉相对位置信息：sin/cos 周期性，pos 与 pos+k 的编码差异可通过三角函数和角公式表示（公式课件为图片），模型可通过位置编码的线性组合捕捉相对位置；许多任务（机器翻译、文本生成）中相对位置比绝对位置更重要
    - 2. 多频率编码：公式分母引入不同频率，随维度索引 i 增加频率逐渐降低；低维度（小 i）高频信号捕捉短距离相对位置，高维度（大 i）低频信号捕捉长距离相对位置；同时捕捉局部和全局位置信息
    - 3. 唯一性和连续性：每个位置 pos 编码唯一；相邻位置编码值变化平滑，有助于泛化到未见过的序列长度
    - 4. 无参数设计：固定公式确定性生成，不需要可学习参数，计算高效；可处理比训练时更长的序列
    - 5. 与输入嵌入的兼容性：位置编码与输入嵌入直接相加而不是拼接；sin/cos 取值范围 [−1, 1] 与嵌入值域兼容，不破坏分布；线性性质可通过矩阵运算高效结合
    - 【结论】Transformer 采用正余弦的绝对位置编码，保证不同位置在所有维度上不会被编码到完全一样的值；对每个词的每个特征值给予位置编码；词嵌入和位置编码相加后输入模型第一层
  - 2.6 灵魂拷问：直接相加，信息不会互相覆盖吗
    - 一维直觉：5 加 3 等于 8，盯着 8 猜不出是 5+3 还是 4+4——一维世界里相加是信息的坟场
    - 512 维空间性质：任意两个独立生成的向量，夹角几乎必然接近 90°（正交）；词向量指向"语义子空间"，位置编码指向"位置子空间"，各走各的"频道"，相加只是在垂直方向延伸
    - 类比：词向量是色彩丰富的照片，位置编码是印着坐标网格的透明胶片——这不是混合，是透明叠加
    - 叠加向量 $(x + p)$ 进入注意力层，$(x+p)W^Q$ 与 $(x+p)W^K$ 点积自然展开四项：$\underbrace{xW^Q (xW^K)^T}_{\text{语义×语义}} + \underbrace{xW^Q (pW^K)^T}_{\text{语义×位置}} + \underbrace{pW^Q (xW^K)^T}_{\text{位置×语义}} + \underbrace{pW^Q (pW^K)^T}_{\text{位置×位置}}$
    - 矩阵乘法像自动分拣机，把揉在一起的信息拆成独立信息流：纯词义关系、词与位置的上下文关系、纯相对距离关系；模型训练中学会各取所需
- 第三章 多头注意力与掩码：并行看清句子全局
  - 3.1 为什么一个头不够用
    - 例句"这家火锅店的毛肚确实新鲜，就是排队要两个小时"：理解"毛肚"要关注"火锅店""新鲜"；理解"排队"要关注"两个小时"；主谓、修饰、转折多种关系交织
    - 单个注意力头只有一套 Q/K/V 投影，一次只能在一个"语义子空间"算相关性，权重是所有关系揉在一起的平均（一把尺子同时量长度和重量）
    - CV 参考答案：CNN 每层几十个卷积核分别提边缘、纹理、色块，拼成多通道特征图；多头注意力同一哲学
    - 把 d_model 维向量切成 h 份（512 维切 8 头，每头 64 维），每个头拥有独立的 $W^Q_i, W^K_i, W^V_i$，各自在子空间算注意力：头 1 盯"指代关系"（"它"指谁）；头 2 盯"时态/程度"（"确实""有点""非常"）；头 3 盯"转折关系"（"就是""但是"后面才是重点）
    - 最后把 h 个头输出拼起来，再过一次线性映射融合
    - 【结论】多头注意力相比单个注意力模块，只增加了一个线性映射的计算量，却可以提取到更丰富的信息；每个位置的表示都可以被任意远的词影响——Transformer 能捕捉长距离依赖的关键
  - 3.2 Padding Mask：别让填充位带偏计算
    - GPU 批处理要求一个 batch 里序列等长，用特殊 pad token（索引通常设为 0）把短句补齐；pad 也会过 Embedding 和位置编码变成"看起来正常"的向量，不处理会分走注意力权重
    - 【结论】解决：在 softmax 之前，把 pad 位置的分数填成 -1e9；softmax 之后这些位置权重约等于 0，在注意力层面"隐身"
    - 【代码】masked_fill：inputs = tensor([[1,2,3],[4,5,0]])；mask = (inputs == 0).unsqueeze(1)；scores.masked_fill(mask, -1e9)
    - 【代码】def get_padding_mask(x, padding_idx=0): return (x == padding_idx).unsqueeze(1)——输入 (batch, seq_len)，输出 (batch, 1, seq_len)，第 1 维留给注意力分数的行做广播；mask.shape = torch.Size([2, 1, 3])
  - 3.3 缩放点积注意力：完整计算链路（单个头流程图课件为图片）
    - 【代码】def attention(q, k, v, mask=None, dropout=None)：q,k,v 形状 (batch, n_head, seq_len, d_k)；d_k = k.size(-1)（每个头的维度，不是总维度 d_model）；第一步 scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)，形状 (batch, n_head, seq_len, seq_len)，第 (i, j) 元素 = 第 i 个位置"问"第 j 个位置的匹配程度；第二步 除以 sqrt(d_k) 缩放防止大维度下 softmax 饱和；第三步（可选）scores.masked_fill(mask, -1e9)，softmax(-1e9) ≈ 0 等于"蒙住眼睛"；第四步 p_attn = torch.softmax(scores, dim=-1) 每行权重和为 1；dropout；第五步 torch.matmul(p_attn, v) 输出 (batch, n_head, seq_len, d_k)
    - 冒烟测试：attention(pos_out, pos_out, pos_out)，q=k=v（自注意力就是"自己问自己"），输出与输入形状一致
- 第四章 残差、归一化与前馈网络：稳定训练的三大护法
  - 注意力和位置编码解决"算得准"，本章三个组件解决"训得动"；Transformer 动辄几十层，没有它们梯度早就消失
  - 4.1 残差连接：深层网络的生命线
    - 公式：$\text{输出} = \text{LayerNorm}\big(x + \text{Sublayer}(x)\big)$；每个子层（注意力或 FFN）的输入被原封不动加回到输出上；代码 return self.norm(res + output)
    - 两层理由：梯度层面（反向传播时梯度沿 +x 这条"高速公路"跳过子层直接回传，不被几十层矩阵乘法连乘稀释）；兜底层面（子层什么都没学到输出接近 0 时 x + 0 = x，信息至少不比进来时差；每层只需学"增量改进"）
    - 【结论】硬性前提：子层的输入输出维度必须完全一致——整个 Transformer 所有模块死守 d_model 维度，也是位置编码选"相加"而非"拼接"的深层原因
  - 4.2 LayerNorm：把每个向量拉回稳定分布
    - 对单个向量两步：标准化（减均值、除标准差，拉成均值 0 方差 1）；缩放平移（可学习参数 γ 缩放、β 平移微调）
    - $\text{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$
    - 为什么需要：层层堆叠时各层输出数值范围飘忽不定，下一层参数疲于应付分布抖动；LayerNorm 先统一尺度，让每一层拿到的输入分布稳定可控
    - 【结论】LayerNorm vs BatchNorm（本质区别是沿哪个方向算统计量；行是样本列是特征）：统计方向 横着算一个样本自己的所有特征 vs 竖着算一批样本在同一特征上的取值；依赖 batch 不依赖、单样本也能算 vs 强依赖、batch 小统计量剧烈抖动；对变长序列 天然适配各算各的 vs 很尴尬、同一列凑的是长短不一的句子；典型场景 NLP / Transformer vs 图像 CNN
    - 【结论】NLP 句子长短不一、batch 未必大，BatchNorm 两个前提全不成立——Transformer 选 LayerNorm 不是偏好问题，是被数据结构逼出来的必然
  - 4.3 多头注意力+残差连接+layernorm 的完整实现
    - 【代码】class MultiHeadedAttention(nn.Module)(d_model, n_head, dropout=0.1)：assert d_model % n_head == 0；d_token = d_model // n_head（例 d_model=512, n_head=8 → 每头 64 维）；W_Q/W_K/W_V = nn.Linear(d_model, d_model, bias=False)（不为每个头单独建小矩阵，用一个大矩阵投影后再"切分"，数学上等价于 h 个小矩阵但效率高）；self.linear = nn.Linear(d_model, d_model, bias=False)（跨头融合）；self.norm = nn.LayerNorm(d_model)
    - forward(q, k, v, mask=None)：res = q（残差用）；分头 .view(batch, seq_len, n_head, d_token).transpose(1, 2) → (batch, n_head, seq_len, d_token)；mask.unsqueeze(1)（(batch, 1, seq_len) → (batch, 1, 1, seq_len)，同一掩码作用到所有头）；context = attention(q, k, v, mask, self.dropout)；拼头 context.transpose(1, 2).reshape(batch, -1, n_head * d_token)；output = self.linear(concat)；return self.norm(res + output)
    - 测试：MultiHeadedAttention(d_model=8, n_head=2)，输入什么形状输出还是什么形状
  - 4.3 FFN：先摊开加工，再收拢输出
    - 前馈神经网络 FFN：两个线性层夹一个激活函数；$\text{FFN}(x) = W_2 \cdot \text{ReLU}(W_1 x + b_1) + b_2$
    - 形状特征：两头窄、中间宽；原论文 512 维进来 → 撑到 2048 维 → 非线性 → 压回 512；流程 输入 x (512) → W1 升维到 2048 → 激活 ReLU / GELU / SwiGLU → W2 降维回 512 → 输出 (512)
    - 为什么先升维：注意力输出的 512 维里信息"挤"在一起（词义、搬来的上下文、搭配关系全纠缠），窄空间做非线性难施展；升到 2048 维把信息摊开，不同特征各占方向，激活函数才能对每部分单独取舍
    - 为什么又降回去：接口对齐（残差要求 x + FFN(x) 形状一致，下一层等着收 512 维）；第二个线性层把宽空间加工筛选过的结果重新浓缩打包回 512 维
    - 【结论】注意力是横向通信（加权求和，把别的位置信息搬到当前位置，回答"谁跟谁有关"）；FFN 是纵向加工（对每个位置独立做非线性深加工，所有位置共享同一套参数、位置间不交流，回答"这些信息该怎么提炼表达"）
    - 注意力对单点信息加工很弱（加权求和本质是线性操作，学不了"A 高且 B 高就激活某模式"的非线性规则）；FFN 里存储了模型学到的大量"事实知识"，像可查询的记忆库；整个模型约 2/3 的参数在 FFN 里（d_model=4096 时注意力约 67M 参数，FFN 约 134M）
    - 4 倍扩张比是大量实验后的经验折中；用 SwiGLU 的模型（LLaMA、Qwen）把比例调成约 8/3 倍
  - 4.4 激活函数的现代选择
    - 【结论】ReLU：max(0, x)，负值直接清零，简单高效但有"死神经元"问题——原版 Transformer；GELU：软化版 ReLU，负值不完全清零，梯度更平滑——BERT、GPT-2；SwiGLU：多一组权重做门控 (W₁x ⊙ σ(W₂x))·W₃，效果最好、参数多 1/3——DeepSeek、Qwen、LLaMA
    - 理解原理阶段用 ReLU 完全没问题，"升维 → 非线性 → 降维"主干思想三者一致
  - 4.5 FFN 代码实现
    - 【代码】class FeedForwardNet(nn.Module)(d_model, d_ff, dropout=0.1)：self.w1 = nn.Linear(d_model, d_ff)（升维，原论文 d_ff = 4 * d_model）；self.w2 = nn.Linear(d_ff, d_model)（降维，必须压回去才能接残差）；nn.ReLU()（现代可换 nn.GELU()）；nn.LayerNorm(d_model)；forward：res = x；x = relu(w1(x))；x = dropout(w2(x))；return norm(x + res)；"position-wise"：每个位置向量独立过同一个 FFN
    - 测试 FeedForwardNet(d_model=8, d_ff=32)，形状不变——Transformer 的维度守恒铁律
- 第五章 编码器-解码器协作：掩码自回归与交叉注意力
  - Encoder 每层两个组件（自注意力 + FFN），Decoder 每层三个组件（掩码自注意力 + 交叉注意力 + FFN）
  - 5.1 Encoder：把输入读成语义表示
    - 任务：理解输入序列，转成富含语义的向量表示（下游叫 memory 或 context）；单层 Encoder 两个子层，堆 N 层（原论文 N=6）
    - 【代码】class EncoderLayer(nn.Module)(d_model, n_head, d_ff, dropout)：self.mha = MultiHeadedAttention；self.ffn = FeedForwardNet；forward：output = self.mha(x, x, x, mask)（q、k、v 全是同一个 x，自己问自己）→ self.ffn(output)
    - 【代码】class Encoder(nn.Module)(vocab_size, d_model, n_head, d_ff, N=6, dropout=0.1)：Embeddings → PositionalEncoding → nn.ModuleList([EncoderLayer(...) for _ in range(N)])（用普通 list PyTorch 注册不上参数，模型会漏学）；forward：emb → pos → 逐层 layer(x, mask)
    - 冒烟测试：src_inputs = tensor([[1,2,3],[4,5,0]])，get_padding_mask(src_inputs, 0)，Encoder(vocab_size=10, d_model=8, n_head=2, d_ff=32) → memory.shape (2, 3, 8)
    - 【结论】Encoder 为什么不需要掩码遮住未来：职责是"理解"，理解本来就需要看到完整输入——译者当然可以把整句原文读完
  - 5.2 自回归与三角掩码：生成时禁止"剧透"
    - Decoder 职责是生成，生成本质是自回归（Autoregressive）：当前时刻输出依赖之前已生成内容；词 1 → 预测词 2；词 1、2 → 预测词 3；词 1、2、3 → 预测词 4
    - 问题：训练时有完整标准答案可整句并行计算，但直接喂会让模型生成第 3 个词时"偷看"第 4、5 个词，等于考试作弊
    - 解决：三角掩码（look-ahead mask / causal mask）——上三角矩阵把"当前位置之后"全部屏蔽，第 i 个位置只能看到第 1 到第 i 个位置
    - 【代码】torch.tril(torch.ones((3, 3))) 保留下三角（含对角线）→ [[1,0,0],[1,1,0],[1,1,1]]；def get_subsequent_mask(size): return 1 - torch.tril(torch.ones((1, size, size))).byte()（需要屏蔽的"未来位置"为 True，输出 (1, size, size)）
    - 【代码】Decoder 最终掩码 = padding mask 和三角掩码叠加（按位或）：pad_mask (2,1,3) | sub_mask (1,3,3) → tgt_mask = (sub_mask | pad_mask) != 0，广播后 (2,3,3)，True = 屏蔽
    - 【结论】Teacher Forcing：训练时"把答案右移一位喂进去、用三角掩码防偷看"，每个位置在"已知前文是标准答案"条件下练习预测下一个词，并行高效；和 DeepSeek 聊天时逐字蹦出回答，推理阶段跑的是同一个自回归逻辑，只是没有答案可看，全靠自己刚生成的前文
  - 5.3 Decoder 层：三件套流水线
    - Decoder 既要"理解自己已经写了什么"，又要"回看原文"，最后还要"加工生成"；三个子层固定顺序
    - 【代码】class DecoderLayer(nn.Module)：self.self_mha = MultiHeadedAttention（自注意力，带三角掩码防偷看未来）；self.cross_mha = MultiHeadedAttention（交叉注意力：q 来自 Decoder，k/v 来自 Encoder 输出 memory）；self.ffn；forward(x, mask, memory, src_mask)：x = self_mha(x, x, x, mask) → x = cross_mha(x, memory, memory, src_mask)（src_mask 是源序列 padding mask，不用三角——原文随便看）→ ffn(x)
    - 【代码】class Decoder(nn.Module)(vocab_size, d_model, n_head, d_ff, N=6, dropout=0.1)：Embeddings → PositionalEncoding → nn.ModuleList of DecoderLayer；forward(x, mask, memory, src_mask)
  - 5.4 Cross-Attention：到底是谁在"交叉"谁
    - 算法上和自注意力没有任何区别（Q·K 打分、softmax、加权 V），唯一差别是来源
    - 【结论】Self-Attention vs Cross-Attention：Q 来自 当前序列自己 vs Decoder 当前位置（"我现在需要什么"）；K 来自 当前序列自己 vs Encoder 输出（原文每个位置的索引）；V 来自 当前序列自己 vs Encoder 输出（原文每个位置的内容）；需要三角掩码 Decoder 侧需要 vs 不需要（原文完整摆在那儿随便看）
    - 【结论】一句大白话：问题是解码器自己的，资料库是编码器给的
    - 翻译例：源句"我 喜欢 机器 学习"经 Encoder 变成带上下文向量；Decoder 生成下一个英文词时拿自己的 q 和原文每个位置的 k 打分，softmax 后可能得 {我: 0.05, 喜欢: 0.10, 机器: 0.55, 学习: 0.30}，加权汇总 v——等于回原文"查"了一次；每生成一个词都重新查一次
    - 两个易误解点：① 查回来的向量 z 不带语种（纯数值向量表达"这一步原文想说什么"的语义；最终输出英文是输出层英文词表投影矩阵的功劳）② Cross-Attention 负责查资料，FFN 负责消化资料（Decoder FFN 加工"目标前文 + 原文信息"综合结果，Encoder FFN 加工"源句子的上下文表示"）
    - 三种注意力位置：自注意力、掩码自注意力、交叉注意力（架构图课件为图片）
  - 5.5 输出层：把向量变回词，以及温度这个"旋钮"
    - Decoder 顶层输出 (batch, seq_len, d_model) → Generator：线性层把 d_model 维投影到 vocab_size 维（每个词一个 logits），再过 softmax 变成词表上的概率分布 → 采样或取最大概率的词 → 查词表还原成文字
    - 【代码】class Generator(nn.Module)(d_model, vocab_size)：self.linear = nn.Linear(d_model, vocab_size)；forward：torch.softmax(self.linear(x), dim=-1)（本质是个分类网络）
    - 温度（Temperature）：$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$
      - T = 1 原样输出；T > 1 分布被"熨平"，低概率词分到更多机会，输出更发散（T→∞ 退化成均匀乱采）；T < 1 分布被"削尖"，高概率词优势放大，输出更保守（T→0 等价于贪心解码，每步只选概率最大的词）
      - 【结论】经验法则：翻译、代码、事实问答求准用低温（0.1~0.3）；文案、头脑风暴求活用高温（0.7~1.0）；DeepSeek 官方 API 文档建议代码生成 0.0、文学创作 1.5；温度不是"创意开关"，只是概率分布的调节旋钮
  - 5.6 封装完整模型
    - 【代码】class Transformer(nn.Module)(src_vocab_size, tgt_vocab_size, d_model, n_head, d_ff, N=6, dropout=0.1)：self.encoder = Encoder(src_vocab_size, ...)；self.decoder = Decoder(tgt_vocab_size, ...)（源语言和目标语言各有词表，Embedding 两套）；self.generator = Generator(d_model, tgt_vocab_size)；forward(src_x, src_mask, tgt_x, tgt_mask)：memory = encoder(src_x, src_mask) → output = decoder(tgt_x, tgt_mask, memory, src_mask) → generator(output)
    - 【代码】def make_model(src_vocab_size, tgt_vocab_size, d_model=512, n_head=8, d_ff=2048, N=6, dropout=0.1)：for p in model.parameters(): if p.dim() > 1: nn.init.xavier_uniform_(p)（只初始化二维以上权重矩阵，一维 bias/LayerNorm 参数跳过）
    - 完整跑一遍：make_model(src_vocab_size=6, tgt_vocab_size=8)，总参数量四千多万；src_inputs [[1,2,3],[4,5,0]]，tgt_inputs [[1,2,3,4],[4,5,0,0]]，tgt_mask = (get_subsequent_mask(4) | tgt_pad_mask) != 0；predict.shape (2, 4, 8)（2 句话 × 4 个位置 × 8 词表概率）；torch.argmax(predict, dim=-1)
    - 工程上把这些类规整进 model.py，训练代码另放
- 第六章 从零训练到工程落地：初始化、评估与官方模块速查
  - 6.1 Xavier 初始化：让梯度一开始就保持健康
    - 初始化太差（全零、全同值或方差离谱）梯度要么消失要么爆炸
    - 核心思想：让每一层输出的方差和输入的方差大致相等，信号在前向和反向传播中既不放大也不衰减
    - 均匀分布版本：权重从 $U\left(-\frac{\sqrt{6}}{\sqrt{n_{in}+n_{out}}}, +\frac{\sqrt{6}}{\sqrt{n_{in}+n_{out}}}\right)$ 采样，$n_{in}$、$n_{out}$ 是该层输入输出维度
    - 【代码】nn.init.xavier_uniform_(p) for p.dim() > 1（跳过 bias、LayerNorm 的 γ/β 一维参数，按 PyTorch 默认值走）
    - 呼应第二章：Xavier 初始化后 Embedding 每个维度服从 $N(0, 1/d_{model})$，所以才需要乘 $\sqrt{d_{model}}$ 拉回标准尺度
  - 6.2 数据预处理管线
    - 三个模块：data_processor.py（生成词表：扫描语料统计 token 频次，生成 token → 索引映射文件）；utils.py（词表解析与特殊词配置：加载词表，定义 `<pad>` 填充、`<bos>` 句首、`<eos>` 句尾索引，提供"句子 ↔ 索引序列"双向转换）；data_loader.py（加载平行语料，转索引、对齐长度、打 batch）
    - 【结论】最容易踩的坑是特殊 token 处理顺序：目标序列输入 Decoder 前在开头加 `<bos>`（"右移"的含义），计算损失用的标签在结尾加 `<eos>`——一个是"给模型的提示"，一个是"要模型预测的目标"，错位一个位置整个训练白费
  - 6.3 Label Smoothing：别让模型"过度自信"
    - one-hot 标签等于告诉模型"正确答案概率必须是 100%"，模型拼命把正确类别 logits 推到无穷大——训练集信心满满，测试集脆得像纸，过拟合
    - 标签平滑：正确类别从 1 降到 $1-\varepsilon$（比如 0.9），剩下的 $\varepsilon$ 均摊给词表里其他所有词；模型学会"高度倾向但留有余地"，泛化改善；对几万词的词表避免在无关词上浪费区分度；从 GPT 时代到 DeepSeek 一直是标配正则手段之一
  - 6.4 BLEU：给翻译质量打个分
    - BLEU：衡量模型输出与参考译文之间的 n-gram 重合度，分数越高越接近人工翻译；每轮算一次 BLEU，缓存分数最高的权重（early stopping 常规操作）
    - 【代码】pip install sacrebleu；sacrebleu.corpus_bleu(hyps, refs, tokenize='zh')（tokenize='zh' 中文分词模式；BLEU 满分 100；每个样本可给多个参考）；bleu.score
  - 6.5 PyTorch 官方模块速查：什么时候别自己造轮子
    - 【代码】nn.Transformer（完整 Encoder-Decoder，不含 Embedding 和输出层）；nn.TransformerEncoder / nn.TransformerDecoder（N 层堆叠容器）；nn.TransformerEncoderLayer（单个编码器层：自注意力 + FFN）；nn.TransformerDecoderLayer（单个解码器层：自注意力 + 交叉注意力 + FFN）；nn.MultiheadAttention（独立多头注意力）；nn.LayerNorm / nn.Embedding
    - nn.TransformerEncoderLayer 关键参数：d_model 嵌入维度（"维度守恒"主角）；nhead 头数（必须整除 d_model）；dim_feedforward FFN 隐藏层维度默认 2048；dropout 默认 0.1（业内习惯每个复杂结构后都加）；activation 默认 "relu" 可换 "gelu"；batch_first 务必设 True（输入 (batch, seq, feature)，否则默认 (seq, batch, feature)）；norm_first True = Pre-Norm（现代大模型同款），默认 False = Post-Norm
    - 【代码】基于官方 Encoder 层的 TextClassifier(vocab_size, d_model=512, nhead=8, num_layers=2, num_classes=2)：nn.Embedding(vocab_size, d_model)；PositionalEncoding(d_model)；nn.TransformerEncoderLayer(d_model=d_model, nhead=nhead, batch_first=True, norm_first=True)；nn.TransformerEncoder(encoder_layer, num_layers=num_layers)；nn.Linear(d_model, num_classes)；forward：embedding(src) * torch.sqrt(torch.tensor(512.0)) → pos_encoder → encoder(x, src_key_padding_mask=...)（padding 掩码直接传官方参数，不用自己 masked_fill）→ fc_out(x.mean(dim=1))（序列维平均池化压成固定长度）

- 第 2 章 Pipeline：三行代码背后的流水线
  - 2.1 Pipeline 到底是什么：不是一个模型，而是一条流水线——输入文本依次经过"预处理 → 模型推理 → 结果后处理"三站，直接给人类可读答案
  - 2.2 Pipeline 支持哪些任务
    - text-classification 文本分类（情感分析、垃圾短信）；token-classification token 级分类（NER、词性标注）；question-answering 抽取式问答；text-generation 文本生成（大模型对话、续写）；summarization 摘要；translation 翻译；fill-mask 完形填空（掩码预测、数据增强）；feature-extraction 提取文本向量（语义检索、RAG 嵌入）；image-classification 图像分类；automatic-speech-recognition 语音识别
    - 【代码】from transformers.pipelines import SUPPORTED_TASKS 查看全部任务类型
  - 2.3 三种创建方式
    - 【代码】方式一 pipeline("text-classification") 只给任务类型（加载官方默认模型，通常英文）；方式二 pipeline("text-classification", model="uer/roberta-base-finetuned-dianping-chinese")（日常最常用，输出 [{'label': 'positive (stars 5)', 'score': 0.99xx}]）；方式三 先 AutoModelForSequenceClassification.from_pretrained + AutoTokenizer.from_pretrained 再 pipeline(task, model=model, tokenizer=tokenizer)（最灵活）
  - 2.4 用 GPU 加速推理
    - 【代码】device = 0 if torch.cuda.is_available() else -1；pipeline(..., device=device)（GPU 序号 0 = 第一块卡，-1 = CPU）；pipe.model.device 查看 cuda:0 或 cpu
  - 2.5 把 Pipeline 扒光：手动实现一遍
    - 【代码】第一站预处理 inputs = tokenizer(text, return_tensors="pt")（返回 PyTorch 张量 input_ids、attention_mask 等）；第二站推理 with torch.no_grad(): outputs = model(**inputs)（**inputs 字典展开成关键字参数）；logits = outputs.logits（形如 [[-1.2, 2.8]] 未归一化）；第三站后处理 probs = torch.softmax(logits, dim=-1)、pred_id = torch.argmax(probs, dim=-1).item()、label = model.config.id2label[pred_id]（下标翻译回标签名，存在模型 config 里）
- 第 3 章 Tokenizer：把人话翻译成模型能懂的数字
  - 3.1 数据预处理四部曲：① 分词（中文按字、英文按子词 subword）② 查词表（每个 token 唯一 id，词表随模型不同）③ 映射（token 序列 → id 序列）④ 填充与截断（短的补齐、长的砍断，batch 内长度一致）
  - 3.2 基本操作
    - 【代码】AutoTokenizer.from_pretrained("hfl/chinese-macbert-base")（哈工大讯飞中文预训练模型）；tokenizer.tokenize(text) 中文按字切 ['今', '天', '点', '的', ...]；tokenizer.vocab_size = 21128（沿用 BERT 中文词表）；tokenizer.encode(text) 自动在首尾加 [CLS]、[SEP]；tokenizer.convert_ids_to_tokens(ids)；encode(text, add_special_tokens=False) 不要特殊 token；tokenizer.decode(ids, skip_special_tokens=True)
    - 【结论】经典坑：模型和分词器必须是"原配"——不同模型词表不同，同一个字在 A 模型是 1024 号在 B 模型可能是 2048 号，拿错分词器等于拿错钥匙开锁
  - 3.3 填充与截断
    - 【代码】tokenizer.encode(text, padding="max_length", max_length=15)（不足补 [PAD]，id 为 0）；tokenizer.encode(text, max_length=5, truncation=True)（最多保留 5 个 token 含特殊 token）
  - 3.4 batch 处理与"三件套"
    - 【代码】tokenizer(batch_texts, max_length=20, padding="max_length", truncation=True)
    - 【结论】BERT 系模型标准输入三件套：input_ids 每个 token 的词表 id（句子的"身份证号序列"）；token_type_ids 区分句子 A / 句子 B（A 全 0，B 全 1；问答任务区分"问题"和"原文"）；attention_mask 1 = 真实内容、0 = 填充位（告诉模型凑数的 PAD 别理）
- 第 4 章 Model：模型本体与"任务头"
  - 4.1 什么是 Model Head：同一个预训练底座（如 MacBERT）能干分类、问答、NER，差别在任务头——底座把文本编码成向量，任务头把向量映射成任务输出格式；类比底座是发动机、任务头是变速箱
  - 4.2 常见 Head 家族
    - 【结论】AutoModel 每个 token 的向量、无任务头（提取特征、二次开发）；AutoModelForSequenceClassification 整句一个类别（情感分析、文本分类）；AutoModelForTokenClassification 每个 token 一个类别（NER、词性标注）；AutoModelForQuestionAnswering 答案在原文中的起止位置（抽取式问答）；AutoModelForCausalLM 下一个 token 的概率（GPT 类生成、大模型对话）；AutoModelForSeq2SeqLM 编码器+解码器生成序列（翻译、摘要）
  - 4.3 加载、配置与调用
    - 【代码】backbone = AutoModel.from_pretrained(model_id)；config = AutoConfig.from_pretrained(model_id)，config.hidden_size = 768、config.num_hidden_layers = 12；clf_model = AutoModelForSequenceClassification.from_pretrained(model_id, num_labels=2)；outputs = clf_model(**inputs)，outputs.logits.shape = torch.Size([1, 2])（1 个样本，2 个类别分数）
  - 4.4 num_labels：新手必踩的坑
    - 预训练模型分类头默认按 2 分类配置；10 分类必须显式传 num_labels=10；标签数不匹配时 transformers 重建分类头（权重随机初始化，等微调来喂）；忘记指定的常见症状是莫名其妙的 device / shape 错误
  - 4.5 保存与加载
    - 【代码】clf_model.save_pretrained("./my_sentiment_model")、tokenizer.save_pretrained("./my_sentiment_model")（分词器是模型的"原配钥匙"，都要存）；AutoModelForSequenceClassification.from_pretrained("./my_sentiment_model")
  - 4.6 同一套 API，向上直通国产大模型
    - 【代码】AutoModelForCausalLM.from_pretrained(model_id, dtype="auto"（跟随权重精度，v5 新参数名，旧版 torch_dtype）, device_map="auto"（自动在 GPU/CPU 间分配层，需要 accelerate）)；model_id 如 "deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B" 或 "Qwen/Qwen3-0.6B"；区别只是任务头换成 ForCausalLM（生成式），以及显存账单变长
- 第 5 章 Datasets 与 Evaluate：数据与评估的工具链
  - 5.1 Datasets：加载数据的 N 种姿势
    - 【代码】姿势一 load_dataset("madao33/new-title-chinese")（在线 Hub，需联网配镜像）；姿势二 load_dataset("csv", data_files="./comments.csv", split="train")（本地 CSV，日常最常用）；姿势三 Dataset.from_pandas(df)；load_dataset("csv", data_dir="./all_data/", split="train") 加载整个文件夹
  - 5.2 查看、切片、划分
    - 【代码】ds[0]、ds[:3]（返回 {字段: [值列表]} 字典）、ds.column_names；ds.train_test_split(test_size=0.1, seed=42)（10% 做验证，seed 固定可复现）→ split["train"], split["test"]
  - 5.3 select / filter / map 三剑客
    - 【代码】ds.select([0, 5, 10]) 按下标挑样本；ds.filter(lambda x: x["label"] == 1) 按条件过滤；ds.map(preprocess, batched=True, remove_columns=ds.column_names)（batched=True 一次进一批效率远高于逐条；remove_columns 扔掉原始文本列只留数字列）
    - preprocess 内：out = tokenizer(batch["text"], max_length=128, truncation=True)；out["labels"] = batch["label"]（Trainer 约定俗成：标签字段必须叫 labels）
  - 5.4 处理结果存盘：【代码】tokenized.save_to_disk("./tokenized_data")；from datasets import load_from_disk；load_from_disk("./tokenized_data")（预处理只跑一次，下次秒加载）
  - 5.5 DataCollatorWithPadding：勤俭持家的动态填充
    - 为什么不在 map 里直接 padding 到 128：batch 里最长可能才 30 个 token，统一填到 128 浪费算力；DataCollatorWithPadding 在组 batch 那一刻按"本批最长"动态填充
    - 【代码】collator = DataCollatorWithPadding(tokenizer=tokenizer)；DataLoader(tokenized, batch_size=8, shuffle=True, collate_fn=collator)；batch["input_ids"].shape = [8, 本批最长长度]，每个 batch 可能不同
  - 5.6 Evaluate：阅卷老师上线
    - 【代码】evaluate.load('./evaluate-main/metrics/accuracy/accuracy.py')（需联网走镜像，或 git clone evaluate 仓库指向本地路径 https://github.com/huggingface/evaluate）；acc_metric.compute(references=[0,1,1,0], predictions=[0,1,0,0]) → {'accuracy': 0.75}；evaluate.combine([accuracy, f1, precision, recall 脚本路径]) 多指标打包一次算全
    - 指标定义（公式课件为图片）：Accuracy 准确率——预测正确的样本占总样本的比例（总体对了多少）；Precision 精确率——所有被预测为正类的样本中真正正类的比例，衡量"不误报"（预测为正的有多准）；Recall 召回率——所有真正正类样本中模型成功找出的比例，衡量"不漏报"（真正的正类找出了多少）；F1 Score——精确率和召回率的调和平均数，在两者间取得平衡
