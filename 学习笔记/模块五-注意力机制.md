## 学习中问过的问题(Claude 整理)

### Q / K / V 是什么

**Q:Key 为什么有两个数?标签不是一个值吗?文本怎么转成标签值?**
A:混淆了"类别标签"和 Key。Key 是一个向量(一行数,和词向量一样),与分类的类别号无关。文本→切词→查 ID→Embedding 得词向量→乘一张表→Key。以后统一叫 Query/Key/Value,不翻译。

**Q:为什么需要 softmax,直接拿点积分数当权重不行?**
A:三个理由:①总量要固定为 1,否则输出随句长和分数尺度乱飘(分数 [0,3,3] 直接当权重输出放大 6 倍);②点积可能为负,负权重无意义,e^x 全变正;③要"分蛋糕"不要"挑最高",挑最高不可求导,梯度传不回去。附带效果:e^x 放大差距,分数差 3 比例差 20 倍。

**Q:Q/K/V 到底是什么?(用 Java 讲)**
A:注意力 = 模糊版 HashMap。Key = map 里存的键(用来被比对),Value = 配对存的值(比对成功后真正拿走的内容),Query = 你拿来查的键。与普通 get 只差两处:不要求 q 和 k 完全相等而是算"有多像"(点积);不返回一个 v 而是把所有 v 按像的程度混合返回。打分只用 Q 和 K,混合只用 V。

**Q:这不是用户 query 向量化后去 LLM 词表比对吗?**
A:那是 RAG/向量检索(模型外面,一次,找资料)。注意力在模型里面:Q/K/V 全来自同一句话,句子里每个词都发 Query,比对对象是同句其他词的 Key,目的是给每个词造一个"看过上下文之后"的新向量(同一个"苹果"在"苹果股价"和"苹果好吃"里向量应不同,第六节的固定词向量+直接相加做不到)。两者共用的只有"点积=相似度"。

**Q:课件说注意力是"注意文本中最值得关注的部分",和"吸收上下文"矛盾?**
A:同一件事两个角度。softmax 出来的比例 `[0.024, 0.488, 0.488]` 就是"关注度分配";按这份分配搬 Value 就是"吸收"。第一节讲注意力长什么样,第二节讲怎么算出来,第三步讲算出来拿它干什么。

**Q:map 里的 (k, v) 从哪来?W_K/W_V 怎么训练?所有用户输入共用一张表?**
A:一句话建一个 map,一个词放一条 (k, v):`k = x·W_K`,`v = x·W_V`(一行数乘一张表,同第五节)。不直接拿 x 兼任是因为"被找"和"被拿"是两个活,两张表给同一个词两副面孔。W_Q/W_K/W_V 是注意力层全部可训练参数,训练方式与 Embedding/卷积核完全一样:随机初始化→前向→loss→backward→step;没有自己的目标,只被最终任务 loss 逼着长成"这样打分最准"。训练完冻住,所有输入共用同一套。

**Q:为什么说每一层都有一套 W_Q/W_K/W_V?**
A:注意力是一个"层",与 Conv2d/Linear 同级;一套三张表 = 一个注意力层的参数,叠几层就几套(同 LeNet5 两个卷积层各有自己的核),下一层拿上一层"看过全句"的输出再看一遍。本课件只有一层,记一套即可;多层是 Transformer 的事。

**Q:流水线是不是 切词→Embedding→Q/K/V?**
A:是。第六节八步旅程前四步一字不改,注意力替换的是第⑤步"词向量直接相加"(每词权重相等、互不看),换成"每词乘三张表得 q/k/v→打分→softmax→按比例混合 v",输出仍是每词一个向量但带了上下文;第⑥步 Linear 打分不变。注意力是塞在 Embedding 和分类头之间的一个层。

**Q:V 到底是什么?为什么每个词 q/k/v 三样都要算?**
A:V = 这个词"被别人查到之后交出去的内容"。k 是招牌(便于被匹配的特征),v 是货(混进对方新向量的语义内容);`it` 关注 `animal` 打分用 k_animal,真正搬走的是 v_animal,于是 it 变成"一个会累的动物"。简化理解 v≈词向量本身也八九不离十。自注意力里每个词既是查的人(需要 q)也是被查的人(需要 k、v),所以三样都要。

**Q:词向量"2 个位置"是谁定义的?**
A:位置**个数**是人定的超参数(embedding_dim,课件 128/256);每个位置**代表什么**没人定也没人知道,是训练磨出来的,人类读不懂。例子里的 [动物性, 地点性] 是教学假设。机制对位置含义毫不在意,只做点积/softmax/加权和。

**Q:完整流程复述(已纠正版)**
A:文本→分词→每词查 Embedding 得词向量→每个词向量分别乘 W_Q/W_K/W_V 得该词 q、k、v→对每个词:它的 q 与全句所有词的 k 点积得一排分数→**softmax 变比例(在混合之前!)**→用比例把全句所有词的 v **加权求和(不是点积)**→该词带上下文的新向量;每词各做一遍。三张表一次注意力恰好三张;"多个"来自叠层(每层一套)和多头(同层并行几套)。

**Q:注意力到底解决什么问题?就是算词与词相似度?**
A:相似度是手段不是目的。问题:Embedding 查出的词向量是死的,"苹果股价"和"苹果好吃"里的苹果向量一样,`it` 指谁全靠上下文。注意力让每个词按相关度从全句吸收信息,产出带上下文的新向量。对比:直接相加词间不交互;卷积只看相邻几个词;注意力任意两词一步直达。

**Q:新向量能对应上词表里的词吗?不是词的话 LLM 怎么找到词去运算?**
A:不需要对应。新向量 `[1.34, 0.53]` 不是任何词,是同一空间里的新点("红+蓝=紫,不在原颜料里但可直接画")。模型从头到尾只对数字运算:词只在**入口**(查 ID→Embedding,唯一需要词在词表里的时刻)和**出口**(`Linear(D, vocab_size)` 给词表每个词打分选最高)出现;中间所有层(注意力/Linear)只要求输入长度是 D,不检查"是不是某个词"(Java:`float[] f(float[] x)` 只查数组长度)。出口是"打分选最高"不是"查表找相等",所以永远选得出词表内的词。

### 代码与公式

**Q:`scores = q @ k.transpose(-2,-1) / sqrt(d_k)` 里面的计算过程?**
A:矩阵乘法唯一规则:结果第 i 行第 j 列 = 左边第 i **行** · 右边第 j **列**(Java 三层 for);形状 `[m,n]@[n,p]→[m,p]`,第五节"一行乘一张表"是 m=1 的特例。转置 = 行列互换。我们把 q、k 都"一个词一行"存,规则要一行配一列,所以把 k 转置让它第 j 行变第 j 列,于是 `(q@kᵀ)[i][j] = q_i·k_j`,一次矩阵乘法算完全部两两点积(手算例子 `[3,2]@[2,3]→[3,3]`,第 2 行就是 it 的 [2, 1, 1.25])。

**Q:转置一定是这个组合吗?之前流程里没有除以 sqrt(d_k)?**
A:转置只是配合"一个词一行"的记账习惯,`k@qᵀ` 得同一张表的转置、k 按列存就不用转,本质只是"每个 q 对每个 k 点积"。sqrt(d_k) 是我手算时为数字干净省掉的,正确流程:打分→**除以 √d_k**→softmax→加权和。它只把分数整体缩小让比例不极端,顺序不变(it 行 [0.54,0.20,0.26]→[0.48,0.24,0.28]);d_k=512 不除会变 [1,0,0] 梯度归零。数值稳定性补丁,真实代码必须有。

**Q:注意力和自注意力到底什么区别?**
A:计算完全一样(三步走、三张表、softmax),区别只在 q 和 k/v 是否来自同一份数据。注意力机制 = 那套计算方法本身,不规定 q 和 map 从哪来;自注意力 = 用它时 q 和 map 来自同一句话(句子自己查自己)。翻译:中文句子建 map,英文那边的状态当 q 来查 → 跨句注意力;`it` 查 `animal street it` 自己建的 map → 自注意力。代码:`SelfAttention.forward(x)` 只收一个 x;`MultHeadedAttention.forward(q,k,v)` 三个分开传是为通用留口子,传 `(x,x,x)` 就退化成自注意力。

**Q:p_attn 为什么没有 D?q=[2,3] 点积所有 k 不是得到 [X,Y] 吗?**
A:一个点积的结果是**一个数**不是向量:对应位置相乘后"全部加起来",D 个数收成 1 个。买手机:性能权重 2、续航权重 1,手机 A 性能 3 续航 0 → 3×2+0×1 = 6 分,一个总分;三款手机三个分 `[6,3,3]`,长度=候选数不是指标数。所以一句话 10 个词 → 每个 q 得 10 个分 → 10×10 关注度表,不管 D 是 2 还是 64。

**Q:`SelfAttention` 多出来的三行 `q = self.q_linear(x)` 在干什么?`__init__` 在做什么?**
A:`nn.Linear(D,D)` 就是一张 D×D 的表;`self.q_linear(x)` = x 的每一行(每个词)各自乘同一张表,得每个词的 q。同一个 x 乘三张不同的表得三个不同版本(demo:表 Q 什么都不改→q=x;表 K 两数对调;表 V 翻倍)。`__init__` 在 `SelfAttention(4)` 那一刻跑一次:造三张表填随机数并登记为可训练参数(Java 构造方法);`forward` 每来一句话跑一次,只用表不造表;表里的数在 `opt.step()` 时改。**真实模型也是 __init__ 时造表,训练不"生成"表只"修改"表**;demo 手动覆盖成 0/1/2 只为可手算。

### 多头注意力(第五节)

**Q:为什么同一套表能算出不同特性?分开算是为了更精确?**
A:不是精确度,是表达能力。瓶颈在点积:单头把 8 个数压成 1 个分,每个词只有一张关注度表,只能表达一种关系(买手机只有一个总分只能排一个榜,回答不了"性能谁强/续航谁强")。切成 n 段各自点积 → n 个分、n 张表 → `红包` 可同时在头 1 关注 `发`、头 2 关注 `两百块`。且顺序是**先有切分结构,训练才把不同特性磨进不同段**:不切分时 loss 没理由让前 4 列后 4 列分工;切开后梯度分别推两组列,自然分化。参数量不变(demo 实测 n_head=1/2/4 都是 256)。

**Q:各头结果合在一起怎么区分不同关注点?**
A:不需要区分,拼接是"并排放"不是相加:头 1 永远占前 4 格、头 2 占后 4 格,位置固定;下一层的表训练时学会按位置取用(同词向量各位置含义由训练磨出)。最后的融合表 `self.linear` 让各头信息可按需交叉,怎么搭配由 loss 决定。

**Q:`view` 是干嘛的?`nn.Dropout` 为什么放 `__init__`?`q.size(0)` 那几行取什么?**
A:`view` 不动数据不拷贝,只改"分组方式":8 个数 `.view(2,4)` 看成 2 组×4(Java 把 int[8] 当 int[2][4] 用),这就是零成本"切头";总数必须相等。`nn.Dropout` 是层,惯例层在 `__init__` 造、`forward` 用;它要保存 p 和"训练/测试"状态,`model.eval()` 靠登记过才能关掉它;作用是随机清零 10% 关注度格子防"合谋"。`size(0)`=句数、`size(1)`=词数,运行时从输入读,给后面 `view` 用;q/k/v 词数分开读是为跨句注意力(翻译时英文 5 词、中文 8 词)留口子。

**Q:`mha(q,k,v)` 没显式调 forward,参数怎么进去的?**
A:Python 对象加括号 = 调 `__call__`,`nn.Module` 的 `__call__` 转发给 `forward`。`MultHeadedAttention(8,2)` 是类名加括号→`__init__` 造表;`mha(q,k,v)` 是对象加括号→`forward` 算。`model(x)`、`net(x)`、`self.q_linear(x)` 全是同一机制(Java 最接近 `Function.apply`,Python 省掉了 `.apply`)。`q=k=v=torch.randn(...)` 链式赋值三个名字指同一对象 = 自注意力调法。

**Q:注意力 / 自注意力 / 多头 分别用在什么场景?**
A:不是三个并列物,是一个机制 + 两个独立维度的选择。维度一"q 和 k/v 从哪来":两份数据→跨注意力(翻译:英文生成状态查中文原句;看图说话:文字查图片特征;Transformer 解码器中间层);同一份→自注意力(句子编码消歧/指代/长距离;特征图每个位置看全图;GPT/BERT 主体层)。维度二"切几头":正式模型默认多头(单头只能表达一种关系),单头只在教学/极小模型;头数取 d_model 能整除的,常见 8。课件第六节 = 多头 + 自注意力(`self.attention(x,x,x)`,`n_head=4`)。

**Q:d_model=512、8 头、30 个词:每头几个数?几张 30×30 表?**
A:每头 512/8=64;关注度表张数 = 头数 = 8 张(不是 q/k/v 三张——30×30 表是 q·k 打分出来的,v 不参与打分,q/k/v 本身各是 [30,512])。
