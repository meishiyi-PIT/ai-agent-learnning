2026-09-29 学模块六《2.低精度训练与量化》第 2–4 章加载代码（quant_demo.py 在 AutoDL 跑 bf16 / int8 / nf4）时，用户连续四轮说"没理解 / 很懵 / 比较粗糙"，最后一轮点破："你不要只对代码讲，这样会很懵，你直接对进去整个训练和推理的整体的流程中"。当天摸出来的几条习惯：

1. **困惑的根源多半是"不知道这一步在整条线上的位置"，不是那一步本身。** 用户问"BF16 转 INT8 在哪里发生"，我先后给了：结果解读 → 逐行讲代码 → ASCII 箭头流程图 → 跟着一个数走 8 步，全部失败；改成"模型的一生 6 站（预训练 → 对齐 → 微调 → 合并 → 部署加载 → 每个请求），每站只看权重什么格式、有没有被改"才通。之后用户主动要求"同时指出代码中会怎么做"——**顺序是：全流程位置 → 概念（类比）→ 才落到 file:line**，不能反过来。
2. **ASCII 箭头图（│ ▼ →）用户读不进去**："你这样的形式，我没办法理解"。改用**编号站点/步骤 + 每步两三行白话**；细节用**跟着一个具体的数**（0.83 那一行）从磁盘走到输出。文字里的层级用加粗小标题，不用画图。
3. **基础缺口会以"为什么要 X"的形式突然冒出来**（"为什么要搬到显存"）。不要当追问跳过，用一个生活类比（硬盘=仓库、显存=工作台）一屏答完，并顺手接回主线（工作台小所以要压缩 → 量化为什么在 from_pretrained）。
4. **用户会用"所以你的意思是……是吗？"复述来核对理解。** 这是他的消化方式：答"对/不对 + 一句补充"，补充只加一条最要紧的例外（如 QLoRA 多一行 prepare），不借机展开。
5. **实战环节的闭环**：用户在 AutoDL 跑 → 贴输出 → 我解读 → 追问 → Q&A 进《大模型微调.md》（格式见 [[module6-notes-doc]]）；小算例我本机跑完贴结果（s5/s6 纯 Python），用户只跑 AutoDL 命令。每次追问的答案同步写进对应站点脚本 docstring。
6. **后台多代理核对不能挡住教学。** 我开了两个 Workflow 去核对 bitsandbytes 源码，用户等了 18 分钟来问"还需要继续等嘛"；一个核对代理还触发了账号每周用量上限（WEEKLY_LIMIT_EXCEEDED）。规则：教学会话里**先用已核实的内容直接答**，源码级核对只在不阻塞回复时后台跑、结果回来再以"勘误"补进笔记；核对代理必须限制工具调用次数（GitHub 拉源码很慢），一次最多 2–3 个代理。
7. **用户按主题开新窗口**。新会话先读《大模型微调.md》末尾两节 + 学习计划，从"上次停在哪、下一条是什么"接上（本次停在课件 2 全部讲完，下一条 = 课件 5 第 2 块 Prefill / Decode）。

8. **每次回答先给"整体一句话 + 接上前文"，再给细节；推导先判断要不要懂。**（2026-09-29 课件 5 Roofline：我为解释 n=2048 时 I=1303 把权重/输入/输出三块字节逐项算了三遍，用户说"这个计算需要理解嘛，讲太细了，没和之前的内容联系起来，没先说明整体描述，很碎很细又看不懂"。）规则：开头第一句说"这块内容要回答什么问题、结论是什么"，第二句说"它和前面哪个知识点接上"；面试深度（[[interview-goal]]）下公式推导默认**不要求会算**，只给结论 + 一个代表数，并明说"这个算式不用会推"；用户追问"怎么算的"才展开，展开也只算一个 n，不算三遍。[[explain-demo-output]] 第 5 条的"跟一个数走"指一个数，不是逐项推导。

**Why:** 用户 Python/数学基础弱（[[user-python-level]]、[[user-math-level]]），对代码逐行讲时他没有"这行在整个训练/推理里是第几步"的框架，细节越多越懵；全流程地图给了框架后，同样的代码行一句话就懂。等待和密度一样是专注力的敌人。

**How to apply:** 讲任何"某机制在哪里发生"的问题，第一屏永远是全流程站点图（编号、不画箭头），标出该机制出现在哪一站；第二屏概念 + 类比；第三屏才 file:line。用户说"没理解"两次仍不通，立刻换表达形式而不是加细节。与 [[pacing-small-chunks]]（一屏一步、不用表格）、[[teaching-concepts-first]]（先概念后应用）、[[tutor-role]] 第 10 条（📍定位行）配合。
