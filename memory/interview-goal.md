2026-09-29 学模块六《4.大模型微调数据集完全指南》时，用户先说"我希望你能尽快帮我掌握这个内容 主要是面对面试"；
我随即把 1.4 改成"面试官会问 → 30 秒答 → 挂项目"的格式并提出每章末追加面试题库，用户纠正：
"不需要这样 不需要把面试官会问的问题整理出来 当前还是以学习为目的 学习的深度是面试的程度"。

**Why:** 面试是目标，但用户要的是"学到面试够用的深度"，不是把内容改造成题库背答案；题库格式会破坏原有的学习节奏（[[pacing-small-chunks]] 的微步模板）。

**第二次纠正（2026-09-29 同日，讲到第二章 2.2 后）：** 用户说"我觉得你现在讲课讲的非常的简单和随意"，并让我重读 [[teaching-map-before-code]] 与 [[pacing-small-chunks]] 的新增条目。我当时的毛病：每节压成 3~4 句、自问自答互不承接、2.0→2.1→2.2 再跳回 2.0 补漏、画了 ASCII 树状图、没有"这节在整条微调流水线里的位置"、没有类比、没有跟着一个具体样本走。
→ "面试深度"不是"压短"，是"讲透但不铺开"。每步固定骨架：📍位置（编号站点，说清这节在微调流水线哪一站）→ 是什么（定义）→ 为什么（直觉 + 生活/Java 类比）→ 跟一个具体样本走（优先用用户 train.json 的真实记录）→ 架构层为什么 / 和用户项目对应 → 🔖 要记。自问自答必须成链（先说为什么会有这个疑问再答）。不画 ASCII 图，层级用编号和加粗。严格按小节顺序，一节讲完整再进下一节，不回头补漏。

**How to apply：**
- 带学格式不变：📍 → 生词 ≤3 → 先做（我跑贴输出）→ 再讲 ≤4 句 → 🔖 要记 → 用户回"下一节"。
- 用"面试深度"做取舍标尺：一个知识点讲到"能说清是什么、为什么、和替代方案怎么选"即止；实验细节、配比数字、UI 操作、安装步骤一笔带过或不讲。
- 不产出面试题库、不用"面试官会问"开头；用户主动说"考我"时才出题。
- 章末追加《大模型微调.md》仍只三样（[[module6-notes-doc]]），不加"本章面试题"。
- **不要每节都挂用户的 code/lora train.json**（2026-09-29 讲课件 4 第 4.1 节时用户说"不需要一直提到我的这个项目中的 train.json，这好像是之前课程内容用到的"）。"跟一个具体样本走"这一环改用**课件里提到的数据集**（alpaca-zh、guanaco-sharegpt-style、PubMedQA、imdb、NuminaMath-CoT 等）或**网上查到的真实数据集**取样本做示例；用户项目只在课件内容与它直接冲突或动手日才提。
- 动手/代码走读仍攒到整篇讲完（[[quiz-frequency-feedback]] 第五次补充）。
