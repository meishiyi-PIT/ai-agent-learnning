好提问 = **指向哪份材料/代码 + 用户当前状态（卡在哪/理解到哪）+ 要的输出形式**。总口诀：让 Claude 出题、批改、给提示——别让 Claude 替用户输出结论。

分场景模板（发给用户时按当天场景挑 2-3 条，别全发）：

1. **学新课件/视频前**："我要学 `<路径>`，你先读一遍，给我三问框架（解决什么问题/核心模式/对应我工作区哪份代码），告诉我哪些精读哪些跳过，留 3 道检验题。"
2. **概念没懂**："`<概念>` 没看懂。用 Java 里的 `<XX>` 类比，再用我工作区真实代码举例，讲完写进对应代码注释。"（鼓励说出自己的错误理解："我以为是 XX，课件说 YY，矛盾在哪？"）
3. **检验真懂（最值钱，多推）**："我用自己的话讲一遍：……帮我挑错"（费曼）；"出 3 道预测输出题考我"；"给我一段藏 bug 的代码让我找错"。
4. **要练习**："把 `<示例>` 改成挖空版放 `<目录>`，TODO 带提示"；"出个 20 分钟小练习，先别给答案"。
5. **卡住报错（20 分钟规则）**："跑 `<命令>` 报错 `<贴报错>`，我预期 `<XX>`，试过 `<YY>`。先别给答案，给提示让我自己修。"
6. **看完视频**："我理解的流程是 1…2…3…，哪里错了漏了？"
7. **每天收尾**："今天学了 XX，核对进度、更新计划，没解决的挂卡点清单。"

**Why:** 用户提问方式决定辅导质量；"给我讲讲XX"式提问会退化成灌输式总结，重蹈只看不练的覆辙。用户明确要求每次学习时收到该问什么的指令。
**How to apply:** 每次学习会话开始（含每日定时核查触发时），根据用户当天要学的内容主动发对应场景的 2-3 条模板；用户提问过于宽泛时，用模板引导重新提问而不是直接灌输。关联 [[tutor-role]]。
