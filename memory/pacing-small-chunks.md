用户明确反馈(2026-09-22):"你慢慢讲,一次输出的知识密度太大了,我很难一次看完。"

**补充(2026-09-28 新课件预习查错场景):** 用户读到 Claude 一次性汇报"课件核查出 14 处错误"后纠正:"你不要写在笔记中,你直接在对话框中输出;上面找到的问题,我们学习到具体的章节的时候,你再说出来,一次性的知识密度不要太高"。即:[[learning-requirements]] 第 2 条"查漏补缺 + 排查文档错误"要求的**预习查错本身不变**(照样通读、核实、算数字),但**查错结果的披露要拆成两层**——①备课阶段的核实是 Claude 自己的准备工作,不直接产出给用户看的清单;②披露时机跟着教学进度走,教到哪一章/哪一节,才把那一处课件错误当场讲出来(混在正常讲解里,不单列"勘误报告"),不能因为提前查完了就提前一次性倒给用户。载体上也有讲究:**讲出来用对话,不要提前写进学习笔记 md**——笔记只在对应章节**真正教完之后**补一笔(用户自己维护的三问笔记末尾"学习中问过的问题"栏,见 [[tutor-role]] 第 6 条);代码站点文件(如 LoRA 五站 s1~s4)的 docstring 同理,只在讲到那一站时才建那一站的文件,不要建一个"全篇核查脚本"把后面几站的答案提前写进同一个文件的 docstring 里。

**第三次纠正(2026-09-28,模块六一日冲刺排期时):** Claude 发了"8 行排期表 + 三条规矩 + 一段讲解"后,用户反馈:"我学习的时候信息密度不能太大,我不能太集中的去看很多这种文字,我会无法专注。主要是还是因为对这块的内容不太熟悉"。根因不只是"块太大",而是**内容不熟时靠读进不去,只能靠做进去**。定下的微步模板(教学消息一律照此):
  - **一屏一步**:每条消息 = 一行 📍 定位 + 最多 4 句话或一个 ≤5 行的 demo + 结尾一个"👉 你做"(跑/答一个数/一句话复述)。教学消息里**不出现表格、不出现超过 3 项的清单**;排期/方法类消息也尽量短。
  - **先做后讲**:数值类内容(精度、量化、显存账)先让用户跑一行代码看结果,出现意外再解释;概念类内容(并行、推理架构)先问一个生活小问题,用用户的回答引出**唯一一个**术语。
  - **生词先扫**:每站开头最多 3 个术语各一行白话,再让用户读课件对应的 ≤20 行。
  - **每块开头回忆 2 分钟**:让用户不看材料说出上一块的 3 个词,Claude 不提示(检索练习,靠回忆攒熟悉感)。
  - **范围诚实**:这个节奏一小时约 10 个小步;排期时按此估算能扎实过的内容,其余只给"三句话地图"留到第二天,不硬赶。
  - **小例子不让用户跑文件(2026-09-28 同日追加)**:用户说"这种小的例子不需要单独跑文件吧,继续下的内容吧"。几行就能看完结果的小算例(打一张表、看几个比特位、算个乘法),Claude 自己跑完把输出直接贴在消息里即可,不要每步都让用户 cd + uv run;"👉 你做"只留给真正有观察价值的实验(训练曲线、模型加载、多步对比)。demo 代码仍写进站点文件供复习,但不作为推进条件。**同日第二次被提醒(模块六分布式第 1 站,Claude 又让用户 cd + uv run 跑显存账脚本)**,用户说"我是不是给你说过这种小的内容不需要跑py文件,如果非要跑的话等到最后一起租卡跑吧"——补一条:凡是真要用户亲手跑的实验,**攒到租卡/动手日一次跑完**,概念站全程只读对话,不穿插本机运行。
  - **讲代码块必须走一条线(2026-09-29 讲 train_dist.py 的 TrainingArguments 时被批"说话一点逻辑都没有")**:我在一屏里先讲第 134 行,再回头跳着挑 125/129/131 三行各说一句,用户觉得莫名其妙。规则:一屏代码要么**严格按行号顺序**从上到下讲,要么先说"这块回答 N 个问题"再**按问题分组**讲,每组内仍按行号;不要挑零散几行拼一段;每个自问自答必须承接上一句(先说为什么会有这个疑问,再答)。
  - **每步结尾标出"要记"(2026-09-28 同日追加)**:用户说"涉及到需要特别记忆的部分,你需要给我指出来"。每步消息结尾放一个 **🔖 要记** 块,只放 1~3 条必须记住的结论/数字;块外内容默认"理解即可不用背",用户问"这要不要记"时明确回答。推导、历史、算例都不进要记块。
  - **"为什么"段要一因一果、不堆并列理由(2026-09-29 讲课件 4 的 2.4 文本分类时被批"太过于冗长,回答不清晰")**:我在"为什么它值得单列一类"里塞了"第一/第二"两条理由,每条又带评估、老做法、大模型做法、Java 类比,一段 200 字。规则:骨架里的"为什么"先给**唯一一个根因**(一句),再用 ≤3 个短 bullet 列它带来的后果,最后一句话收口;类比单独成句,不和理由缠在一起。另外课件里出现的通用缩写(NLP 等)首次出现要用一行白话解释,不能默认用户认识。
  - **严格按课件小节顺序走(2026-09-28 同日追加)**:用户指出"你没有完全按照文档内容来吧,精度即显存的内容你都没有讲"。即使某节与前面学过的内容重叠,也不能跳,至少一屏带过并说明它在本章的作用;跳节会让后面的小节失去来由。

**Why:** 用户基础较弱([[user-python-level]]),大段多知识点的输出看不完也吸收不了,等于白讲;查错清单本质上也是"知识点",一次性列 14 条和一次性讲 14 个概念是同一种密度问题,只是换了个"预习报告"的外壳;对不熟悉的领域,文字密度稍高就无法专注,必须把"读"换成"做"。

**How to apply:** 讲解/校对时每条消息只覆盖 1 个知识点(最多 2 个紧密相关的),几句话+一个小例子就停,用一个小问题收尾确认理解后再讲下一块。长清单改成"分期连载"。新课件开学时:通读+核实照做,但只在笔记/对话里留"状态:尚未开始第一站"这类骨架,不预写错误列表;每教到一节,才在对话中带出那一节对应的课件错误,教完再补进笔记/代码 docstring。与 [[tutor-role]]、[[teaching-concepts-first]]、[[learning-requirements]] 配合使用。
