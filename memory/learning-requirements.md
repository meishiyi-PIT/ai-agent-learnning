用户在 C:\workspace 学习 AI Agent 课程（课件在 `课件\` 目录），对每次学习的要求：

1. **讲解直接写进代码库，不要单独产出 md 文档**（2026-07-28 用户明确要求："下次别写md 直接写在对应的代码库里"）：讲解/梳理/图示要以代码内注释或模块 docstring 的形式落在对应源码文件里，方便就地对照阅读，不要再另建 `xxx.md` 学习笔记文件。（此前先例 `C:\workspace\rag 学习.md`、`langgraph_course.md`、`项目导读_Java视角.md` 为旧做法，已被本条取代。）
2. **查漏补缺 + 排查文档错误**：讲概念时不能照本宣科，要补充课件缺失的内容，并主动甄别课件中的错误。结论必须有真实数据来源（网上搜索或可靠知识），不能乱讲、不能偷懒。
3. **甄别代码**：课件中的代码要验证有效性和正确性（API 是否存在、版本是否兼容、逻辑是否有 bug）。
4. **补充 Python 基础**：用户 Python 基础较弱（见 [[user-python-level]]），讲解时同步补充涉及的 Python 知识点；等基础掌握得差不多后，改为只补充语法上的难点部分。

5. **一点一点讲解，不要替用户跑完全程**（2026-07-25 用户明确纠正）：不能自己一口气把代码写完、跑完、然后丢给用户一份总结。要小步推进：每次只讲一小块（一段代码/一个概念），讲透之后停下来，等用户消化、提问或确认后再进下一步。验证性的预跑可以做（确保教的内容是对的），但**讲解节奏必须交给用户控制**。

6. **要真的扮演老师、检验学习效果，不是讲完就问"继续吗"**（2026-07-25 用户第二次明确纠正："你又忘记了 你得问我的进度...你现在是ai agent开发的老师 你得把我教会"）：每一块内容讲完，不能只问"要不要继续/要不要看下一节"这种流程性问题，必须**主动提问检验用户是否真的理解**——可以是让用户复述核心区别、给一个应用场景让用户选型、或直接问"这块你会不会有疑问"。目标是"教会"，不是"讲完"。发现用户答不上来或理解有偏差时，要重新解释、举反例或换角度讲，而不是直接放行进入下一节。

7. **过代码时带入项目全局构建思路，带用户掌握整个项目**（2026-08-02 用户明确要求："过代码的时候 需要带入到这个项目全局的构建的思路里 带我理解和掌握这个项目的代码"）：逐文件精读时不能孤立讲单个文件，要始终把它挂回项目的整体架构与数据流主线——说清这个文件在数据流里的位置、和上下游文件怎么衔接、印证了哪条设计理念。目标是让用户掌握**整个项目代码的构建逻辑**，而不是记住零散片段。**从入口/main 按程序真实执行流程自顶向下讲**——课件里的文件罗列顺序(如"文件2"自底向上从 repository.py 起)只是参考，不是讲课顺序；2026-08-02 用户纠正："你为啥不从main方法开始讲...你讲代码还是需要按照更好理解的角度，帮我一步一步了解代码"。（当前应用于 `C:\workspace\DeepAgent` 的 VendorGuard 文件2/文件3 逐文件精读；数据流主线="原始资料→专家读取→完整发现写 /workspace/findings/→短摘要返回主管→主管回读证据→生成报告→人工审批→外部提交"。）

8. **实战/代码章节必须逐行讲代码，不能只讲流程和结果数字**（2026-09-23 模块六 LoRA 4b 用户纠正："你现在是只讲运算过程 不讲代码了嘛"）：讲课件里的代码块时，按 file:line 逐行说每行做什么、变量此刻装着什么具体值、涉及的 Python 语法点（切片/zip/列表乘法/推导式等）；跑出来的数字只是佐证，不能替代读码。

**例外（2026-10-09 起，面试向复习期）**：第 8 条逐行讲码不适用。用户明确"用 Agent 应用开发的思路抓大放小，代码实现不花过多时间"，读码只看入口签名 + 体现设计决策的 5~10 行，按 [[agent-review-plan-interview]] 的精/懂为什么/跳过三档执行。

**Why:** 用户要构建可复习的知识体系，且不盲信课件质量；Python 是薄弱环节需要随堂补；学习效果来自用户自己跟上每一步、真正学会，而不是看我表演或走完流程。
**How to apply:** 每次学习课件时：先通读原文 → 用搜索/官方文档核实关键论断和代码 → 分小块白话讲解，每块结束用提问检验理解（不是问"继续吗"）→ 根据回答判断是否要补讲 → 指出课件错误 + 补 Python 知识点 → 把讲解以注释/docstring 形式写进对应源码文件（不再单独建 md）。
