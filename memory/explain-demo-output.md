2026-09-29 讲课件 5 第 7 节采样时，我按"先做后讲"贴了一个裸输出块（`T=0.3 函数:0.74 重复:0.14 …` + 贪心/采样两次的句子），然后才讲温度。用户连问两轮：
- "没太懂这一步在做什么……你这里都是什么意思，你都没解释"
- "函数是什么意思？……你的意思是函数、重复、定义是三种答案分类……你在对比这几分类回答的概率吗？"
最后靠"IDE 自动补全列表"的类比 + 三句话把三个候选词各自接出来的完整句子写出来才通。用户总结："从你之前的描述中我都完全没明白你在做什么，你回答问题的方式得调整。"

**Why:** 输出块里的每个词（"函数"）、每个数（0.74）对我来说是不言自明的，对用户是黑盒；"先做后讲"的本意是用结果引出概念，但裸结果没有"这是什么"的标签时，用户连结果在描述什么都不知道，更谈不上引出概念。用户不熟的领域，**"实验目的 → 每行是什么 → 结论"这三层缺一层就读不进去**。

**How to apply（贴任何 demo 输出的固定格式）：**
1. **先一两句说实验在做什么、想看什么**（"我让模型写到'递归是一种通过'时停下，看它对下一个词的打分"），放在输出之前。
2. **输出不贴裸块**：每一行前面用白话标注它是什么，输出里出现的词/数第一次出现就解释指的是什么（"函数 = 候选的下一个词，0.74 = 它被选中的概率"）。行数控制在 ≤5 行，多了就删。
3. **结论一句**：这几行合起来说明了什么。
4. 用户误解时先用一个生活/IDE 类比重述整件事，再把误解点直接指出（"不是分类，是候选词"），并把每个候选各自接出来的完整结果写出来让他看到差别。
5. **符号每条消息都重新解释，不只首次**（同日 Roofline 第 3 节用户追问"n 和 I 有什么关系，你每次需要把这些都解释出来"）：跨消息出现的 n、I、d 这类符号，用户上一屏记不住；每条消息里第一次出现时就用括号写明它是什么（n = 这一步一起处理的 token 行数），并且把它们之间的关系用"跟一个数走"算一遍（1 行：运算 1.03 亿次 ÷ 搬 1.03 亿字节 = 1；128 行：运算 ×128、搬运不变 → 约 128），不能只给结论"I ≈ n"。
与 [[pacing-small-chunks]]（先做后讲）、[[teaching-map-before-code]]（先位置再细节）配合：先做后讲仍成立，但"做"的输出必须自带说明。
